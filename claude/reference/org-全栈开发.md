# 全栈开发（强制）

> 全栈任务必须前后端同步完成，禁止半成品交付。

## 核心：先后端，后前端

正确顺序：后端 API -> 前端调用 -> 联调验证 -> 标记完成。

## 强制行为

| 场景 | 必须做 |
|------|--------|
| 前端调用 API | 先确认后端 API 已存在，不存在则先实现 |
| 发现前后端不同步 | 立即继续实现后端，不是报告等用户 |
| 标记完成 | 前后端都能运行，不是"前端做好了" |

## 禁止状态

- 前端调用未实现的 API
- Plan 前端 Phase 全完成、后端未完成
- "前端已完成，等后端配合"

## Plan 组织

按功能模块组织（后端->前端->联调），禁止按技术层组织（"Phase 1: 全部后端"）。

## 联调验证

- 前端能正常调用后端 API，数据结构匹配
- 错误和边界情况处理正确，用户流程走通

## 接口契约优先

- 全栈功能的接口定义必须使用标准版以上结构化模板（详见 design interface-spec.md）
- tech-lead 必须将全栈功能拆为独立的后端 API Task 和前端 Task
- 每个全栈 Task 必须包含 api_ref 指向具体接口定义
- 开发中接口变更按 TWEAK/BREAK 分级处理（详见 developer SKILL.md）
