# 审查指引 — test-design 阶段特异维度

> 本文件定义 test-design 阶段（测试用例设计）的 2 个特异审查维度。
> 与 `review-guide-base.md` 拼接后传给 Codex，基础维度（一致性/完整性/DECEPTION）在 base 文件中定义，此处不重复。

---

## 特异维度 1: AC 覆盖率

- 审查焦点: 每条 AC 是否有测试用例映射
- 判定标准:
  - PASS: 每条 AC 至少有 1 个测试用例覆盖，且覆盖矩阵明确标注映射关系
  - WARN: 大部分 AC 已覆盖，但少量非关键 AC 缺少直接映射（如 GAC 未单独出用例）
  - FAIL: 存在关键 AC 无测试用例覆盖，或覆盖矩阵缺失

### 审查检查项

1. 是否有 AC 覆盖矩阵（AC 编号 -> 测试用例编号的映射表）？
2. 每条 AC 是否至少有 1 个测试用例？
3. 正例/反例/边界类型分布是否合理（不能全是正例）？
4. 排除项（EX）是否有对应的排除项验证用例？
5. 是否存在测试用例未关联任何 AC（孤儿用例）？

## 特异维度 2: 可执行性

- 审查焦点: 测试用例是否可自动化运行
- 判定标准:
  - PASS: 每个用例有明确的前置条件/输入/操作/期望输出/验证命令，可直接转化为自动化测试
  - WARN: 大部分用例可执行，但部分用例的验证命令不够具体（如"检查输出正确"）
  - FAIL: 用例缺少前置条件或验证命令，无法直接转化为自动化测试

### 审查检查项

1. 每个用例是否有明确的前置条件？
2. 每个用例是否有具体的输入/操作步骤？
3. 每个用例是否有可观察的期望输出（不是"正常运行"）？
4. 每个用例是否有验证命令或验证方法？
5. 用例之间是否存在隐含的执行顺序依赖？
