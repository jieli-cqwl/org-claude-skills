# 审查指引 — design 阶段特异维度

> 本文件定义 design 阶段的 2 个特异审查维度。
> 与 `review-guide-base.md` 拼接后传给 Codex，基础维度（一致性/完整性/DECEPTION）在 base 文件中定义，此处不重复。

---

## 特异维度 1: 技术可行性

- 审查焦点: 方案是否可实现，依赖是否可用
- 判定标准:
  - PASS: 方案基于已验证的技术/工具，依赖明确且可获取，无不可实现的假设
  - WARN: 方案整体可行但部分依赖未验证（如第三方 API 未实测）
  - FAIL: 方案依赖不存在的技术/工具，或核心假设不成立

### 审查检查项

1. 设计方案中引用的技术/工具/库是否真实存在且可用？
2. 外部依赖（API/服务/数据库）是否可获取且已确认兼容？
3. 是否存在未验证的核心假设（如"假设 API 响应 < 100ms"但未实测）？
4. 迁移/部署方案是否可操作（不是纸上方案）？

## 特异维度 2: 闭环完整性

- 审查焦点: 接口定义闭环（入参/出参/错误码）+ 迁移/回滚方案
- 判定标准:
  - PASS: 接口定义含入参/出参/错误码/超时/边界，迁移和回滚方案完整
  - WARN: 接口定义基本完整但缺少部分非关键字段（如缺少 INFO 级错误码），迁移方案存在但回滚方案简略
  - FAIL: 接口缺少出参或错误码定义，或无迁移/回滚方案

### 审查检查项

1. 每个接口是否定义了入参（参数名/类型/必选/默认值）？
2. 每个接口是否定义了出参（返回结构/字段/类型）？
3. 每个接口是否定义了错误码/异常场景（至少覆盖常见错误）？
4. 是否定义了超时策略和边界条件？
5. 是否有迁移方案（从现状到目标状态的步骤）？
6. 是否有回滚方案（出问题时如何恢复）？
