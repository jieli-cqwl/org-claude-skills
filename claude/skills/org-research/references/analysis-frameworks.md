# 调研分析框架

三类模式的分析框架、评估维度集与对比/对标模板。

## 技术选型框架

### 评估维度（7 维度）

| 维度 | 权重 | 评估要点 |
|------|------|---------|
| 功能匹配度 | H | 核心需求满足度，缺失功能是否可接受 |
| 成熟度与稳定性 | H | 版本历史、breaking changes、LTS 政策 |
| 社区与生态 | M | GitHub 趋势、StackOverflow、插件生态 |
| 性能特征 | M | 基准数据、资源消耗、扩展性上限 |
| 学习曲线 | M | 文档质量、概念复杂度、团队已有经验 |
| 集成成本 | H | 与现有技术栈兼容性、迁移工作量 |
| 长期维护成本 | M | 依赖链、升级难度、商业/许可风险 |

权重说明：H = 高（决策关键因素），M = 中（有影响但非决定性）。权重可根据项目具体约束调整，调整时须说明理由。

#### 维度详解

## 项目分析框架

### 分析维度（5 维度）

| 维度 | 分析要点 |
|------|---------|
| 核心机制 | 用什么方法解决什么问题，核心创新是什么 |
| 设计哲学 | 底层设计理念，关键取舍及其理由 |
| 实现亮点 | 具体实现中值得学习的技巧/模式 |
| 适用边界 | 在什么条件下有效，什么条件下失效 |
| 与我们的差距 | 他们做得好的 vs 我们做得好的，差距在哪 |

### 对标差距表模板

| 能力项 | 他们的做法 | 我们的做法 | 差距 | 吸收方向 | 优先级 |
|--------|-----------|-----------|------|---------|--------|
| 能力 1 | 具体做法 + 证据 | 我们的现状 | 差距描述 | 拿/改/不拿+理由 | P0/P1/P2 |
| 能力 2 | ... | ... | ... | ... | ... |

### 吸收计划模板

- 拿什么：直接引入的能力/模式，附具体改动项（文件/配置/流程）
- 替换什么：用新做法替换现有做法，附迁移步骤
- 不拿什么：明确不引入的部分 + 理由（不适配/成本过高/已有更优方案）

## 问题域调研框架

### 分析维度（6 维度）

| 维度 | 分析要点 |
|------|---------|
| 核心概念图 | 该领域的核心概念及其关系 |
| 问题本质 | 这个领域要解决的根本问题 |
| 主流解法谱系 | 解法流派 + 各自设计哲学 |
| 最佳实践 | 业界验证有效的模式 + 实证来源 |
| 常见陷阱 | 入门者易犯错误 + 规避方式 |
| 前沿方向 | 活跃研究/工程方向 + 对我们的启示 |

### 知识图谱模板

```
核心问题
├── 子问题 A
│   ├── 解法 A1（流派/哲学）
│   └── 解法 A2（流派/哲学）
├── 子问题 B
│   └── 解法 B1
└── 子问题 C
    ├── 解法 C1
    └── 解法 C2
```
