# 性能检查清单

> 供 /review 审查-C PF-1 性能维度引用。

## 1. 数据库查询

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| N+1 查询 | 循环中是否逐条查询 | 差: `for id in ids: db.get(id)` / 好: `db.get_many(ids)` |
| 缺失索引 | WHERE/JOIN 条件字段是否有索引 | 检查: 新增查询字段的索引覆盖 |
| 全表扫描 | 是否有无 WHERE 条件的大表查询 | 差: `SELECT * FROM large_table` / 好: 分页或条件过滤 |
| 批量操作 | 批量写入是否用 batch/bulk | 差: 循环 INSERT / 好: `INSERT INTO ... VALUES (...)` 批量 |
| 不必要字段 | 是否 SELECT * 而非选择需要的字段 | 差: `SELECT *` / 好: `SELECT id, name` |

## 2. 资源泄露

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| 连接未关闭 | DB/HTTP/文件连接是否在 finally/with 中关闭 | 差: `conn = open()` 无 close / 好: `with open() as f:` |
| 事件监听未清理 | addEventListener 是否有对应 remove | 差: 组件卸载后监听器残留 / 好: cleanup 函数 |
| 定时器未清理 | setInterval/setTimeout 是否在组件销毁时清理 | 差: 无 clearInterval / 好: useEffect cleanup |
| 大对象引用 | 是否持有不再需要的大对象引用 | 检查: 缓存无上界、闭包捕获 |

## 3. 算法复杂度

| 检查项 | 检查方法 |
|--------|---------|
| 嵌套循环 | O(n^2) 或更高复杂度是否有数据量上界 |
| 排序 vs 哈希 | 查找操作是否用了 O(n) 遍历而非 O(1) 哈希 |
| 正则回溯 | 正则表达式是否有灾难性回溯风险 |
| 字符串拼接 | 循环中是否用 += 拼接字符串（O(n^2)） |

## 4. 内存上界

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| 无界集合 | 缓存/队列/列表是否有大小上限 | 差: 无限增长的 Map / 好: LRU 缓存 |
| 大文件加载 | 是否将大文件完整加载到内存 | 差: `readFile(bigFile)` / 好: 流式读取 |
| 响应大小 | API 响应是否可能返回无界数据 | 差: 无分页 / 好: 分页或限制条数 |

## 5. 缓存与异步

| 检查项 | 检查方法 |
|--------|---------|
| 缓存失效策略 | 缓存是否有 TTL 或主动失效机制 |
| 缓存穿透 | 查询不存在的 key 是否直接打到后端 |
| 同步阻塞 | I/O 操作是否在异步上下文中同步阻塞 |
| 并发请求合并 | 相同请求是否合并（dedup/singleflight） |

## 报告格式

每条性能 finding 必须注明：
- 影响量级：估算的性能影响（如 O(n) vs O(n^2)、延迟增加量级）
- 触发条件：什么数据量/并发量下会成为瓶颈
