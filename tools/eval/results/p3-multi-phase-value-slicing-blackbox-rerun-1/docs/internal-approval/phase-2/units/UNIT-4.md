# UNIT-4: 审批状态变更通知

**优先级**: 增强

## 优先级依据
通知不能替代核心审批闭环，但能明显减少人工追问，因此适合作为 Phase 2 的增强价值。

## 背景
审批结果出来后，相关人现在还需要额外去问进度，信息传递效率低。

## 需求描述
当审批状态发生变化时，系统需要把结果同步到企业微信，让申请人或相关处理人能够及时收到通知并回到对应记录。

## 功能闭环定义
- 输入/触发: 审批申请的最终状态发生变化
- 核心行为: 系统生成企业微信通知，并把状态变化信息发送给相关人
- 可观察结果: 相关人收到通知，且通知内容与审批记录中的结果一致

## 验收标准

> AC 编号格式: `AC-U4-{序号}`

### 正常场景
- AC-U4-01: 一笔申请完成通过或驳回后 → 相关人收到企业微信通知，通知内容包含申请标识和当前结果

### 异常场景
- AC-U4-02: 企业微信侧暂时不可用时 → 系统不影响审批结果落库，通知状态可见为失败或待处理

### 边界条件
- AC-U4-03: 同一申请没有产生状态变化时 → 系统不重复发送通知

## 业务规则（如有）
- 通知只服务于状态变化后的信息同步，不改变审批结论。
- 通知内容必须能回指到对应审批记录。

## 依赖
- 依赖 UNIT: UNIT-2
- 依赖业务对象: 审批结果、通知事件
- 受影响方: 申请人、审批人、管理员

## 排除项
- 统计报表
- 多级会签
- 通知模板运营配置
