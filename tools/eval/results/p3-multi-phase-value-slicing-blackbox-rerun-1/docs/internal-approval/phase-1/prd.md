# Phase 1: 核心审批闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

Phase 1 先交付最小可用审批闭环，让员工能提交申请，审批人能处理通过或驳回，申请人和管理员能查看记录，并且一笔申请的当前状态始终可见。

## 入口与出口条件

- 入口条件: Brief 审查通过
- 出口条件: Phase 1 所有 UNIT QA 通过

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 提交审批申请 | 员工填写审批内容并提交 → 系统生成申请记录、置为待处理并返回成功结果 | MVP | - | units/UNIT-1.md |
| UNIT-2 | 审批通过或驳回 | 审批人处理待处理申请并给出通过或驳回结果 → 系统记录审批人、时间、结果和原因 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查看审批记录 | 申请人或管理员查看申请记录 → 系统展示提交人、审批人、时间、结果、原因和当前状态 | MVP | UNIT-1, UNIT-2 | units/UNIT-3.md |
