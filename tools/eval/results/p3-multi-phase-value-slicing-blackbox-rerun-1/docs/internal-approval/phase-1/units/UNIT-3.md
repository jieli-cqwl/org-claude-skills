# UNIT-3: 查看审批记录

**优先级**: MVP

## 优先级依据
如果申请人和管理员不能查看记录，根问题“可追踪”仍然没有被解决，所以查看记录必须进入 Phase 1。

## 背景
审批状态如果只能靠口头确认，申请人和管理员就无法快速追溯是谁在什么时候做了什么决定。

## 需求描述
申请人或管理员打开审批记录后，需要能看到提交人、审批人、时间、结果、驳回原因和当前状态，从而独立判断这笔申请的完整历史。

## 功能闭环定义
- 输入/触发: 申请人或管理员进入审批记录入口并选择一笔申请
- 核心行为: 系统按权限返回该申请的记录详情，包含历史处理信息和当前状态
- 可观察结果: 用户可以直接看到完整记录，不需要再找审批人或提交人确认

## 验收标准

> AC 编号格式: `AC-U3-{序号}`

### 正常场景
- AC-U3-01: 申请人查看自己的审批记录 → 系统展示提交人、审批人、处理时间、结果、驳回原因和当前状态

### 异常场景
- AC-U3-02: 无权限用户尝试查看他人审批记录 → 系统返回无权限结果，不展示记录内容

### 边界条件
- AC-U3-03: 记录列表为空时打开查看入口 → 系统返回空状态，不报错

## 业务规则（如有）
- 记录展示必须包含当前状态。
- 驳回原因在记录里必须可见。

## 依赖
- 依赖 UNIT: UNIT-1、UNIT-2
- 依赖业务对象: 审批申请、审批记录
- 受影响方: 无

## 排除项
- 企业微信通知
- 统计报表
- 记录导出
