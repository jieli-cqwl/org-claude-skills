# UNIT-1: 提交审批申请

**优先级**: MVP

## 优先级依据
没有提交入口，后续审批和记录查看都没有业务起点，因此这是最小闭环的第一步。

## 背景
当前申请散落在聊天和表格里，员工无法形成统一、可追踪的申请记录。

## 需求描述
员工填写审批内容并提交后，系统需要创建一条完整的审批申请，自动进入待处理状态，并给出可确认的提交结果。

## 功能闭环定义
- 输入/触发: 员工在提交入口填写审批内容并点击提交
- 核心行为: 系统校验必填项，保存审批申请，生成唯一申请记录，设置当前状态为待处理
- 可观察结果: 用户收到提交成功反馈，并能看到申请 ID 和当前状态

## 验收标准

> AC 编号格式: `AC-U1-{序号}`

### 正常场景
- AC-U1-01: 输入完整的审批内容并提交 → 系统成功创建申请记录，状态为待处理，页面显示申请 ID

### 异常场景
- AC-U1-02: 缺少必填项或字段格式不合法时提交 → 系统拒绝提交并提示具体原因，不创建申请记录

### 边界条件
- AC-U1-03: 用户重复点击提交按钮 → 系统只保留一条有效申请记录，避免重复创建

## 业务规则（如有）
- 申请创建成功后，当前状态必须可查询。
- 提交结果需要可回溯到唯一申请 ID。

## 依赖
- 依赖 UNIT: 无
- 依赖业务对象: 审批申请
- 受影响方: UNIT-2、UNIT-3

## 排除项
- 企业微信通知
- 统计报表
- 多级会签
