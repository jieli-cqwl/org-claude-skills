# Executor Notes

这次我把 Phase 边界按“业务可独立交付价值”切，而不是按功能均分。

Phase 1 收的是最小闭环：提交申请、审批通过或驳回、查看审批记录。这个闭环单独上线就能解决“记录分散、结果难追踪、状态不可见”的根问题，所以它必须独立成一阶段。

Phase 2 单独放企业微信通知，因为它是在核心闭环成立之后才叠加的增强价值，且用户明确要求不要把通知方案提前写死到第一期。Phase 3 再放统计报表，因为它依赖更稳定的审批数据沉淀，属于管理侧的后续增量价值。

我没有把任务批次、人员安排、实施节奏写进 `/product` 文档，因为那属于执行计划，不属于需求收口。开放问题只保留了通知触发/补偿和报表维度/刷新方式，避免提前替 design 做技术决策。
