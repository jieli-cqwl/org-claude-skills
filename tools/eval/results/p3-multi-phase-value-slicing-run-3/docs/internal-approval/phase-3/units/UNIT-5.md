# UNIT-5: 查看审批统计报表

**优先级**: 扩展

## 优先级依据

统计报表需要建立在稳定的审批记录之上，价值更多体现在管理分析与优化，因此应排在核心闭环和通知能力之后。

## 背景

当审批数据逐步沉淀后，业务方会希望了解审批量、处理结果分布和整体处理情况，为流程优化提供依据。

## 需求描述

提供审批统计报表能力，让业务负责人或管理员能够查看审批数据的汇总结果。

## 功能闭环定义

- 输入/触发: 用户进入审批统计报表页
- 核心行为: 系统汇总审批记录并生成统计结果
- 可观察结果: 用户看到审批量、结果分布或其他统计指标

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U5-01: 管理员进入审批统计页 → 系统展示基于审批记录汇总的统计结果

### 异常场景

- AC-U5-02: 无报表查看权限的用户访问统计页 → 系统拒绝访问并明确提示权限不足

### 边界条件

- AC-U5-03: 当前尚无可统计的审批记录 → 系统展示明确的空状态，而不是错误或空白

## 业务规则（如有）

- 报表建立在已沉淀的审批记录之上。
- 报表不承担审批处理入口职责。

## 依赖

- 依赖 UNIT: UNIT-3
- 依赖业务对象: 审批记录
- 受影响方: 数据分析能力

## 排除项

- 不处理企业微信通知。
- 不定义报表的技术刷新机制。
