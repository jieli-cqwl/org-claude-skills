# Phase 1: 核心审批闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

交付一条可以直接被业务使用的审批主链路：申请人发起审批，审批人完成通过或驳回，申请人和管理员查看结果与记录。

## 入口与出口条件

- 入口条件: Brief 审查通过
- 出口条件: 本阶段所有 UNIT QA 通过，且“提交申请 → 审批处理 → 查看记录”闭环可独立运行

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 提交审批申请 | 申请人提交审批申请 → 系统创建待处理申请 → 申请进入可追踪状态 | MVP | - | units/UNIT-1.md |
| UNIT-2 | 处理审批申请 | 审批人查看待处理申请并执行通过或驳回 → 系统记录处理结果 → 申请状态更新 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查看审批记录 | 申请人或管理员查看审批记录 → 系统返回当前状态和历史结果 → 用户完成追溯 | MVP | UNIT-2 | units/UNIT-3.md |
