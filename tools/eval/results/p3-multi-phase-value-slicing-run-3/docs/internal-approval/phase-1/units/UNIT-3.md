# UNIT-3: 查看审批记录

**优先级**: MVP

## 优先级依据

如果审批结果不能被申请人和管理员追溯，当前审批仍然会回到线下追问状态，核心价值无法闭合。

## 背景

审批处理完成后，申请人和管理员目前很难统一查看状态、处理人和处理原因，复盘成本高。

## 需求描述

提供审批记录查看能力，让申请人和管理员能够查看一笔申请的当前状态、处理结果和关键历史信息。

## 功能闭环定义

- 输入/触发: 申请人或管理员查看某笔审批申请的记录
- 核心行为: 系统返回该申请的当前状态、处理结果和关键时间信息
- 可观察结果: 用户能够追溯这笔申请是谁提交、是否已处理、结果如何

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U3-01: 申请人查看一笔已处理申请的记录 → 系统展示当前状态、处理结果和关键时间信息

### 异常场景

- AC-U3-02: 无权查看该申请的用户访问审批记录 → 系统拒绝访问并明确提示权限不足

### 边界条件

- AC-U3-03: 申请仍处于待处理状态时查看记录 → 系统展示当前状态为“待处理”，而不是空白或报错

## 业务规则（如有）

- 申请记录至少应体现当前状态和处理结果。
- 申请被驳回时，记录中必须能看到驳回原因。

## 依赖

- 依赖 UNIT: UNIT-2
- 依赖业务对象: 审批申请、审批记录
- 受影响方: 申请人、管理员

## 排除项

- 不提供统计分析能力。
- 不提供报表导出能力。
