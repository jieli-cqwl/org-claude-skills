# UNIT-2: 调整项目角色资源权限

**优先级**: MVP

## 优先级依据

只有查看而不能调整，项目管理员仍然无法完成权限治理动作，核心痛点不会真正下降。

## 背景

项目管理员当前需要通过平台管理员代为新增或移除授权，改动效率低且出错后难以及时纠偏。

## 需求描述

提供项目级角色权限调整能力，让项目管理员在确认当前权限后，能对指定角色执行新增授权或移除授权，并看到变更已经生效。

## 功能闭环定义

- 输入/触发: 项目管理员在可管理项目内选中某个角色，并提交新增或移除授权动作
- 核心行为: 系统校验操作范围、保存权限变更，并同步生成变更差异
- 可观察结果: 权限调整保存成功后，当前权限视图立即反映最新结果；越权或非法操作被明确拒绝

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U2-01: 项目管理员为项目 A 的角色 R 新增资源 X 的访问权限并提交 → 系统保存成功，角色 R 的当前权限视图出现资源 X

### 异常场景

- AC-U2-02: 无项目 A 管理权限的用户尝试修改角色 R 权限 → 系统拒绝保存并返回明确的权限不足结果

### 边界条件

- AC-U2-03: 项目管理员重复提交一个角色已经拥有的权限 → 系统不产生重复授权记录，并向用户返回幂等处理结果

## 业务规则（如有）

- 只允许新增和移除授权，不包含复杂审批流。
- 每次调整都必须形成可追溯的变更差异。

## 依赖

- 依赖 UNIT: UNIT-1
- 依赖业务对象: 项目角色、资源权限配置、权限变更记录
- 受影响方: 权限持久化能力、项目管理后台角色配置入口

## 排除项

- 不包含批量授权策略。
- 不包含跨项目继承调整。
