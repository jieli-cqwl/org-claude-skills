# 并发与状态检查清单

> 供 /review 审查-A CS-4 并发/状态维度引用。

## 1. 竞态条件

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| 检查后使用（TOCTOU） | 先检查再操作之间是否有窗口期 | 差: `if exists(f): read(f)` / 好: 原子操作或加锁 |
| 共享可变状态 | 多线程/协程访问的变量是否有同步保护 | 差: 全局字典无锁 / 好: `threading.Lock()` 保护 |
| 非原子复合操作 | read-modify-write 是否原子 | 差: `count = get(); set(count+1)` / 好: `INCR` 原子操作 |
| 事件顺序依赖 | 是否假设事件按特定顺序到达 | 差: 假设消息有序 / 好: 处理乱序场景 |

## 2. 死锁与锁排序

| 检查项 | 检查方法 |
|--------|---------|
| 多锁获取顺序 | 是否所有代码路径按相同顺序获取多把锁 |
| 锁范围最小化 | 临界区是否只包含必要操作 |
| 嵌套锁 | 是否避免在持有锁时调用会获取其他锁的函数 |
| 超时机制 | 长等待的锁是否有超时，避免无限阻塞 |

## 3. 时区与时间处理

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| 时区一致性 | 存储/传输/显示是否统一时区 | 差: 混用 naive datetime / 好: 统一 UTC 存储 |
| DST 边界 | 是否处理夏令时切换的边界情况 | 检查: 时间比较是否考虑 DST |
| 时间戳精度 | 时间戳精度是否满足业务需求 | 检查: 秒 vs 毫秒 vs 微秒 |

## 4. 状态转换

| 检查项 | 检查方法 |
|--------|---------|
| 状态机完整性 | 所有合法的状态转换是否被显式定义 |
| 非法转换防护 | 是否阻止非法状态转换（如 "已取消" -> "已支付"） |
| 并发状态修改 | 两个请求同时修改同一实体状态时是否有保护 |
| 中间状态持久化 | 崩溃恢复后中间状态是否可恢复或可回滚 |

## 5. 幂等性

| 检查项 | 检查方法 | 代码模式示例 |
|--------|---------|-------------|
| 写操作幂等 | 重复执行同一请求是否产生相同结果 | 差: 每次调用都插入 / 好: upsert 或幂等键 |
| 消息消费幂等 | 消息重复投递时是否安全 | 差: 无去重 / 好: 消息 ID 去重 |
| 重试安全 | 失败重试是否产生副作用 | 差: 重试导致重复扣款 / 好: 事务幂等键 |

## 报告格式

每条并发/状态 finding 必须注明：
- 触发条件：什么并发场景下会触发
- 影响范围：数据损坏/逻辑错误/死锁的具体影响
