# UNIT-3: 查询权限变更记录

**优先级**: MVP

## 优先级依据

如果没有可查询的变更记录，权限调整就无法追溯谁改了什么，审计目标会断掉，所以变更查询是闭环的最后一段。

## 背景

项目管理员和支持人员需要在事后快速确认某次权限调整的操作人、时间和差异，避免只能靠口头回忆或零散日志排查。

## 需求描述

支持项目管理员按项目、角色、时间或操作者查询权限变更记录，并查看每条记录的变更前后差异。

## 功能闭环定义

- 输入/触发: 项目管理员进入变更记录页，输入项目、角色、时间或操作者等筛选条件。
- 核心行为: 系统读取审计记录并按条件过滤，返回对应的变更列表和差异详情。
- 可观察结果: 管理员可以看到可追溯的历史变更记录，并定位到每次调整的关键信息。

## 验收标准

### 正常场景
- AC-U3-01: 项目管理员按项目和角色查询变更记录 -> 系统返回匹配的历史记录列表，并可展开查看每条记录的变更前后差异。

### 异常场景
- AC-U3-02: 项目管理员尝试查询自己无权管理的项目变更记录 -> 系统返回 403，且不泄露记录内容。

### 边界条件
- AC-U3-03: 查询条件下没有任何匹配记录 -> 页面显示空状态和明确的无结果提示，不报错。

## 业务规则（如有）

- 变更记录仅允许查询，不允许编辑或删除。
- 查询结果必须能关联到具体操作人、时间和差异。

## 依赖

- 依赖 UNIT: UNIT-2
- 依赖业务对象: 变更记录、项目角色、权限关系
- 受影响方: 审计查询页、权限记录展示、权限校验链路

## 排除项

- 不做变更记录编辑或删除。
- 不做时间线以外的复杂可视化。
- 不做导出和批量分析。
