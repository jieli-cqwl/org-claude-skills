# UNIT-2: 调整角色权限

**优先级**: MVP

## 优先级依据

这是解决“配置慢、容易配错”的核心动作，没有它就只有查看没有闭环，所以必须放在最小闭环里。

## 背景

项目管理员在确认当前状态后，需要直接完成常见的新增、移除和保存操作，避免继续依赖平台管理员人工代办。

## 需求描述

支持项目管理员在自己有权管理的项目中，对某个角色执行新增或移除权限，并在保存后立即生效，同时留下可追溯的变更记录。

## 功能闭环定义

- 输入/触发: 项目管理员在角色权限页选择新增或移除某个资源权限并点击保存。
- 核心行为: 系统校验项目和角色权限，计算变更前后差异，保存新状态，并写入审计记录。
- 可观察结果: 角色当前权限被更新，页面展示保存结果和变更摘要。

## 验收标准

### 正常场景
- AC-U2-01: 项目管理员给某角色新增一个资源权限并保存 -> 角色当前权限更新成功，同时生成一条包含操作人、时间和差异的变更记录。

### 异常场景
- AC-U2-02: 项目管理员尝试修改自己无权管理的项目或提交无效资源项 -> 系统拒绝保存，且角色权限状态不发生变化。

### 边界条件
- AC-U2-03: 项目管理员对已存在的同一权限重复新增，或对不存在的权限重复移除 -> 系统不产生重复状态，且明确提示这次操作没有新增有效变更。

## 业务规则（如有）

- 只允许项目管理员调整自己有权限管理的项目。
- 每次保存都必须写入操作人、时间、变更前后差异。
- 本期不引入复杂审批流，保存后直接生效。

## 依赖

- 依赖 UNIT: UNIT-1
- 依赖业务对象: 项目角色、资源项、权限关系、变更记录
- 受影响方: 权限保存接口、审计写入链路、权限校验链路

## 排除项

- 不做跨项目继承。
- 不做组织架构同步。
- 不把角色树和批量授权当作本期必做能力。
