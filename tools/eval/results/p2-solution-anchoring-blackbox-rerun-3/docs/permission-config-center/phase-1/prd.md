# Phase 1: 项目级权限查看、调整与审计闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

本阶段交付项目级权限配置的最小闭环，让项目管理员先看清当前角色权限，再完成一次常见权限调整，并且能追溯这次调整是谁改的、什么时候改的、改了什么。

## 入口与出口条件

- 入口条件: Brief 审查通过，且范围已收口为项目内角色权限
- 出口条件: 本阶段所有 UNIT QA 通过，且变更留痕可查询

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 查看角色当前权限 | 输入/触发: 项目管理员打开某项目角色权限页 -> 核心行为: 系统读取并展示该角色当前有效权限 -> 可观察结果: 管理员直接看到当前资源权限和数据范围 | MVP | - | units/UNIT-1.md |
| UNIT-2 | 调整角色权限 | 输入/触发: 项目管理员在角色权限页新增或移除权限并保存 -> 核心行为: 系统校验权限、保存差异并写入审计记录 -> 可观察结果: 角色有效权限更新且显示调整结果 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查询权限变更记录 | 输入/触发: 项目管理员按项目、角色或时间查询权限变更 -> 核心行为: 系统读取审计记录并返回差异详情 -> 可观察结果: 管理员看到可追溯的历史变更记录 | MVP | UNIT-2 | units/UNIT-3.md |
