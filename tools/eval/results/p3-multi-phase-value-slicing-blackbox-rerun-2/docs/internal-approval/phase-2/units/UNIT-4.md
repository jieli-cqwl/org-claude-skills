# UNIT-4: 企业微信通知审批结果

**优先级**: 增强

## 优先级依据
这是在审批闭环成立之后增加的主动触达能力，不影响 Phase 1 的核心闭环交付。

## 背景
申请人如果只能被动查看记录，仍然需要反复确认结果；通知可以减少追问成本。

## 需求描述
当审批结果生效后，系统能把结果通知到企业微信，让申请人及时收到通过或驳回消息。

## 功能闭环定义
- 输入/触发: 审批结果从待处理变为通过或驳回
- 核心行为: 系统生成并发送企业微信通知，消息包含结果和审批记录入口
- 可观察结果: 申请人能在企业微信收到审批结果通知，且能回到记录页继续查看详情

## 验收标准

### 正常场景
- AC-U4-01: 审批通过后触发通知 → 申请人收到企业微信通过消息，并能打开记录入口
- AC-U4-02: 审批驳回后触发通知 → 申请人收到企业微信驳回消息，并能看到驳回原因入口

### 异常场景
- AC-U4-03: 通知发送失败 → 系统留下失败可追踪记录，且不影响审批结果本身

### 边界条件
- AC-U4-04: 同一审批单重复变更状态时 → 仅对最终有效结果生成通知

## 业务规则（如有）
- 通知只承载结果感知，不改变审批结论。
- 通知内容必须能回链到审批记录。

## 依赖
- 依赖 UNIT: UNIT-2, UNIT-3
- 依赖业务对象: 企业微信消息、审批结果
- 受影响方: 申请人通知体验、消息失败追踪

## 排除项
- 通知模板后台配置
- 通知重试与补偿策略细节
- 推送频控策略
