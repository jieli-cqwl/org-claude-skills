# UNIT-1: 提交审批申请

**优先级**: MVP

## 优先级依据
没有提交入口，后续审批和记录都没有业务对象可处理，这是审批闭环的起点。

## 背景
员工现在通过聊天工具和表格提审批，申请无法统一落地，后续追踪很困难。

## 需求描述
提供一个可提交审批申请的能力，用户提交后系统生成一条待处理申请并记录提交信息。

## 功能闭环定义
- 输入/触发: 员工填写审批内容并点击提交
- 核心行为: 系统校验必填项，创建审批申请，写入提交人和提交时间，状态设为待处理
- 可观察结果: 申请人看到申请已提交，且有清晰的待处理状态和申请编号

## 验收标准

### 正常场景
- AC-U1-01: 员工填写完整审批内容并提交 → 系统生成一条待处理审批申请，页面展示提交成功和申请编号

### 异常场景
- AC-U1-02: 员工提交时缺少必填项 → 系统拒绝提交，并提示缺失字段

### 边界条件
- AC-U1-03: 员工连续点击提交 → 系统只保留一条有效申请，不产生重复待处理记录

## 业务规则（如有）
- 提交成功后状态必须为“待处理”。
- 申请编号必须唯一且可追踪。

## 依赖
- 依赖 UNIT: 无
- 依赖业务对象: 审批申请
- 受影响方: 审批处理、审批记录查询

## 排除项
- 审批通过/驳回处理
- 企业微信通知
- 统计报表
