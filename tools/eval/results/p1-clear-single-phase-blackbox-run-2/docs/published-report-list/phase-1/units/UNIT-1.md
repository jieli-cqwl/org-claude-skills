# UNIT-1: 已发布周报列表与分页浏览

**优先级**: MVP

## 优先级依据
这是本需求的唯一闭环，没有它就无法解决“登录后自助查看已发布周报”的根问题。

## 背景
员工当前看已发布周报要依赖管理员导出或数据库查询，获取信息太慢，需要一个能直接浏览的列表入口。

## 需求描述
登录后的内部员工可以查看状态为 `published` 的周报列表。列表默认按发布时间倒序展示，支持每页 10 条的上一页/下一页分页；列表为空时应显示明确提示。列表项至少展示标题、作者、发布时间。

## 功能闭环定义
- 输入/触发: 已登录用户进入已发布周报列表页
- 核心行为: 系统加载状态为 `published` 的周报，按发布时间倒序返回并支持分页浏览
- 可观察结果: 页面显示周报标题、作者、发布时间；用户可通过上一页/下一页切换列表；列表为空时显示明确空状态提示

## 验收标准

### 正常场景
- AC-U1-01: 已登录用户打开列表页 → 页面展示状态为 `published` 的周报，且默认按发布时间倒序排列
- AC-U1-02: 已登录用户点击“下一页” → 页面展示下一组 10 条周报，且仍保持倒序规则

### 异常场景
- AC-U1-03: 未登录用户访问列表页 → 页面不展示已发布周报列表内容，并沿用现有登录能力进行拦截或引导

### 边界条件
- AC-U1-04: 可展示的周报数量为 0 → 页面显示明确空状态提示，不出现空白页

## 业务规则
- 仅展示状态为 `published` 的周报。
- 列表默认按发布时间倒序。
- 每页固定 10 条，只支持上一页和下一页。
- 列表项至少展示标题、作者、发布时间。

## 依赖
- 依赖 UNIT: 无
- 依赖业务对象: 已发布周报、登录用户
- 受影响方: 现有登录能力、周报编辑流程

## 排除项
- 不做搜索
- 不做按作者筛选
- 不做周报编辑
- 不做导出
- 不改认证流程
