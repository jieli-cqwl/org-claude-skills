# UNIT-4: 发送企业微信审批通知

**优先级**: 增强

## 优先级依据

通知能显著提升使用效率，但在核心审批闭环已经可用的前提下，它属于增强能力，而不是首期成立所必需的环节。

## 背景

当核心审批流程稳定后，申请人和审批人仍可能希望在关键状态变化时收到主动提醒，以减少主动进入系统查询的频率。

## 需求描述

提供企业微信通知能力，在审批状态发生关键变化时，向相关人员推送审批提醒。

## 功能闭环定义

- 输入/触发: 一笔审批申请发生关键状态变化（如提交成功、审批完成）
- 核心行为: 系统根据通知规则向相关人发送企业微信提醒
- 可观察结果: 相关人在企业微信中收到对应的审批提醒

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U4-01: 一笔新审批申请提交成功 → 对应审批人在企业微信中收到待处理提醒

### 异常场景

- AC-U4-02: 企业微信通知发送失败 → 系统记录失败结果并保留后续补偿空间

### 边界条件

- AC-U4-03: 同一状态变化重复触发通知事件 → 系统不向同一接收人重复发送多条等价提醒

## 业务规则（如有）

- 通知只在关键状态变化时触发。
- 通知建立在稳定审批状态之上，不改变审批核心语义。

## 依赖

- 依赖 UNIT: UNIT-2
- 依赖业务对象: 审批申请、审批结果
- 受影响方: 企业微信集成能力

## 排除项

- 不处理统计报表。
- 不在本 UNIT 中决定失败补偿的具体技术实现。
