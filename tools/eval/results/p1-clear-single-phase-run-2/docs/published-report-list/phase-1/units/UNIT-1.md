# UNIT-1: 查看已发布周报列表并分页浏览

**优先级**: MVP

## 优先级依据

如果员工仍然不能在系统内直接查看已发布周报，这个需求的核心价值就没有成立；列表展示与基础分页共同构成最小浏览闭环。

## 背景

当前员工查看已发布周报需要依赖管理员导出或数据库查询，获取内容的路径不稳定且效率低。

## 需求描述

提供一个登录后可访问的已发布周报列表页，让员工能够查看按发布时间倒序排列的已发布周报，并通过基础分页浏览更早内容。

## 功能闭环定义

- 输入/触发: 已登录员工进入已发布周报列表页并执行分页浏览
- 核心行为: 系统返回按发布时间倒序排列的已发布周报列表，并支持上一页/下一页浏览
- 可观察结果: 员工能看到最近发布周报，且可继续浏览更早内容；无内容或未登录时有明确反馈

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U1-01: 已登录员工进入已发布周报列表页 → 系统展示按发布时间倒序排列的已发布周报列表
- AC-U1-02: 已登录员工在列表页点击下一页 → 系统展示下一页的已发布周报内容

### 异常场景

- AC-U1-03: 未登录用户访问已发布周报列表页 → 系统通过现有登录机制拦截访问，用户无法看到列表内容

### 边界条件

- AC-U1-04: 当前没有任何已发布周报时进入列表页 → 系统展示明确的空列表提示，而不是空白或报错

## 业务规则（如有）

- 列表只展示状态为 `published` 的周报。
- 每页固定展示 10 条内容。
- 本期只支持基础上一页/下一页分页。

## 依赖

- 依赖 UNIT: 无
- 依赖业务对象: 周报、已登录用户
- 受影响方: 现有登录能力、周报数据接口

## 排除项

- 不做搜索。
- 不做按作者筛选。
- 不做周报编辑或导出。
