# UNIT-1: 提交审批申请

**优先级**: MVP

## 优先级依据

没有系统内的申请入口，审批闭环就无法开始，因此这是首期不可缺少的起点能力。

## 背景

当前审批多依赖聊天工具或表格发起，申请入口分散，后续状态也难统一追踪。

## 需求描述

提供审批申请提交能力，让申请人能够在系统内发起一笔审批，并使该申请进入可追踪的待处理状态。

## 功能闭环定义

- 输入/触发: 申请人在系统内填写并提交一笔审批申请
- 核心行为: 系统校验必要信息并创建待处理的审批申请
- 可观察结果: 申请提交成功后，系统中出现一条状态为“待处理”的审批记录

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U1-01: 申请人填写完整审批信息并提交 → 系统创建一条新的待处理审批申请

### 异常场景

- AC-U1-02: 申请人缺少必填信息直接提交 → 系统拒绝创建申请并明确提示缺失项

### 边界条件

- AC-U1-03: 申请人提交成功后立即查看申请详情 → 系统展示该申请当前状态为“待处理”

## 业务规则（如有）

- 申请创建后必须进入待处理状态。
- 申请提交成功后应具备唯一可追踪记录。

## 依赖

- 依赖 UNIT: 无
- 依赖业务对象: 审批申请
- 受影响方: 员工身份体系

## 排除项

- 不处理多级会签。
- 不处理通知发送。
