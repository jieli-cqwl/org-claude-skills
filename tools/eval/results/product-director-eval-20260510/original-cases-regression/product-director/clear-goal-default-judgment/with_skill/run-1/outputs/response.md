**Director 推荐基线草案**

根问题判断：审批慢的根因不是规则复杂度本身，而是审批事项分散、状态不可见、逾期缺少触发机制，导致责任人无法及时发现、跟进和关闭待办。

成功标准：内部审批平均处理时长从当前 `2 天` 降至 `4 小时`。观测口径建议为 Phase 1 上线后，按审批发起到审批完成的平均耗时统计；数据来源应来自现有审批系统或统一审批记录。

本期范围：
- 待办聚合：让审批人能在一个入口看到需要处理的审批。
- 审批状态同步：让发起人和相关方能看到审批当前状态，减少人工追问。
- 逾期提醒：对超过时限的审批触发提醒，推动处理闭环。

本期不做：
- 不改变审批规则。
- 不新增审批层级。
- 不改审批权限模型。
- 不做复杂流程编排。
- 不做审批效率归因分析大盘。
- 不承诺自动审批或智能分派。

Phase 1 交付切片：单 Phase，`iteration_timebox_days <= 14`，预期 UNIT 数量范围 `3-5`。入口条件是现有审批事项、状态和处理人可被读取或同步；出口条件是审批人能看到聚合待办，审批状态能同步展示，逾期审批能被提醒，且平均处理时长具备可观测统计口径。

推荐理由：这三个能力直接打在“看不见、不同步、不催办”这条链路上，是不改变审批规则前提下最小闭环；如果它无法把耗时从 2 天压到 4 小时，再讨论规则优化才有事实基础。
