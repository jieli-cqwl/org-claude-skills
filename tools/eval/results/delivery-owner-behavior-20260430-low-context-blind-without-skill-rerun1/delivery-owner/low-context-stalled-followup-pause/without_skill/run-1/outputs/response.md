理解：对象是“同一个交付缺口”的跟进决策；预期结果是判断是否继续普通催办，并给出门禁、阻断条件和下一步。

不继续普通催。两轮都只有“还在处理”，且没有新报告、新证据、新阻塞、也没有换 owner，应判定为交付跟进失效，进入阻断/升级状态。

**必需字段**
- `decision`: `BLOCK_AND_ESCALATE`
- `status`: `blocked`
- `reason`: 连续两轮无可验证进展，无法证明缺口正在收敛
- `missing`: 新报告、新证据、明确阻塞、owner 调整或恢复计划
- `forbidden_next`: 继续发送同类催办、接受“还在处理”作为进展
- `next_step`: 要求当前 owner 在明确时限内补交证据化进展；若无法提交，立即换 owner 或升级给上游决策人裁决

**门禁结果**
- 进展证据门禁：FAIL
- 阻塞透明度门禁：FAIL
- Owner 有效性门禁：FAIL
- 继续交付门禁：BLOCKED

**下一步**
暂停当前跟进循环，发起升级：要求产出“本轮新增事实 + 证据链接/报告 + 当前阻塞 + 下一动作 owner + 截止时间”。如果仍无法给出，不能继续推进该缺口，应移交或请求上游重新分配 owner。
