**推荐 UNIT 草案**
UNIT：`P1-U1 审批配置创建与生效闭环`

目标：具备配置权限的用户，可以为一个已确认的业务场景创建、校验、启用审批配置；配置启用后，业务触发审批时能够按该配置产出可观察的审批规则匹配结果。

输入/触发：
- 输入：审批业务场景、适用范围、审批节点/审批人规则、启用状态。
- 触发：配置用户新增、编辑、保存、启用或停用审批配置；业务对象进入“需要审批”的触发点。

核心行为：
- 支持创建一条审批配置。
- 保存前校验必填项、审批人规则和适用范围。
- 支持启用/停用配置。
- 同一业务场景触发审批时，只使用当前有效且匹配的配置。
- 配置异常或缺失时，给出明确的业务可理解结果。

可观察结果：
- 配置用户能看到配置的保存、校验、启用、停用状态。
- 业务触发审批后，能观察到命中的审批配置或明确的未命中/异常原因。
- 无效配置不会被启用或参与审批匹配。

Integration Context：
- 上游：M-S0 已确认 Phase 1 范围、审批业务场景和角色边界。
- 下游：交给 `design` 设计审批配置的信息结构、状态流和交互；交给 `test-design` 拆正常、异常、边界测试。
- 关联业务链路：审批配置管理链路 + 业务对象触发审批链路。
- 本 UNIT 只定义产品行为和验收，不规定页面、接口、数据库或具体实现方式。

**AC 草案**
正常场景：
- AC1：当具备配置权限的用户填写完整审批场景、适用范围和审批人规则后，保存成功，并能看到该配置处于可启用状态。
- AC2：当用户启用一条有效配置后，业务对象触发审批时，系统能够命中该配置并产出对应审批规则结果。
- AC3：当用户停用一条配置后，后续业务触发审批不再命中该配置。

异常场景：
- AC4：当审批场景、适用范围或审批人规则缺失时，配置不能启用，并提示缺失项。
- AC5：当审批人规则指向不可用对象时，配置不能启用，并提示规则不可用。
- AC6：当业务触发审批但不存在可用匹配配置时，系统给出明确的未配置/未命中结果，不进入不确定状态。

边界场景：
- AC7：当同一业务场景存在多条配置时，系统只能产生一个明确的有效匹配结果；如业务规则不允许多条并存，则阻止冲突配置启用。
- AC8：当配置被修改但未重新启用或确认生效时，业务触发审批仍遵循当前已生效配置。
- AC9：当适用范围刚好命中边界条件时，审批触发结果必须与配置规则一致，并可被测试复现。

Verification Plan：
- 用 1 条有效配置验证保存、启用、触发命中闭环。
- 用缺失字段、无效审批人、无匹配配置验证异常结果。
- 用重复/冲突配置、停用配置、范围边界验证边界行为。
- 验证证据以业务可观察结果为准：配置状态、触发后的命中结果、错误/阻断提示。

依赖：
- 已确认 Phase 1 支持的审批业务场景。
- 已确认配置用户角色和权限边界。
- 已确认审批人来源的业务定义，例如用户、角色、部门、负责人等。
- 已确认是否允许同一场景多条配置共存及其裁决规则。

排除项：
- 不包含审批单实际流转、同意/驳回/转交等处理能力。
- 不包含复杂多级审批、条件分支、会签/或签策略，除非 Phase 1 已明确包含。
- 不包含技术实现方案、接口设计、数据模型或页面布局。
- 不包含历史审批实例受配置变更影响的迁移规则，除非业务要求补充。

**裁决理由**
推荐拆成这个 UNIT，是因为它覆盖“配置产生、校验、启用、业务触发命中”的最小闭环，既能证明审批配置能力真实可用，又没有扩张到审批执行链路。当前仍有业务事实缺口，所以下一步用户只需选择此 UNIT、修正范围，或补充审批场景、审批人来源、冲突规则和 Phase 1 是否包含多级/条件审批。
