# 闭环 UNIT 规格

## 模板

```markdown
# UNIT-NNN: [闭环功能标题]

**优先级**: MVP | 增强 | 扩展

## 优先级依据
[为什么属于 MVP / 增强 / 扩展]

## 背景
[业务动机]

## 需求描述
[做什么、为什么]

## 功能闭环定义
- 输入/触发: [什么输入、什么状态或什么动作触发该功能]
- 核心行为: [系统做什么]
- 可观察结果: [外部可见结果是什么]

## 验收标准

### 正常场景
- AC-U1-01: [输入/操作] → [期望输出]

### 异常场景
- AC-U1-02: [输入/操作] → [期望错误/拒绝]

### 边界条件
- AC-U1-03: [边界条件] → [期望行为]

## 依赖
- 依赖 UNIT: [UNIT-NNN 列表，无则"无"]
- 依赖业务对象: [业务对象或业务状态，无则"无"]
- 受影响方: [需同步评估的现有功能/流程，无则"无"]

## 排除项
- [本需求明确不处理的场景]
```

## 质量标准

| 检查项 | 要求 |
|--------|------|
| 标题 | 必须是功能名/能力名，不是“梳理/建模/审计/SOP”等主题名 |
| 优先级 | 必须标注 MVP / 增强 / 扩展，并写明优先级依据 |
| 功能闭环定义 | 必须写清 `输入/触发 -> 核心行为 -> 可观察结果` |
| AC | 正常 / 异常 / 边界各 >= 1 |
| 依赖 + 排除项 | 必须显式列出 |

## 拆分规则

- 一个 UNIT 只表达一个闭环功能
- 若一个 UNIT 出现多个独立触发或多个独立结果，必须继续拆分
- 3 个及以上 UNIT 全部标为 `MVP` 时，必须补 `MVP 最小闭环说明`
