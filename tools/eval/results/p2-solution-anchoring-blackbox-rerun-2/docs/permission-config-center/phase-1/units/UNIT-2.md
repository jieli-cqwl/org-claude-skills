# UNIT-2: 调整项目角色权限

**优先级**: MVP

## 优先级依据
根问题的核心是配置慢和容易配错，真正解决问题必须能完成一次权限调整。

## 背景
项目管理员在确认当前权限后，需要能够快速完成常规的新增或移除操作。

## 需求描述
项目管理员在角色权限页中对当前资源权限进行新增、移除或保存当前状态的调整，提交后系统更新权限并保留变更痕迹。

## 功能闭环定义
- 输入/触发: 项目管理员在可管理项目内修改角色的资源权限并点击保存
- 核心行为: 系统校验权限范围，保存新的权限集合，并生成变更记录
- 可观察结果: 页面显示保存成功后的最新权限状态，同时留下可查询的变更痕迹

## 验收标准

### 正常场景
- AC-U2-01: 勾选新增一个资源权限后保存 → 页面显示保存成功且最新状态包含该权限

### 异常场景
- AC-U2-02: 对没有管理权限的项目提交修改 → 系统拒绝保存并不产生任何变更

### 边界条件
- AC-U2-03: 提交前后选择没有变化 → 系统提示无变更并保持当前状态不变

## 业务规则（如有）
- 只允许在自己有管理权限的项目内修改角色权限。
- 调整可以包含新增和移除，但本期不要求把批量调整做成独立能力。
- 每次成功保存都必须进入审计记录链路。

## 依赖
- 依赖 UNIT: UNIT-1
- 依赖业务对象: 项目、项目内角色、资源、权限集合、变更记录
- 受影响方: 权限变更记录查询、下游审计流程

## 排除项
- 不做跨项目继承。
- 不做组织架构同步。
- 不做复杂审批流。
