# UNIT-3: 查询权限变更记录

**优先级**: MVP

## 优先级依据
没有可查询的变更记录，就无法满足“改完后可追溯”的核心成功标准。

## 背景
权限调整后，项目管理员和审计查看者需要快速确认是谁在什么时候改了什么。

## 需求描述
项目管理员或审计查看者可以打开权限变更记录页，查看某项目内角色的历史调整记录，并看到操作人、时间和变更前后差异。

## 功能闭环定义
- 输入/触发: 用户打开某项目内角色的权限变更记录页
- 核心行为: 系统查询并展示该角色的变更历史
- 可观察结果: 页面出现可查询记录，且每条记录都能看到操作人、时间和前后差异

## 验收标准

### 正常场景
- AC-U3-01: 在成功完成一次权限调整后打开变更记录页 → 最新记录显示操作人、时间和变更前后差异

### 异常场景
- AC-U3-02: 对一个从未发生过变更的角色打开记录页 → 页面显示空状态，不报错

### 边界条件
- AC-U3-03: 按某个时间范围筛选但没有匹配记录 → 页面显示无结果状态且保留筛选条件

## 业务规则（如有）
- 变更记录必须可追溯，不允许人工删除或改写。
- 记录展示仅限项目管理员有权查看的项目范围。

## 依赖
- 依赖 UNIT: UNIT-2
- 依赖业务对象: 变更记录、项目内角色、操作人、时间戳、差异内容
- 受影响方: 审计查询、问题排查流程

## 排除项
- 不负责发起权限调整。
- 不负责审批或复核变更。
