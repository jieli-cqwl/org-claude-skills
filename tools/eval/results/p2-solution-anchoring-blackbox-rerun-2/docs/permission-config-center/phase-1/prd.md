# Phase 1: 项目级权限查看、调整与审计闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

本阶段只交付一个完整闭环：项目管理员先查看项目内角色的当前权限，再完成常规权限调整，最后可以查询到这次调整的可追溯记录。阶段内不引入跨项目继承、组织同步或复杂审批流。

## 入口与出口条件

- 入口条件: Brief 审查通过
- 出口条件: 本阶段所有 UNIT QA 通过

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 查看角色当前权限 | 输入/触发 → 展示当前角色的资源权限状态 → 项目管理员可直接确认现状 | MVP | - | units/UNIT-1.md |
| UNIT-2 | 调整项目角色权限 | 输入/触发 → 修改角色权限并保存 → 系统更新当前状态并记录变更 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查询权限变更记录 | 输入/触发 → 查询权限调整记录 → 可看到操作人、时间和前后差异 | MVP | UNIT-2 | units/UNIT-3.md |
