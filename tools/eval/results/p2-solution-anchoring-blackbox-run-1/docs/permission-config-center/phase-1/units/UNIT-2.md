# UNIT-2: 调整项目角色权限

**优先级**: MVP

## 优先级依据
根问题之一是常规授权调整效率低，若不能由项目管理员直接完成新增/移除操作，权限配置中心就无法兑现核心业务价值。

## 背景
当前项目级权限调整需要平台管理员手工改配置，流程慢且容易因人工传递造成误配。

## 需求描述
系统需要允许项目管理员在自己有权管理的项目内，对项目角色执行新增权限和移除权限操作，并在操作完成后立即反映最新状态，同时生成对应变更记录。

## 功能闭环定义
- 输入/触发: 项目管理员在查看到当前角色权限后，对某角色提交新增或移除权限操作
- 核心行为: 系统校验项目管理权限，保存权限变更，更新该角色当前权限状态，并生成审计记录
- 可观察结果: 调整成功后，角色当前权限立即显示最新结果，且该次调整可被后续查询追溯

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景
- AC-U2-01: 项目管理员在自己有权管理的项目 A 中，为角色 R 新增资源权限 P 并提交 → 系统返回提交成功，角色 R 的当前权限结果中出现 P，且生成一条对应变更记录

### 异常场景
- AC-U2-02: 项目管理员尝试调整自己无管理权限的项目 B 中角色权限并提交 → 系统拒绝本次调整，返回“无权修改该项目权限”的结果，且项目 B 目标角色原权限保持不变

### 边界条件
- AC-U2-03: 项目管理员移除角色 R 当前最后一项已授权权限并提交 → 系统返回提交成功，角色 R 当前权限结果更新为“无已授权权限”，且变更记录仍保留本次前后差异

## 业务规则（如有）
- 本期权限调整仅包含新增和移除，不包含复杂审批或批量授权。
- 每次调整都必须写入操作人、时间、变更前后差异。

## 依赖
- 依赖 UNIT: UNIT-1
- 依赖业务对象: 项目、项目内角色、资源权限项、权限变更记录
- 受影响方: 项目管理员权限调整流程、权限审计流程

## 排除项
- 不定义批量调整能力。
- 不处理跨项目继承带来的联动调整。
