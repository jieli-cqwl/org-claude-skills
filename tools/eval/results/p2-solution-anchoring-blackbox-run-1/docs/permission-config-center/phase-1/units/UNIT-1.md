# UNIT-1: 查看项目角色当前权限

**优先级**: MVP

## 优先级依据
如果项目管理员不能先看清当前角色拥有哪些资源权限，就无法判断是否需要调整，也无法降低误配风险，因此这是最小闭环的入口能力。

## 背景
当前项目侧往往需要找平台管理员人工核对角色权限，信息分散且容易理解偏差。

## 需求描述
系统需要为项目管理员提供查看某个项目内角色当前权限的能力，明确展示该角色已拥有的功能模块和数据范围权限，作为后续调整和审计的事实基线。

## 功能闭环定义
- 输入/触发: 项目管理员进入权限配置中心，选择自己有权管理的项目和项目内角色
- 核心行为: 系统读取该角色当前权限集合，并按资源维度返回当前授权状态
- 可观察结果: 项目管理员能直接看到该角色当前拥有的功能模块和数据范围权限

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景
- AC-U1-01: 项目管理员选择自己有权管理的项目 A 和角色 R → 系统展示角色 R 当前拥有的功能模块权限和数据范围权限，且每项权限状态可直接识别

### 异常场景
- AC-U1-02: 项目管理员尝试查看自己无管理权限的项目 B 的角色权限 → 系统拒绝展示该项目权限信息，并返回“无权查看该项目权限”的结果

### 边界条件
- AC-U1-03: 项目管理员选择的角色当前没有任何已授权资源 → 系统返回“当前无已授权权限”的明确状态，且不展示不确定或空白结果

## 业务规则（如有）
- 仅允许查看自己有权管理的项目内角色权限。
- 权限结果至少包含功能模块和数据范围两个资源维度。

## 依赖
- 依赖 UNIT: 无
- 依赖业务对象: 项目、项目内角色、资源权限项
- 受影响方: 项目管理员权限查看流程

## 排除项
- 不规定权限信息必须以树形结构展示。
- 不覆盖公司统一身份角色或跨项目权限聚合查看。
