# UNIT-3: 查询权限变更记录

**优先级**: MVP

## 优先级依据
根问题明确包含“事后难审计”，如果没有标准化的变更记录查询能力，即使调整效率提升，也无法完成追溯闭环。

## 背景
权限问题发生后，当前流程通常无法快速回答“谁在什么时候改了哪些权限”，排查高度依赖人工沟通和零散记录。

## 需求描述
系统需要允许项目管理员或审计相关角色查询某个项目内角色的权限变更记录，明确展示每次调整的操作人、时间和变更前后差异。

## 功能闭环定义
- 输入/触发: 项目管理员或审计相关角色对指定项目和角色发起变更记录查询
- 核心行为: 系统读取该角色历史权限变更记录，并返回与查询条件匹配的审计条目
- 可观察结果: 查询者可看到每次调整的操作人、时间和变更前后差异，用于追溯变更来源

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景
- AC-U3-01: 项目管理员查询自己有权管理的项目 A 中角色 R 的历史权限变更 → 系统返回至少包含操作人、操作时间、变更前、变更后的记录列表

### 异常场景
- AC-U3-02: 查询者尝试查询自己无权访问的项目 B 的角色变更记录 → 系统拒绝返回该项目变更记录，并返回“无权查看该项目变更记录”的结果

### 边界条件
- AC-U3-03: 指定项目和角色当前还没有任何权限变更历史 → 系统返回“暂无变更记录”的明确状态，而不是空白或报错

## 业务规则（如有）
- 变更记录至少保留操作人、时间、变更前后差异三类信息。
- 展示结构可由 design 决定，但不得影响追溯信息可见性。

## 依赖
- 依赖 UNIT: UNIT-2
- 依赖业务对象: 项目、项目内角色、权限变更记录
- 受影响方: 权限问题排查流程、审计追溯流程

## 排除项
- 不定义记录必须以时间线方式展示。
- 不覆盖跨项目合并审计报表。
