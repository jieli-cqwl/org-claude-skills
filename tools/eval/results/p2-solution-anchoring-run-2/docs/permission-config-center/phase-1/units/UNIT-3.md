# UNIT-3: 查询权限变更记录

**优先级**: MVP

## 优先级依据

如果做完调整却无法追溯是谁在什么时间改了什么，项目管理员依然无法完成审计和复盘闭环，这会直接削弱本需求的业务价值。

## 背景

权限问题当前很难复盘，出现异常时通常需要继续依赖平台管理员翻日志确认是谁做了什么操作。

## 需求描述

提供权限变更记录查询能力，让项目管理员或负责人能够查看某个项目角色的历史权限调整，并知道操作人、操作时间和变更前后差异。

## 功能闭环定义

- 输入/触发: 项目管理员进入某个项目角色的权限变更记录页
- 核心行为: 系统按项目和角色返回对应的权限调整历史
- 可观察结果: 用户可看到操作人、操作时间、变更前后差异；无记录时有明确空状态

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U3-01: 项目管理员查看项目 A 的角色 R 变更记录 → 页面展示每次变更的操作人、时间和前后差异

### 异常场景

- AC-U3-02: 无项目 A 管理权限的用户访问角色 R 变更记录页 → 系统拒绝访问并展示明确的权限不足结果

### 边界条件

- AC-U3-03: 项目 A 的角色 R 尚无任何权限变更记录 → 页面展示明确的空状态提示，而不是报错或空白

## 业务规则（如有）

- 变更记录至少保留操作人、时间和前后差异。
- 变更记录用于追溯，不承担重新配置权限的入口职责。

## 依赖

- 依赖 UNIT: UNIT-2
- 依赖业务对象: 权限变更记录、项目角色
- 受影响方: 审计查询能力、项目管理后台角色详情入口

## 排除项

- 不包含统计报表能力。
- 不包含复杂筛选和导出能力。
