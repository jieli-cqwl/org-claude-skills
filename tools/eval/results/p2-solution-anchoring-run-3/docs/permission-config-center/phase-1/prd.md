# Phase 1: 项目级权限治理最小闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

交付一条完整的项目级权限治理链路：项目管理员能够先理解角色当前权限，再完成一次常规授权调整，并在事后追溯对应变更。

## 入口与出口条件

- 入口条件: Brief 审查通过
- 出口条件: 本阶段所有 UNIT QA 通过，且用户可以独立完成“看状态、做调整、查责任”的完整链路

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 查看项目角色当前权限 | 项目管理员进入角色权限页 → 系统展示当前权限状态 → 用户获得现状认知 | MVP | - | units/UNIT-1.md |
| UNIT-2 | 调整项目角色资源权限 | 项目管理员提交新增或移除授权 → 系统校验并保存变更 → 当前权限即时更新 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查询权限变更记录 | 项目管理员进入记录页 → 系统返回操作人/时间/差异 → 用户完成追溯 | MVP | UNIT-2 | units/UNIT-3.md |
