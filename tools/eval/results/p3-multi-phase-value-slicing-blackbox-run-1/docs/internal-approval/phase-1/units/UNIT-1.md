# UNIT-1: 提交审批申请

**优先级**: MVP

## 优先级依据

没有申请提交入口，审批流程无法开始，也无法形成后续审批与记录查询闭环，因此属于最小闭环的起点能力。

## 背景

当前审批申请通过聊天工具或表格发起，入口不统一，导致记录分散且后续难追踪。

## 需求描述

员工需要能够发起一笔审批申请。系统在收到有效申请后，创建对应审批记录，并把当前状态初始化为“待处理”，为后续审批和历史查询提供基础。

## 功能闭环定义

- 输入/触发: 员工提交一笔审批申请
- 核心行为: 系统校验提交内容并创建审批申请与对应记录
- 可观察结果: 申请创建成功后可见一笔状态为“待处理”的审批记录

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U1-01: 员工提交一笔有效审批申请 -> 系统创建申请成功，并生成一条状态为“待处理”的审批记录

### 异常场景

- AC-U1-02: 员工提交缺少必填信息的审批申请 -> 系统拒绝提交，并明确提示申请未创建

### 边界条件

- AC-U1-03: 员工提交成功后立即查看该申请记录 -> 记录中可见提交人、提交时间和当前状态“待处理”

## 业务规则（如有）

- 申请创建成功后必须立即形成可查询记录。
- 本期不要求定义复杂申请类型或多级流转规则。

## 依赖

- 依赖 UNIT: 无
- 依赖业务对象: 审批申请、审批记录
- 受影响方: 无

## 排除项

- 不处理企业微信通知。
- 不处理驳回后重新提交。
- 不处理多级会签与复杂 SLA。
