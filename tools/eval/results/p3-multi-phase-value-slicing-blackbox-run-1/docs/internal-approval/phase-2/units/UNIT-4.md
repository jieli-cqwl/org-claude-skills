# UNIT-4: 审批状态变更通知

**优先级**: 增强

## 优先级依据

通知能力能提升信息触达效率，但不影响审批闭环是否成立；即使没有通知，用户仍可通过记录查看结果，因此属于增强项。

## 背景

在 Phase 1 中，用户需要主动查看记录才能获知结果。后续希望通过企业微信通知减少人工关注成本。

## 需求描述

当审批状态发生变化时，系统需要向相关人发送企业微信通知，让用户在不主动查询的情况下也能及时获知审批结果。

## 功能闭环定义

- 输入/触发: 一笔审批申请状态从“待处理”变为“通过”或“驳回”
- 核心行为: 系统触发通知流程并向相关人发送结果提醒
- 可观察结果: 相关人收到能识别申请结果的通知消息

## 验收标准

> AC 编号格式: `AC-U{UNIT序号}-{序号}`（如 AC-U1-01），由 product 定义权威编号，UNIT 内唯一递增。

### 正常场景

- AC-U4-01: 审批申请状态更新为“通过” -> 相关人收到一条包含申请结果为“通过”的企业微信通知

### 异常场景

- AC-U4-02: 通知发送失败 -> 系统记录该次失败，不影响审批结果本身已更新

### 边界条件

- AC-U4-03: 同一笔申请仅发生一次状态变更 -> 相关人仅收到与该次变更对应的结果通知

## 业务规则（如有）

- 通知能力依赖审批结果已产生。
- 本阶段只定义业务期望，不定义具体触发和补偿技术方案。

## 依赖

- 依赖 UNIT: UNIT-2、UNIT-3
- 依赖业务对象: 审批结果、审批记录
- 受影响方: 申请人、审批人

## 排除项

- 不定义企业微信接入方案细节。
- 不定义通知重试、补偿、去重算法。
- 不把通知作为审批成功的前置条件。
