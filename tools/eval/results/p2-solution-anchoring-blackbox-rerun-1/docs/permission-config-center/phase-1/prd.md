# Phase 1: 项目级权限查看、调整与追溯闭环

> 项目背景、约束与设计决策见 [brief.md](../brief.md)

## 阶段目标

本阶段交付项目级权限管理的最小闭环：项目管理员先看清当前权限，再完成一次权限调整，最后能够查询到可追溯的变更记录。这里不把角色树、批量授权或复杂审批流当成本阶段的必做范围。

## 入口与出口条件

- 入口条件: Brief 审查通过
- 出口条件: Phase 1 所有 UNIT QA 通过

## 功能需求（UNIT 索引）

| UNIT | 标题 | 闭环目标 | 优先级 | 依赖 | 定义文件 |
|------|------|----------|--------|------|----------|
| UNIT-1 | 查看项目角色权限 | 项目管理员进入已管理项目的权限中心并选择角色 → 展示当前角色拥有的资源权限 → 当前状态可直接查看 | MVP | 无 | units/UNIT-1.md |
| UNIT-2 | 调整项目角色权限 | 项目管理员对已管理项目角色提交一次权限调整请求 → 系统校验范围并保存变更 → 当前权限状态更新且返回成功 | MVP | UNIT-1 | units/UNIT-2.md |
| UNIT-3 | 查询权限变更记录 | 项目管理员查询某项目/角色的权限变更记录 → 系统返回操作人、时间、变更前后差异 → 变更可追溯 | MVP | UNIT-2 | units/UNIT-3.md |
