# UNIT-2: 调整项目角色权限

**优先级**: MVP

## 优先级依据
这是解决“开权限慢”的核心动作，没有调整能力，查看和追溯都只能停留在旁路。

## 背景
项目管理员现在往往要靠平台管理员代操作，导致权限变更速度慢，还容易在传递过程中出错。

## 需求描述
提供一次项目级权限调整能力，让项目管理员对自己有权管理的项目角色提交新增或移除权限的请求，并在提交后看到当前权限状态被更新。

## 功能闭环定义
- 输入/触发: 项目管理员对一个自己有权管理的项目角色提交一次权限调整请求
- 核心行为: 系统校验项目范围与操作权限，执行权限新增或移除，并保存变更结果
- 可观察结果: 权限状态更新成功，且用户能确认本次调整已经生效

## 验收标准

### 正常场景
- AC-U2-01: 项目管理员对自己管理的项目角色新增一个权限 → 系统保存成功且当前权限状态同步更新

### 异常场景
- AC-U2-02: 项目管理员尝试修改自己无权管理的项目角色 → 系统拒绝本次调整且当前权限状态不变

### 边界条件
- AC-U2-03: 用户提交的调整不会改变权限集合（例如重复新增已存在权限） → 系统返回明确的无效变更结果且不更新状态

## 业务规则（如有）

- 本期仅覆盖项目级角色权限调整。
- 每次调整都必须属于当前管理员有权管理的项目。

## 依赖
- 依赖 UNIT: UNIT-1
- 依赖业务对象: 项目、角色、资源、权限映射
- 受影响方: 权限配置入口、权限校验执行链路、审计记录生成链路

## 排除项
- 不做跨项目继承
- 不做组织架构同步
- 不做复杂审批流
- 不把批量调整作为本 UNIT 的必做能力
