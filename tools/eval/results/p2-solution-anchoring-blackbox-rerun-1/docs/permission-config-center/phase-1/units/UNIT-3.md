# UNIT-3: 查询权限变更记录

**优先级**: MVP

## 优先级依据
没有变更记录，就无法满足“改完后可追溯”的业务目标，也无法解释谁在什么时候改了什么。

## 背景
权限调整后，项目管理员和排查人员需要快速知道操作人、时间以及变更前后差异。

## 需求描述
提供一个可查询的权限变更记录能力，让项目管理员能够查看某个项目或角色的权限变更历史。

## 功能闭环定义
- 输入/触发: 项目管理员打开某项目或角色的变更记录入口
- 核心行为: 系统查询并展示对应的权限变更记录，包含操作人、时间和变更前后差异
- 可观察结果: 用户可以直接追溯到本次或历史权限调整的具体内容

## 验收标准

### 正常场景
- AC-U3-01: 项目管理员查询自己管理项目的权限变更记录 → 页面返回包含操作人、时间和差异内容的记录

### 异常场景
- AC-U3-02: 未被授权管理该项目的用户尝试查询变更记录 → 系统拒绝访问且不暴露记录内容

### 边界条件
- AC-U3-03: 目标项目暂时没有任何权限变更记录 → 页面显示空状态，不报错

## 业务规则（如有）

- 变更记录必须包含操作人、时间和变更前后差异。
- 变更记录的展示形式由 design 决定，但可查询性必须保留。

## 依赖
- 依赖 UNIT: UNIT-2
- 依赖业务对象: 项目、角色、变更记录、权限映射
- 受影响方: 审计查询入口、权限变更落库链路

## 排除项
- 不做变更分析报表
- 不做导出
- 不强制规定时间线展示样式
