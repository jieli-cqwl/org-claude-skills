# 运行时现状采证方法

## 目标

把会改变架构决策的运行时事实变成可复查证据。只采会影响边界、数据、接口、质量、迁移、回滚或风险回应的事实。

## 采证边界

- 使用只读命令或只读 API；采证动作保持只读，不改配置、重启进程、写文件或改变运行态。
- 采证前先写 `输入边界`：本轮要验证的系统事实、关联决策和不采的无关信息。
- 每条事实写当前观测值、采证方式、数据来源、`evidence=` 和 `observed_at=`。
- 采证摘要包含 `输入边界`、`当前判断`、`证据锚点`、`未决项（如有）`、`禁止越权项`。

## 有效证据

有效证据包括输入基线引用、源码/配置路径、只读命令输出、第三方只读 API 响应或用户明确确认。

无效证据包括 `design.json#input_analysis` 自指、`design.json#runtime_facts` 自指、agent 自我报告、未保存的口头推断和无法复验的概括句。

## 采证维度

- 运行环境、部署拓扑、配置中心、数据源、外部中间件、密钥管理、链路可达性、已知偏差 vs 设计约束。
- 采证方式按场景选择：环境信息、进程状态、端口监听、服务状态、配置读取、依赖连通性、数据源只读探测、文件元数据或第三方只读 API。
- 命令保持只读、可复验，并与本轮设计决策直接相关。

纯代码层重构写「运行时采证不适用」、理由、源码证据和 `observed_at=`；这条事实只能支撑“不需要运行态采证”的判断。

## 产出

写入会影响架构决策的运行时事实、待补采项和阻塞原因。每条事实都能被 ASR 提炼、复杂度建模、方案取舍、设计合成或风险回应消费。

## 阻断路由

- 运行时实际与设计预期不一致时，写差异、影响决策和回流环节。
- SSH、账号、鉴权或第三方限流导致采证受阻时，写 `待补采 + 阻塞原因 + owner + 预期恢复方式`。
- 影响冻结决策的事实未验证时阻断；只影响后续验证时写入风险或验证义务。
