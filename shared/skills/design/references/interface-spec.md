# 接口契约定义标准

## 目标

让接口边界可实现、可测试、可回滚。接口契约写调用双方对输入、输出、错误和边界行为的共同承诺。

## 完整性

每个接口包含：入参（字段/类型/校验规则）、出参（成功响应格式）、错误码（至少参数校验错误、业务逻辑错误、系统错误）。

边界行为是一等契约。权限、幂等、并发、状态转换、超时、重试、降级、幂等键、重复提交、跨标签页、缓存命中/失效和异常恢复，只要影响调用双方预期，就写入 `boundary_behaviors` 或 `interface_boundary`。边界行为必须能被 `/test-design` 转成断言。

## 定义档位

| 档位 | 触发条件 | 定义方式 |
|------|---------|---------|
| 精简版 | 接口 <= 3 且非全栈 | 简化结构内联 `design.json.interface_boundary` |
| 标准版 | 接口 4-10 或全栈功能（不论接口数） | `design.json.interface_boundary` 结构化描述 |
| 增强版 | 接口 > 10 或对外 API | 在 `design.json.interfaces` 和 `interface_boundary` 完整结构化，必要时再投影为 API 展示文档 |

全栈功能判定：PRD/UNIT 同时涉及前端页面/组件和后端 API/Service。即使只有 1 个接口，只要存在前后端交互，就结构化定义。

## 结构化要素

```markdown
### {METHOD} {PATH}
描述: {一句话}
入参: | 字段 | 类型 | 必填 | 校验规则 | 说明 |
出参（成功 {STATUS_CODE}）: 成功响应结构
错误码: | 协议/状态码 | error_code | 触发条件 | 用户消息 key |
边界行为: | 场景 | 预期行为 |
```

## 产出

接口设计支撑 `/test-design` 生成断言：正常路径、校验失败、业务失败、系统失败、权限/幂等/并发等边界行为。接口内容要能转成断言；缺少断言信息时回到接口定义补齐。
