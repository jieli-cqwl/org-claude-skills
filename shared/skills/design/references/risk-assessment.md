# 风险评估方法

## 目标

识别会阻断实施、放大业务损失或破坏回滚能力的风险，并给出可执行缓解动作。

## 识别信号

| 维度 | 常见信号 |
|------|------|
| 技术风险 | 性能瓶颈、迁移失败、外部依赖不稳定 |
| 交付风险 | 单点知识、跨团队阻塞、关键资源冲突 |
| 业务风险 | 合规缺口、核心流程失败、数据偏差 |

## 评估矩阵

按概率 P × 影响 I 评估优先级：

| P\I | 高影响 | 中影响 | 低影响 |
|-----|--------|--------|--------|
| 高概率 | P0 | P1 | P2 |
| 中概率 | P1 | P2 | P3 |
| 低概率 | P2 | P3 | P3 |

## 裁决标准

- P0：写清可执行缓解动作、验证方式和回滚触发；缺任一项时保持阻断。
- P1：写清缓解动作、负责人或下游承接路径。
- 任意风险：用动作、证据或触发条件闭合；“关注/监控”只能作为观测手段。
- 复杂防护绑定高影响风险；证据不足时选择更小的验证或升级路径。
- 高影响风险写入 `risk_response`、`verification_mapping`、`rollback_plan` 或 `planning_constraints` 中至少一个可执行承接点。

## 有效风险回应

- 缓解动作要改变风险概率、影响或发现时间；“关注/监控”只作为观测手段。
- 高影响风险写清触发阈值、负责人、验证方式和回滚或升级路径。
- 复杂防护绑定具体风险；缺少高影响场景支撑时走验证或升级路径。

## 产出

每条风险写清维度、概率、影响、优先级、缓解动作、验证方式、回滚触发或升级路径。高优风险缺少可设计缓解动作时，升级给用户裁决。
