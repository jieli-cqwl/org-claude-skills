# Agent6: 文档一致性扫描规则

> 引用者：scan（Agent 6）| 文档管理规则：`{{RUNTIME_HOME}}/rules/文档管理.md`

## 前置条件

项目含 `docs/` 目录或 `README.md`。两者皆无时输出"项目无文档体系，跳过扫描"，不计入健康度评分。

## 扫描范围

- `docs/` 下所有 `.md` 文件（排除 `docs/archive/`）
- 项目根目录 `README.md`
- 不扫描：`node_modules/`、`.venv/`、`vendor/` 等依赖目录
- 不扫描：图片/PDF 等非文本文档

## 检测维度

### V1: 引用有效性

| 检测项 | 方法 | 严重度 |
|--------|------|--------|
| 文件路径引用失效 | Grep 文档中 `见 xxx`/`详见 xxx`/`See xxx`/`[xxx](xxx)` 模式 → 检查目标文件存在性 | 警告 |
| 符号引用失效 | 文档中引用的函数名/类名（`\`xxx()\``/`class xxx`） → Grep 代码库确认存在 | 警告 |

> 仅检测显式路径引用和反引号包裹的符号引用。代码块内（```...```）的内容不检测。

### V2: 归档状态

| 检测项 | 方法 | 严重度 |
|--------|------|--------|
| 已完成未归档 | `docs/{feature}/` 含 `qa-report.md` 且内容含 `PASS` → 检查是否仍在 docs/ 而非 archive/ | 建议 |
| Phase 已完成未归档 | `docs/{feature}/phase-*/qa-report.md` 含 `PASS` → 检查 `phase-{N}/` 是否仍在活跃区 | 建议 |
| Phase 目录命名不符合 | `docs/{feature}/` 下存在 `phase-{N}/` 子目录时，检查目录名是否符合 `phase-{数字}` 格式 | 警告 |
| UNIT 目录命名不符合 | `docs/{feature}/phase-{N}/` 下存在 `unit-{N}/` 子目录时，检查目录名是否符合 `unit-{数字}` 格式 | 警告 |

### V3: 过时检测

| 检测项 | 方法 | 严重度 |
|--------|------|--------|
| 文档可能过时 | 文档中显式引用的代码文件 → `git log -1 --format=%ai` 比较两者最后修改时间 → 差值 > 30 天 | 建议 |

> 关联关系仅基于文档中显式引用的文件路径，不做模糊推测。

### V4: README 准确性

| 检测项 | 方法 | 严重度 |
|--------|------|--------|
| README 为空 | `wc -l README.md == 0` | 建议 |
| 引用路径不存在 | README 中引用的文件/目录路径 → 检查存在性 | 警告 |
| 命令可能过时 | README 中 `\`\`\`bash` / `\`\`\`shell` 块内的 `npm`/`pip`/`python`/`go` 命令 → 检查 package.json scripts 或入口文件是否匹配 | 警告 |

### V5: 结构完整性

| 检测项 | 方法 | 严重度 |
|--------|------|--------|
| 缺少设计文档 | `docs/{feature}/` 含 `brief.md` 但无 `design.md` 且含代码实现文件引用 | 建议 |

## 边界处理

| 场景 | 处理 |
|------|------|
| `docs/` 只有 `archive/` | 输出"所有文档已归档，无活跃文档需扫描" |
| 文档中的代码块引用 | 不检测（```...``` 内的路径不视为文件引用） |
| 第三方文档 | 跳过（依赖目录下的文档） |

## 严重度映射

| 条件 | 严重度 |
|------|--------|
| 引用失效 | 警告 |
| README 不准确 | 警告 |
| 归档未清理 | 建议 |
| 结构缺失 | 建议 |
| 过时检测 | 建议 |
