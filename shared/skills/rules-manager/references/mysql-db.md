# MySQL 规则模板

1. 数据库变更用什么管理？Flyway / Liquibase / 手动 SQL 脚本？
2. ORM 框架是 MyBatis / MyBatis-Plus / JPA？有没有直接写原生 SQL 的场景？
3. 有没有分库分表？读写分离？

## 规则草稿 + 共创提问（init Step 3 使用）

### 规则 1：表设计规范

```
表名使用 snake_case 小写，禁止使用 MySQL 保留字。
每张表必须有自增主键 id（BIGINT）和 create_time、update_time 字段。
字段注释（COMMENT）必须填写业务含义。
```

**共创提问**：你们的主键策略是自增还是雪花算法？有没有统一的审计字段（create_by、update_by、is_deleted）？软删除还是硬删除？

### 规则 2：索引规范

```
WHERE 条件中频繁使用的字段必须建索引。
联合索引遵循最左前缀原则，字段顺序按区分度从高到低排列。
单表索引数量不超过 5 个，禁止冗余索引。
```

**共创提问**：你们有没有定期的慢查询分析机制？索引命名有约定吗（如 idx_表名_字段名）？

### 规则 3：SQL 编写规范

```
禁止 SELECT *，必须明确列出字段。
大表查询必须分页，单次查询结果集不超过 1000 条。
禁止在 WHERE 条件中对索引列使用函数或隐式类型转换。
```

**共创提问**：你们的分页限制具体是多少？有没有需要全表扫描的批处理场景？这些场景怎么处理的？

### 规则 4：变更管理

```
数据库结构变更必须通过迁移脚本管理，禁止直接在生产环境手动执行 DDL。
迁移脚本必须包含回滚方案。
大表 DDL（ALTER TABLE）必须评估锁表影响，记录预计执行时间。
```

**共创提问**：你们用 Flyway/Liquibase 还是手动管理 SQL 脚本？迁移脚本放在哪个目录？有没有 DBA 审核流程？

### 规则 5：数据安全

```
敏感字段（手机号、身份证、密码）必须加密存储，查询结果必须脱敏展示。
密码存储使用 BCrypt 或 PBKDF2，禁止 MD5/SHA1。
数据库连接信息禁止硬编码，必须通过配置中心或环境变量管理。
```

**共创提问**：你们有哪些字段属于敏感数据？脱敏是在 SQL 层做还是应用层做？有没有统一的加解密工具类？

## 生成的规则文件 paths 配置

```yaml
---
paths:
  - "**/*.sql"
  - "**/mapper/**/*.xml"
  - "**/mybatis/**/*.xml"
  - "**/migration*/**"
---
```

> paths 根据实际项目结构调整。如果使用 JPA 无 XML mapping，移除 mapper/mybatis 相关 glob。共创时确认后调整。
