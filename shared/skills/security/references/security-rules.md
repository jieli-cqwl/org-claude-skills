# Security Rules Reference

## 语言检测

| 标识文件 | 语言 | 推荐工具 |
|---------|------|----------|
| `pyproject.toml` / `requirements.txt` | Python | Bandit + pip-audit |
| `package.json` | JavaScript/TypeScript | Semgrep + npm audit + eslint-plugin-security |
| `pom.xml` / `build.gradle` | Java | Semgrep + SpotBugs |
| `go.mod` | Go | Semgrep + govulncheck |
| `Dockerfile` / `docker-compose.yml` | 容器 | Trivy |
| 混合项目 | 多语言 | Semgrep (全栈) + Trivy (容器) |

## OWASP Top 10 检查清单

| 编号 | 类别 | 检查项 |
|------|------|--------|
| A01 | 访问控制缺陷 | 权限校验缺失、越权访问 |
| A02 | 加密失败 | 明文存储、弱加密算法 |
| A03 | 注入攻击 | SQL/命令/XSS 注入 |
| A04 | 不安全设计 | 业务逻辑漏洞 |
| A05 | 安全配置错误 | 默认配置、调试模式 |
| A06 | 易受攻击组件 | 已知漏洞依赖 |
| A07 | 身份认证失败 | 弱密码、会话管理 |
| A08 | 数据完整性 | 不安全的反序列化 |
| A09 | 日志监控失败 | 敏感信息日志 |
| A10 | SSRF | 服务端请求伪造 |

## AI 重点检查（工具盲区）

- 业务逻辑漏洞（支付绕过、权限提升）
- 上下文相关漏洞（框架特定配置问题）
- 组合漏洞（多低危 → 高危）

## STRIDE 威胁建模框架

> 适用场景：系统架构级安全评审时使用，单文件扫描仍以 OWASP Top 10 为主。

| 维度 | 威胁类别 | 典型检查点 | OWASP 映射 |
|------|---------|-----------|-----------|
| S | Spoofing（仿冒） | 身份伪造、Token 劫持、会话固定 | A07 身份认证失败 |
| T | Tampering（篡改） | 请求参数篡改、数据库直接修改、中间人攻击 | A03 注入、A08 数据完整性 |
| R | Repudiation（抵赖） | 缺少审计日志、日志可被篡改、关键操作无记录 | A09 日志监控失败 |
| I | Information Disclosure（信息泄露） | 错误堆栈暴露、敏感数据明文传输、日志泄露凭证 | A02 加密失败、A05 安全配置错误 |
| D | Denial of Service（拒绝服务） | 资源耗尽、无速率限制、大文件上传无限制 | A05 安全配置错误 |
| E | Elevation of Privilege（提权） | 越权访问、角色绕过、默认管理员权限 | A01 访问控制缺陷 |

使用方式：对每个系统组件/数据流逐一过 STRIDE 六维度，记录威胁场景和缓解措施。

## 误报处理

- 确认误报标记 `[误报]` 并说明原因
- 风险高估的降低严重程度
- 已确认误报记入 `.security-ignore`（每条须注明原因）

## 可自动修复的漏洞

| 漏洞类型 | 修复方式 | 置信度 |
|---------|---------|--------|
| 硬编码密钥 | 移至环境变量 | 高 |
| SQL 注入 | 参数化查询 | 高 |
| 弱哈希算法 | 替换为安全算法 | 高 |
| 不安全依赖 | 升级到安全版本 | 中 |

## 需人工确认的漏洞

| 漏洞类型 | 原因 |
|---------|------|
| 业务逻辑漏洞 | 需理解业务上下文 |
| 权限控制问题 | 可能影响功能 |
| 配置变更 | 可能影响其他环境 |
