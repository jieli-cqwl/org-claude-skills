# E2E 用户旅程测试方法论

## 0. 定义边界

| 术语 | 定义 | 工具约束 |
|------|------|----------|
| E2E | 真实用户入口下的完整任务闭环验证，必须覆盖跨步骤状态流转与最终结果 | 不限定工具 |
| 浏览器 E2E | 当真实入口是 Web/H5，且验收依赖页面渲染、交互反馈、前端状态或路由行为时的 E2E | 必须通过浏览器执行 |

原则：
- E2E 是完整任务闭环验证，覆盖任意真实入口；浏览器 E2E 是其中 Web/H5 入口的子集。
- 命中 `execution_mode=browser_required` 时，`QA_B` 走浏览器 E2E；证据必须来自浏览器执行。
- 浏览器执行默认使用 `webapp-testing` / Playwright；项目浏览器插件可替代，但证据强度必须等价。

## 1. 旅程识别

### 从 AC 组合推导用户操作路径

| 步骤 | 方法 |
|------|------|
| 1. 提取动作 | 从 PRD AC 中提取所有用户动作（创建/读取/更新/删除/搜索） |
| 2. 排列时序 | 按用户自然使用顺序排列动作（注册 → 登录 → 操作 → 退出） |
| 3. 识别数据依赖 | 标记哪些步骤的输出是后续步骤的输入 |
| 4. 组合旅程 | 将关联的动作组合为完整旅程 |

### 旅程类型

| 类型 | 说明 | 必要性 |
|------|------|--------|
| 核心路径（Happy Path） | 用户最常见的完整操作流 | 必测 |
| 异常中断路径 | 操作中途遇到错误/中断后的恢复 | 必测 |
| UX 检查点 | 关键状态反馈、错误提示、交互连贯性 | 条件触发时必测 |
| 分支路径 | 用户选择不同选项的变体流程 | 选测 |

## 1.1 何时必须浏览器 E2E

默认必须标记 `browser_required` 的场景：
- 登录/权限/重定向/路由守卫
- 多步骤表单/向导/下单流
- 文件上传下载
- 富交互状态切换
- 错误提示与恢复路径
- 关键 UX 反馈会影响任务完成

如果是否通过验收，取决于页面本身而不是后端结果，就应判定为 `browser_required`。

## 2. 旅程设计

### 核心路径设计

1. 从"新用户首次使用"视角出发
2. 串联所有必经步骤
3. 每步记录：操作 + 输入 + 期望输出 + 数据传递

### 异常中断路径设计

| 中断点 | 设计策略 |
|--------|---------|
| 步骤 N 失败 | 验证步骤 1~N-1 的数据未被破坏 |
| 中途退出 | 验证部分完成的数据状态 |
| 重复操作 | 验证幂等性（同一步骤执行两次） |
| 并发操作 | 两个用户同时操作同一资源 |

### 浏览器执行设计

当 `execution_mode=browser_required` 时，额外记录：
- `browser_tool`: `webapp-testing` / `Playwright` / 项目浏览器插件
- `entry_url`: 真实入口 URL 或首个可导航页面
- `browser_evidence`: 至少 1 个有效锚点
  - `screenshot=...`
  - `trace/video=...`
  - `browser_log=...`
  - `webapp-testing=...` 或 `Playwright=...`

## 3. 数据流转验证

| 检查项 | 验证方法 |
|--------|---------|
| 前序输出 → 后续输入 | 步骤 A 返回的 ID 在步骤 B 中可用 |
| 数据持久性 | 步骤 A 创建的数据在步骤 B 中可查询到 |
| 数据一致性 | 步骤 A 修改的字段在步骤 B 中反映变更 |
| 跨接口一致性 | 创建接口返回的数据与查询接口返回的一致 |

## 4. 状态持久性验证

| 检查项 | 验证方法 |
|--------|---------|
| 数据库状态 | 旅程结束后查询数据库确认最终状态 |
| 缓存一致性 | 缓存中的数据与数据库一致 |
| 文件状态 | 上传/生成的文件在后续步骤中可访问 |
| 会话状态 | 用户会话在多步骤间保持 |

## 5. UX / 恢复检查点

| 检查项 | 验证方法 |
|--------|---------|
| 状态可见性 | 关键加载/成功/失败状态是否可理解 |
| 错误反馈 | 错误提示是否能指导下一步动作 |
| 恢复路径 | 中断/失败后是否能重试、回退或继续 |
| 幂等/重复操作 | 重复点击、重复提交后结果是否一致 |

## 5.1 浏览器证据判定

以下内容可视为有效浏览器证据：
- 截图或录屏
- Trace / Video
- 浏览器控制台或 network log
- 明确可追溯到浏览器执行的 `webapp-testing` / Playwright 输出锚点

以下内容不能单独作为 `browser_required` 的通过证据：
- 纯 API 响应
- CLI 输出
- 只证明后端成功、但不证明页面交互/路由/反馈的日志

## 6. 旅程模板

```
### 旅程: [名称]
- **类型**: 核心路径 / 异常中断 / 分支
- **涉及 AC**: AC-001, AC-003, AC-005
- **前置条件**: [环境/数据准备]

| 步骤 | 操作 | 输入 | 期望输出 | 数据传递 |
|------|------|------|---------|---------|
| 1 | 创建用户 | POST /users {...} | 201 + userId | userId → 步骤 2 |
| 2 | 登录 | POST /login {userId} | 200 + token | token → 步骤 3 |
| 3 | 查询资源 | GET /resources (token) | 200 + list | — |
```
