# 专项测试设计手册

## 目标

当架构设计暴露专项风险时，设计最小有效专项测试义务。专项测试不是全量展开清单；只覆盖本 UNIT 的真实风险和下游必须消费的证据。

## 集成测试

定义：以被测系统边界为准，打穿从真实入口到可观察结果的端到端链路。

适用信号：

- 跨模块、跨服务、异步事件、事务一致性或外部依赖。
- 一个 AC 需要多个边界共同完成。
- 设计出现编排、回调、重试、补偿或聚合流程。

设计步骤：

1. 确定被测系统边界、真实入口、可观察结果、参与边界和关键数据流。
2. 设计一条成功链路，从真实入口触发，证明输入、传递、状态变化和输出一致。
3. 设计一条失败链路，证明超时、下游失败、重试或补偿可观测。
4. 明确证据：请求/响应、事件、日志、状态记录或监控指标。

无法定位边界或证据时，记录 `DESIGN_GAP` 或 `TESTABILITY_GAP`。

## 契约测试

适用信号：

- 多消费者接口、外部 API、DTO/VO、错误码、分页、幂等或版本兼容。
- 设计出现向后兼容、字段扩展、枚举扩展或旧客户端兼容要求。

设计步骤：

1. 确认 provider、consumer 和契约 owner。
2. 覆盖请求结构、响应结构、错误结构和兼容约束。
3. 对新增字段设计缺省/忽略/类型变化场景。
4. 对版本演进设计旧消费者仍可用的证据。

缺少契约 owner、兼容口径或错误码时，记录 `DESIGN_GAP`。

## 安全测试

适用信号：

- 认证、授权、敏感数据、开放输入、文件上传、高权限操作。
- `design.json.cross_cutting_concerns` 同时涉及 auth、error、log 或 config 约束。
- 输入进入查询、执行、模板渲染、日志或响应。
- 返回用户隐私、业务敏感字段或内部错误信息。

设计步骤：

1. 识别主体、权限、资源和操作。
2. 设计未登录、越权、权限降级和权限升级场景。
3. 设计输入验证场景：非法格式、越界、注入、脚本或文件边界。
4. 设计敏感数据场景：响应、日志、错误信息和导出内容不泄露。

安全测试只设计测试义务；发现设计缺少权限模型、脱敏规则或审计证据时，记录 gap。

## 性能与容量测试

适用信号：

- 明确性能指标、大数据量、并发、搜索、聚合、报表、批量导入导出。
- 设计出现缓存、异步队列、锁、分页、排序或跨表查询。

设计步骤：

1. 确认指标、数据规模、环境和观测口径。
2. 设计典型负载场景，证明基线性能。
3. 设计边界负载场景，证明容量或退化行为。
4. 设计风险场景：N+1、慢查询、锁冲突、队列堆积或超时。

缺少阈值、数据规模或观测指标时，记录 `TESTABILITY_GAP`。

## 数据一致性与迁移

适用信号：

- 数据迁移、回滚、历史记录、幂等、事务、最终一致性、审计追踪。
- `design.json.data_architecture` 定义了写入点、读模型、迁移、归档、审计或一致性约束。

设计步骤：

1. 识别写入点、读取点、状态转换和回滚点。
2. 设计成功写入与读取一致性场景。
3. 设计失败中断、重复提交和补偿场景。
4. 设计迁移前后等价性或审计可追踪证据。

无法证明迁移前后等价或回滚结果时，记录 `EQ_GAP` 或 `DESIGN_GAP`。
