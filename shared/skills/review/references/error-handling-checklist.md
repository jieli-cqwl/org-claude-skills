# 错误处理检查清单

> 供 /review 错误处理维度和 /verify Phase 2 引用。

## 必检项

1. 空 catch 块：绝对禁止，必须至少记录或重新抛出
2. 仅 log 并继续的 catch 块：错误被吞掉，调用者无感知
3. 返回 null/undefined/默认值但不记录：静默掩盖失败
4. 可选链(?.)无声跳过可能失败的操作：隐藏本应处理的错误路径
5. 回退链未解释原因地尝试多种方法：掩盖根因
6. 重试逻辑耗尽尝试但未通知用户：用户无感知地卡住
7. catch 块过宽：仅捕捉预期错误类型 vs 捕捉所有异常（意外抑制无关错误）
8. 错误消息不可操作：通用"出错了"vs 具体、可定位的错误描述
9. 回退行为非用户请求：静默降级到备选方案，用户不知情

## 报告格式

每条错误处理 finding 必须注明：
- 隐藏的错误类型：哪些错误会被掩盖
- 用户影响：终端用户会遇到什么问题
