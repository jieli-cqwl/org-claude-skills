# 测试有效性评估方法论

## 1. 行为覆盖 vs 行覆盖

| 维度 | 说明 | 评估方法 |
|------|------|---------|
| 行覆盖 | 代码行被执行过 | 覆盖率工具（表面指标） |
| 分支覆盖 | 条件分支被执行过 | 覆盖率工具（较好指标） |
| 行为覆盖 | 业务行为被验证 | 人工审查（核心指标） |
| 变异覆盖 | 代码变异后测试能否检测 | 变异测试工具（最严格） |

### 评估步骤
1. 列出被测代码的所有业务行为（从 AC 推导）
2. 检查每个行为是否有对应的测试断言
3. 未覆盖的行为 = 关键缺口

## 2. 测试行为 vs 测试实现

| 信号 | 判定 |
|------|------|
| 断言函数调用次数 | 测试实现（脆弱） |
| 断言内部状态变量 | 测试实现（脆弱） |
| 断言返回值/副作用 | 测试行为（健壮） |
| 断言抛出的异常类型和消息 | 测试行为（健壮） |
| 断言数据库中的记录 | 测试行为（健壮） |
| 断言方法被调用的参数 | 测试实现（脆弱） |

### 判定标准
- 重构实现（不改行为）后测试是否仍通过 → 是 = 测试行为 / 否 = 测试实现

## 3. 测试韧性评估

| 评估项 | 健壮 | 脆弱 |
|--------|------|------|
| 方法重命名 | 测试仍过 | 测试挂 |
| 内部重构 | 测试仍过 | 测试挂 |
| 新增参数（有默认值） | 测试仍过 | 测试挂 |
| 改变内部实现顺序 | 测试仍过 | 测试挂 |

## 4. 关键缺口识别

必须检查以下是否有测试覆盖：

| 缺口类型 | 检查方法 |
|---------|---------|
| 未测试的错误路径 | 每个 try/catch、每个 if-error 分支是否有对应测试 |
| 未测试的边界条件 | 参数的边界值（0、空、MAX）是否有测试 |
| 未测试的并发行为 | 并发操作是否有竞态测试 |
| 未测试的状态转换 | 实体状态变更是否覆盖所有合法/非法转换 |
| 未测试的集成点 | 模块间调用是否有集成测试 |

## 5. 临界度评分（1-10）

| 分数 | 含义 | 标准 |
|------|------|------|
| 9-10 | 测试优秀 | 所有行为覆盖、韧性强、缺口为零 |
| 7-8 | 测试良好 | 核心行为覆盖、少量边界缺口 |
| 5-6 | 测试及格 | 主路径覆盖、错误路径部分缺失 |
| 3-4 | 测试不足 | 仅 happy path、多个关键缺口 |
| 1-2 | 测试无效 | 占位测试、镜像测试、无有效断言 |
