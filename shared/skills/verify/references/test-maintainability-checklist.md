# 测试可维护性判定口径

## 目标

Phase2C 用本文件判断测试是否能长期保护行为，而不是只能在当前实现下偶然通过。

## 裁决标准

| 检查 | PASS | ISSUE |
| --- | --- | --- |
| 命名 | 名称说明行为、条件和结果。 | `test1`、`edge case`、只写内部函数名。 |
| 结构 | Arrange / Act / Assert 清楚，单一 Act。 | 准备、执行和断言混在一起。 |
| 断言 | 断言用户可观察行为、错误、状态或副作用。 | 断言内部调用顺序、临时变量或无关字段。 |
| 隔离 | 测试顺序无关，数据和全局状态独立。 | 依赖上一个测试、污染全局状态或未清理资源。 |
| setup | 共享 setup 只服务共同前提，清理动作配对。 | 大段复制、全局 beforeEach 做局部场景准备。 |
| 参数化 | 重复输入/输出场景参数化且可读。 | 多个近似测试复制粘贴，差异难以看清。 |

## 验收输出

每个 ISSUE 给出测试文件、行号、影响的 AC 或行为，以及推荐 owner。不要因为测试“当前通过”就忽略维护性风险。
