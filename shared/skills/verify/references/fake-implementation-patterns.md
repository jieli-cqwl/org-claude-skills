# 虚假实现判定口径

## 目标

Phase2A 用本文件判断实现和测试是否真的证明 AC，而不是用占位、硬编码或互抄制造通过信号。

## 裁决顺序

1. 先定位 AC 需要的真实行为：输入、输出、副作用、错误路径和边界。
2. 再读取实现：确认代码是否根据真实输入和状态产生结果。
3. 再读取测试：确认断言是否观察行为，而不是复述实现细节。
4. 最后改动输入或条件做反证：如果输出不随真实条件变化，优先判为可疑。

## FAIL 信号

| 信号 | 判定 |
| --- | --- |
| 空函数、`pass`、`return null`、TODO / FIXME | 占位实现。 |
| `console.log`、`print` 或注释替代功能 | 未实现。 |
| 固定返回值刚好匹配测试期望 | 硬编码预期。 |
| 测试数据、fixture 或 expected 被复制进实现 | 测试定制实现。 |
| 测试复制实现里的计算过程 | 镜像测试。 |
| 条件分支、循环或错误处理存在但不会改变结果 | 伪复杂度。 |
| 异步副作用未 await / 未断言结果 | 行为未被证明。 |

## PASS 要求

- 实现读取真实输入或状态，并产生 AC 要求的可观察结果。
- 测试断言外部行为、错误路径或副作用，不依赖内部步骤。
- 改变关键输入、边界或失败条件时，测试能区分正确和错误实现。
- 结论带 `file:line` 和对应 AC / test_ref。
