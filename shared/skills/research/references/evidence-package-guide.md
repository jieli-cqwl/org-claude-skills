# 证据包整理指南

本文件不是报告模板，也不是 `deep-research` 入口。它只在 Source Targeting Package 已成立之后，把候选或论点整理成可挑战的证据包，作为 Evidence Qualification、Judgment Calibration 和后续 challenger 的输入。

## 使用边界

- 读取时机：候选或论点已经收敛，且 Source Targeting Package 能说明对象、范围、上游来源和关键维度。
- 允许动作：拆核心机制、绑定证据、完成 Evidence Qualification、记录反方挑战、列出失效边界和待验证项。
- 禁止动作：不得抢占 `decision` 或 `understanding` 首屏；不得把轻量预判断升级成完整报告；不得把证据不足的判断写成结论。
- 停止条件：找不到可追溯证据，或发现 Source Targeting Package 目标不明/来源不稳时，输出待验证项和验证路径；不要补想象中的证据。

## 输出合同

每个候选或论点输出一个证据包，供结构化评估、Judgment Calibration 和 challenger 使用。弱证据只能支撑搜索线索或待验证项，不能独立支撑采纳、排除或推荐结论。

```markdown
## {分析目标名称}

### 核心机制
- 解决什么问题：[一句话 + 证据编号]
- 怎么解决：[核心技术原理/设计思路，不写功能列表]
- 适用边界：[有效条件]
- 失效边界：[无效条件]

### 证据分层
- Evidence Qualification：[strong / medium / weak + 理由]
- A 级证据：[官方文档/源码/基准/生产案例 + 时间]
- B 级证据：[社区统计/第三方测评/行业报告 + 时间]
- 弱证据：[只作为线索的博客/评论/目录页 + 不能支撑什么结论]
- 证据冲突：[冲突来源 + 当前处理方式]
- 证据不足：[缺口 + 待验证项]

### 正反论证
- 最强支持证据：[最能支撑当前论点的事实]
- 最强反方挑战：[最强反对意见或替代解释]
- 反例/失败案例：[失败场景 + 失败原因]

### 项目适配
- 匹配点：[为什么适合当前项目]
- 不匹配点：[为什么不适合当前项目]
- 采纳成本：[工作量 + 风险]
- 退出成本：[切换代价]

### 当前判断
- Judgment Calibration：[当前判断 + 置信度 + 决定性理由]
- 判定：[成立 / 部分成立 / 不成立 / 待验证]
- 稳健性：[高 / 中 / 低 + 理由]
- 翻案条件：[什么新证据会改变判断]
- 下一步：[一个可执行验证或行动]
```

## 证据标准

| 类型 | 可用条件 | 不可用条件 |
| --- | --- | --- |
| 官方文档 | 有稳定链接、版本或发布时间 | 只引用营销口号 |
| 基准测试 | 有环境、数据规模和测试方法 | 只有排名或截图 |
| 源码分析 | 指到文件、函数、行号或提交 | 只说“看起来是” |
| 社区数据 | 有时间窗口和口径 | 只说“大家都在用” |
| 生产案例 | 有场景、规模、结果和限制 | 只有品牌背书 |
| RFC/ADR | 有决策背景和取舍 | 只引用结论标题 |

无效证据处理：

- 个人博客主观评价：只能作为搜索线索，不能作为关键论据。
- 过时信息：标注时间，补当前状态。
- 无出处数据：进入待验证项。
- 目录站或镜像：回溯上游后再使用。

## 判定规则

- `成立`：支持证据强于反方挑战，且适用边界清楚。
- `部分成立`：方向成立，但依赖额外条件或只适用于局部场景。
- `不成立`：反方挑战更强，或关键证据缺失/被反例击穿。
- `待验证`：当前证据不足以下结论，但验证路径明确。
