# 调研报告呈现框架

`/research` 不是单一模板生成器，而是“同一套严谨研究过程 + 不同首屏呈现路径”。

先判断 `research_mode`，再判断 `presentation_profile`。前者决定怎么研究，后者决定结果怎么给人看。

## 四层阅读路径

所有 profile 都遵循同一信息分层，只是首屏落点不同：

1. 答案层
   - 这次到底在回答什么问题
   - 当前判断是什么
2. 判断层
   - 决定性理由
   - 最大风险 / 主要边界
   - 建议动作
3. 证据层
   - 深度分析
   - 正反论证
   - 项目适配
4. 审计层
   - 独立 challenge 记录
   - 覆盖证明
   - 项目上下文
   - 证据索引

## presentation_profile

### `decision`

- 适用问题：该不该选、值不值得做、现在怎么推进
- 首屏重点：问题、当前判断、2-4 个决定性理由、最大风险、建议动作
- 读者心态：想尽快做决定，不想先读完整证据链
- 常见误用：把 challenge/覆盖证明堆到首屏，导致答案不突出

### `understanding`

- 适用问题：这是什么、为什么重要、和相近对象差在哪
- 首屏重点：对象定义、价值、核心机制、关键差异、适用边界
- 读者心态：先建立心智模型，再考虑采纳与否
- 常见误用：把“推荐/不推荐”写得过早，打断理解过程

### `audit`

- 适用问题：为什么能定这个案、证据是否充分、还有哪些盲区
- 首屏重点：当前判断、挑战表、覆盖证明、剩余盲区
- 读者心态：默认会追问“证据在哪”“为什么不是别的解释”
- 常见误用：把 `audit` 当成更高级版本，导致所有报告都变成审计文档

## 默认路由

| research_mode | 默认 profile | 何时切换 |
|---------------|-------------|---------|
| `selection` | `decision` | 用户更想先搞懂概念时才切到 `understanding` |
| `analysis` | `decision` 或 `understanding` | 若目标是“是否采纳”选 `decision`；若目标是“先看懂观点”选 `understanding` |
| `discovery` | `understanding` 或 `audit` | 若目标是“先定位对象”选 `understanding`；若目标是“证明命中/排除”选 `audit` |

## 结构约束

- 所有 profile：最终报告都必须包含 `独立挑战记录`、`检索路径与覆盖证明`、`项目上下文`
- `decision`：`建议动作` 必须早于共享审计层
- `understanding`：`这是什么` 与 `适用边界` 必须都出现在首屏区，且共享审计层不得插到它们前面
- `audit`：`当前判断` 与 `关键论点挑战表` 必须先于共享审计层出现
- 所有 profile：权威来源都必须被拆成可验证论点，不能只写“某某很权威所以可信”
