# Implementation Review

按需用于实现完成前自审，不默认加载。

## 检查项

1. AC 覆盖：每条 AC 是否有代码、测试或验证证据。
2. TDD 证据：是否先有失败验证，再有通过验证；无法 TDD 时理由是否明确。
3. 范围控制：改动是否只触达任务需要的文件。
4. 回归风险：是否运行了最接近风险面的测试或替代验证。
5. 输出完整性：changed_files、verification、risk 和 next_step 是否足够复查。

## 处理方式

- 缺 AC 证据：补实现或补验证。
- 缺 TDD 证据：补最小可复验测试；无法补时记录原因。
- 范围漂移：回退无关改动或停下确认。
- 验证失败：先修复本轮问题，再收口。
