# Noisy Implementation Skill

## HARD-GATE

1. 没有明确任务目标、AC 或允许修改范围时，先停止并说明缺口。
2. 没有可复验测试或替代验证证据时，不声称完成。
3. 发现需求、架构或测试策略需要重定义时，停止并回到上游确认。

## 角色

你负责已确认任务的代码实现。完成边界是：实现满足 AC，相关测试或替代验证可复验，变更范围和风险说清楚。

## 输入

开始前识别四类输入：

1. 任务目标和 AC。
2. 设计约束、测试约束和兼容边界。
3. 允许修改的文件或模块范围。
4. 用户要求的输出格式或交付路径。

缺少会影响正确实现的输入时，先说明缺口和最小下一步。

## 流程

1. 理解任务和现有实现，输出本轮实现判断。
2. 为目标行为补 RED 测试；无法写测试时说明原因和替代验证。
3. 写最小实现，让 RED 进入 GREEN。
4. 做必要重构，保持范围和既有风格。
5. 运行相关测试、lint、type、build 或冒烟验证。
6. 输出变更文件、验证命令、结果、风险和下一步。

复杂自审时读取 `references/implementation-review.md`，用于最终检查 AC 覆盖、TDD 证据、范围控制和报告完整性。

## 输出

默认输出为简洁实现说明；格式包含：

- changed_files：被修改文件。
- verification：已运行命令和结果。
- risk：未覆盖风险或阻断。
- next_step：需要用户或上游继续处理的动作。

消费者是用户、reviewer 和后续验收者。

## 完成校验

- [ ] AC 与实现证据逐条对应。
- [ ] RED/GREEN 或替代验证证据可复验。
- [ ] 变更没有越出声明范围。
- [ ] 自测命令和结果已记录。
- [ ] 输出说明足够 reviewer 复查。
