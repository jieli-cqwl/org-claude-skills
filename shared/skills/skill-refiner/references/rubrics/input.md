# Input 诊断口径

**目标**：输入对象来自真实办事流程，足以启动当前职责；可枚举的存在性和引用解析交给脚本或 gate。

## 裁决标准

1. 输入服务流程：每个输入都能解释它支撑哪一步真实工作。
2. 必需和可选分清：缺必需输入时停止，缺可选输入时按流程补齐或降为风险。
3. 来源可信：用户、上游产物、代码、测试、runtime payload 或文件路径能定位。
4. 定位可执行：路径、ID 或产物引用能定位到来源；无法唯一定位时阻断。
5. 机器检查外移：存在性、active 状态、schema、引用解析由脚本、hook、gate 或测试验证，不靠文字描述提醒。
6. 不堆字段：不把报告字段、hook payload、历史 registry 当成默认阅读清单。

## 问题信号

- `SKILL.md` 罗列大量 JSON 字段但没有消费动作。
- 文字要求"确认存在"，却没有脚本入口或执行时机。
- 写"默认从 X 接手/读取"，但没有给出 X 的来源、提供方、缺失定位或阻断方式。
- 默认读取旧设计、长方法论或历史报告。
- 缺输入时继续执行并猜测目标。
