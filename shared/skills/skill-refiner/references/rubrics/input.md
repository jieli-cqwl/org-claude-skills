# Input 环节标准

## Why

输入定义错误会把运行时字段、旧文档或内部状态误当成办事起点。Agent 会围绕噪音行动，而不是围绕任务行动。

## 目标

输入对象来自真实办事流程，足以启动当前职责；可枚举的存在性和引用解析交给脚本或 gate。

## 裁决标准

1. 输入服务流程：每个输入都能解释它支撑哪一步真实工作。
2. 必需和可选分清：缺必需输入时停止，缺可选输入时按流程补齐或降为风险。
3. 来源可信：用户、上游产物、代码、测试、runtime payload 或文件路径能定位。
4. 定位可执行：路径、ID、环境变量或 artifact ref 必须说明来自用户、上游派发、runtime payload、仓库路径或发现步骤；无法唯一定位时阻断。
5. 机器检查外移：存在性、active 状态、schema、引用解析由脚本、hook、gate 或测试验证。
6. 不堆字段：不把报告字段、hook payload、历史 registry 当成默认阅读清单。

## 证据

- 输入识别段落。
- preflight 脚本、schema、hook 或测试。
- 上游 Skill 输出和下游消费路径。
- 失败示例或缺失输入场景。

## 问题信号

- `SKILL.md` 罗列大量 JSON 字段但没有消费动作。
- 文字要求“确认存在”，却没有脚本入口或执行时机。
- 写“默认从 X 接手/读取”，但没有说明 X 在哪里、谁提供、缺失时如何定位或阻断。
- 默认读取旧设计、长方法论或历史报告。
- 缺输入时继续执行并猜测目标。

## 验收

输入清单能让 Agent 找到真实对象或明确阻断；确定性输入校验有执行入口、执行时机和失败状态。
