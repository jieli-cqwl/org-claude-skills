# Trigger 诊断口径

**目标**：description 能让 runtime 和人判断何时使用、何时不使用、相邻 Skill 如何分流。

## 裁决标准

1. 用户意图明确：覆盖真实用户会说出的任务表达。
2. 触发对象明确：区分改造、创建、审计、验证、迁移等场景。
3. 入口动作明确：有路径读路径；无路径按能力名、相邻 Skill、测试和运行入口找现有承载。
4. 最终操作后置：最终判断必须等策略制定阶段汇总全部诊断后冻结。
5. 相邻分流明确：不抢只读审计、批量自动优化或普通开发 Skill。
6. 入口一致：`user-invocable`、manual-only、adapter 和安装清单与触发描述一致。
7. 反触发清楚：不该触发的高风险相邻场景有正向路由。

## 问题信号

- description 只写"优化 Skill""检查质量"等宽泛词。
- 创建、审计、改造、验证共用同一触发入口。
- 用户未给路径时，不尝试按能力线索寻找现有承载。
- 在策略制定前输出新建、重写、替换或拆分的最终结论。
- active runtime 入口和 manual-only 描述冲突。
- 测试或 eval 仍使用旧 Skill 名称或旧触发边界。
