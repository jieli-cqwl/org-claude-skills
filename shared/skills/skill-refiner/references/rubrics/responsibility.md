# Responsibility 环节标准

## Why

职责不清会让 Skill 变成大而全说明书。Agent 会同时承担上游定义、当前执行和下游验收，最后每一步都不可靠。

## 目标

Skill 对应一个清楚的专业职责域，并能界定负责什么、交给谁、何时停止。

## 裁决标准

1. 职责域真实：来自软件工程、项目管理、产品、测试、研究、设计等真实工作。
2. 任务边界清楚：主任务、非目标、上游输入和下游消费者可说清。
3. 权责不过载：不把需求定义、架构裁决、测试策略、执行改造和最终审计混在一个 Skill。
4. 停止点清楚：职责外问题能给出下一步路由，而不是在本 Skill 内补完。
5. 文件结构服务职责：目录拆分来自职责动作，不来自形式化模板。

## 证据

- `SKILL.md` 角色、目标、输入、流程和停手条件。
- 相邻 Skill 的职责边界。
- 用户反馈中的真实任务目标。
- 下游消费者或交付链路。

## 问题信号

- 只能用“整理文件”“提升质量”“遵守标准”解释 Skill。
- 大量“不负责”覆盖了实际操作步骤。
- 同一个 Skill 同时创建、审计、执行、验收和迁移。
- 旧资料为了兼容而扩张当前职责。

## 验收

读者能用一句话说出该 Skill 的专业职责，并能据此判断一个请求应该进入、转出还是停止。
