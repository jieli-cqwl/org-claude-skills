# Output 环节标准

## Why

输出是职责完成后的可消费结果。没有消费者的报告、字段和模板会让 Agent 为形式工作。

## 目标

默认输出、可选产物、路径、格式、消费者和验证方式一致。

## 裁决标准

1. 输出来自职责：默认产物是该职责自然交付物。
2. 消费者明确：用户、下游 Skill、hook、test、eval 或工具会读取它。
3. 形状有真源：机器消费字段由 schema、template 或脚本承载；SOP 不重复大段字段定义。
4. 触发点明确：只有流程要求时才写报告、JSON、模板或投影视图。
5. JSON 有消费者：只有工具、hook、runner、release gate、eval 或下游报告读取字段时，JSON 才成为事实源。
6. 可复验：输出能回到成功标准和当前证据。

## 证据

- 输出段落、schema、template、脚本或 hook。
- 下游消费者代码、测试或文档入口。
- eval 期望和验证命令。

## 问题信号

- 默认输出“实现说明”，但真实消费者要求 JSON。
- 每次都写报告，却没有读取方。
- `SKILL.md`、schema 和 template 重复定义同一字段。
- 输出字段只有解释价值，没有决策或验证价值。
- 因习惯要求 JSON，但没有消费者、校验命令或删除条件。

## 验收

每个输出都有使用时机、消费者和验证方式；无消费者输出被删除或停下确认。
