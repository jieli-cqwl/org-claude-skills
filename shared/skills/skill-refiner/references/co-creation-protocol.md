# 共创工作协议

## 核心原则

你的目标是基于已闭合事实给出专业默认判断，并只暴露一个会改变下一步判断的关键假设。

回复前读取当前能力步骤声明的 reference、`refinement-ledger.json` 中的最新 checkpoint，以及当前步骤已闭合结论。你只使用这些材料生成本轮草案；缺少会改变结论的事实时，停在当前步骤验证假设。

## 最小决策包

每个全共创或草案修正暂停点，对用户只输出：

- 已闭合事实：当前已确认、可作为本步输入的事实。
- 推荐理解：你基于已闭合事实给出的默认专业理解或推荐结论草案。
- 关键假设：只写一个不成立就会改变推荐理解、候选策略、验证口径或最终操作的事实。
- 用户动作：请用户确认该假设或给出替换事实；你不要求用户选择方法论。

最小决策包可以用自然段、短列表或卡片呈现；表现形式不得反向定义流程。schema key、ledger 字段和 rubric 字段不得作为用户侧标题，只能写入 `refinement-ledger.json`、`skill-refiner-result.json`、schema、validator、eval 或测试。

## 交互模式

| 模式 | 行为 |
| --- | --- |
| 静默 | 读取、盘点和归纳候选线索；不替用户确认目标、边界、策略或最终操作。 |
| 全共创 | 你从已闭合事实生成推荐理解，验证一个会改变结论的关键假设；回应前不形成最终结论。 |
| 草案修正 | 你基于已有草案重写不确定部分；同一轮只处理当前步骤一个会改变结论的事实缺口。 |
| 静默后汇报 | 先验证，再按成功标准报告通过、阻塞、残留风险和下一步。 |

## 用户回应处理

- 回应支撑关键假设时，把推荐理解写入当前步骤 checkpoint，再进入下一步。
- 回应替换当前步骤事实时，重写当前步骤最小决策包并再次验证关键假设。
- 回应替换已闭合上游事实时，回到对应能力步骤重新闭合，记录 supersedes，下游结论待复核。
- 回应包含多个事实时，只处理会影响当前步骤结论的事实；其他事实登记为后续步骤候选线索。
- 回应触发目标 Skill 文件、测试、runtime、引用或文档改动时，策略确认前只登记候选，不执行改动。

## 能力步骤映射

| 能力步骤 | 用户侧最小决策包关注点 | 内部写入 |
| --- | --- | --- |
| 场景理解 | 真实场景、业务约束、预期结果、痛点、保留能力、切入点。 | `current_state.baseline` 与 `co_created_baseline` 字段。 |
| 职责定义 | 专业职责域、非目标、真实办事流程和成功边界。 | 职责/流程 checkpoint。 |
| 结构诊断 | 本维度目标形态、保留能力、问题证据、候选策略、验证线索。 | 维度诊断结论和证据。 |
| 策略制定 | 最终操作、执行范围、排除项、风险和未裁决冲突。 | 策略冻结记录和最终操作。 |
| 验收交付 | 成功标准、proving command、通过/阻塞、残留风险和下一轮候选。 | `skill-refiner-result.json` 与验证证据。 |

## 回退触发

- 场景理解出现最终操作判断或环节策略时，回到场景事实表达。
- 职责定义只能用文件结构、runtime 术语或工具动作解释时，重写为专业职责和真实流程。
- 诊断维度无法说明消费者、证据或验证方式时，只登记候选缺口，不进入策略制定。
- 用户事实改变已闭合场景、职责边界或不可丢能力时，记录 supersedes 候选并停下确认。
- 确认证据是"无关键假设""pending""等待确认"或同义占位时，视为未闭合，停在该步骤重发最小决策包。
- 策略未收到用户明确确认时，不进入执行。
