# Skill 打磨工作纪律

多轮打磨时，LLM 最容易从解决真问题滑向制造新问题。本文件只记录防偏纪律。

## 1. 警惕盲 loop

警戒信号：同义改写但无行为变化；删除旧段后用相似语义替换；问题无法映射到用户卡点或 failure mode；新概念 / 新术语 / 新分类无消费者。

纪律：前 3 轮按真问题驱动；第 4 轮起自评是否为找事做而找事做；第 5 轮后逐轮汇报真实增量，无真实增量自动停手；常规上限 5 轮，超过需用户裁决。

## 2. 不削弱安全红线

反向引导不是全部要改正向。改写前按 `noise-taxonomy.md` 的安全红线、反绕过动作、边界澄清三类筛选；命中三类时保留原强度。改完自问：约束强度是否被削弱；若是，回滚。

## 3. dry-run 不能半真实

真实项目缺失时不造半真实场景。改为 beta 交付 + 试点反馈回路：选 1-2 个真实业务项目试点，并声明未验证项、反馈收集点、loop 触发机制和撤销阈值。

## 4. 中期自评

每 2-3 轮用第三方视角重读产出：是否盲 loop、是否过度正向化、本轮闭合了哪个 failure mode。自评要直说，不粉饰。

## 5. 交付前承认验证层级

验证分层：

| 层级 | 说明 |
| --- | --- |
| structural | frontmatter / JSON / YAML / schema 合法 |
| empirical 脚本层 | 脚本多场景实测通过 |
| integration | 下游契约测试通过 |
| 真实使用 | 完整主流程真实端到端跑过 |

真实使用未验证时按 beta 交付，不写成"已完成"。

## 6. 撤销阈值

达到任一阈值，停止增量打磨，汇报根基维度需要重设：同一 HARD-GATE 真实使用中被绕过 >=3 次；同一流程在真实项目被跳过 >1 次；schema 需改动超过 2 个字段；连续 2 轮问题都落在同一段且修不掉。
