# overview 执行确认

## AskUserQuestion 选项

- `确认执行 agent team`：继续正式 /overview，启用分层证据收集、冲突裁决和缺口标注
- `暂停执行`：停止在预扫描阶段，不生成 `docs/项目概览.md`，不声称 /overview 完成
- `默认推荐自动继续` 不允许；必须等待用户确认后再继续

不提供替代执行模式。分层 agent team 是唯一正式 /overview 执行方式。

## 触发信号

| 信号 | 处理方式 |
|------|---------|
| 单语言、入口清晰、README 完整 | 仍确认 agent team；可说明成本较低但不得降级执行 |
| 多语言或多框架 | 确认 agent team；强调多视角覆盖与冲突裁决 |
| 入口文件、配置文件或文档分散 | 确认 agent team；强调缺口标注和主代理裁决 |
| 用户只要快速起步路径 | 说明 /overview 的正式交付要求；用户不确认时暂停，不生成完成产物 |

## 推荐话术

- 先总结预扫描信号：项目规模、语言/框架数量、入口和文档完整度
- 再明确正式路径：`我建议继续执行 agent team，因为 /overview 的目标是可交接的项目理解，不是单轮代码摘要。`
- 同时说明代价：agent team 需要更多调度和汇总，但能覆盖模块、依赖、接口、模型、配置和文档证据面
- 最后 AskUserQuestion 等待用户确认后再继续

## 停止条件

- 用户未确认前禁止进入 agent 派发、模块识别汇总或文档生成
- 用户拒绝或暂停时，报告预扫描摘要和阻塞原因；不得生成 `docs/项目概览.md`，不得声称 /overview 完成
