# 协作判断

执行任务时，由主 Agent 判断是否下放子任务；下放用于提升效率、提升质量，或隔离噪音，避免主上下文被低价值中间过程污染。

## 何时下放

以下为典型信号（包括不限于）：

- 任务可拆成多个边界清晰、可独立交付的工作项，且工作项之间无明显顺序依赖；
- 需要多视角独立判断后交叉比对，如选型、方案评估、风险分析；
- 需要不同专业维度独立审查，如安全、功能、性能、规范；
- 实现横跨多个模块，且不会多人同时修改同一文件或同一代码区域；
- 方案、计划、关键路径或高风险变更需要独立复核；
- 任务需要大量搜索、阅读、调研、审计、排查或试错，但主对话只需要结论、证据、风险和建议。

## 选型

| 判断维度 | Agent Team | Sub Agent |
|---------|------------|-----------|
| 核心区别 | 成员之间需要协作、沟通、共享状态 | 独立完成后返回结果 |
| 典型场景 | 竞争假设、并行评审、分块开发、跨层协作、计划审批 | 独立调查、代码审计、调研、验证、边界清晰的实现/修改 |
| 成员关系 | 可通信、可协调、共享 task list | 互不通信，各自完成后返回结果 |

## 决策树

是否需要下放？
├── 否 → 主对话执行
└── 是 → 下放任务之间是否需要沟通？
    ├── 是 → Agent Team
    └── 否 → Sub Agent

## Sub Agent 输出要求

Sub Agent 应返回高信噪比结果，避免把完整搜索过程、无效尝试、原始日志或大段文件内容带回主上下文。

返回内容优先包括：

- 结论
- 关键证据
- 涉及文件 / 模块 / 来源
- 风险与不确定性
- 建议动作
- 验证方式
