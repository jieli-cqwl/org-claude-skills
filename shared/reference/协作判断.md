# 协作判断

执行任务时，由你负责主动评估是否需要协作以提升效率和质量。

## 触发信号

出现以下信号，或其他表明协作能提升效率、质量或独立审查价值的情况时，应考虑启用协作：

- 2+ 独立子任务且无顺序依赖
- 需要多视角独立判断后交叉比对（选型、方案评估）
- 需要不同专业维度独立审查（安全 + 功能 + 规范）
- 跨模块实现且写入边界清晰
- 方案或计划需要独立审查

## 选型

| 判断维度 | 协作团队 | Sub Agent |
|---------|---------|-----------|
| 能力 | agent teams | sub agents |
| 核心区别 | 成员间需要协作沟通 | 独立任务并行，互不影响 |
| 典型场景 | 竞争假设、分层评审、模块化开发、规划-审批 | 多个独立 bug 调查、独立子任务并行执行 |
| 成员关系 | 互相发现、可通信、共享 task list | 互不知道、各自完成后返回结果 |

选型的关键判断：成员之间是否需要知道彼此的存在和产出。

运行边界：

- 要求 agent teams 时，必须由当前 runtime 提供真实 agent-team 创建、消息和清理能力；否则阻断并报告能力缺口。
- Sub Agent 可用于独立子任务降上下文压力，但不等价于 agent teams，不能替代需要成员互相通信、共享 task list 或形成三方独立评审证据的步骤。
- Skill 正文使用 `agent teams` 描述专业动作；具体工具名只出现在 runtime 授权、adapter 或验证规则中。
