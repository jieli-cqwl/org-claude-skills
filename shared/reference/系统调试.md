# 系统调试（四阶段根因分析）

HARD-GATE: 完成 Phase 1 之前禁止改代码。
Phase 1-3 属于铁律允许的受控诊断范围，只用于定位根因、收集证据和验证假设；不得借调试名义继续实现、静默切换方案或宣称任务完成。
Phase 4 仅在根因已确认、修复不改变原目标与验收标准时进入；若修复需要扩大范围、切换方案或调整标准，必须先向用户报告并等待裁决。
## 四阶段

| 阶段 | 目标 | 产出 |
|------|------|------|
| 1. Observe | 复现问题，记录错误信息/堆栈/环境/时间线 | 问题事实卡片 |
| 2. Hypothesize | 默认列多个可证伪假设；直接证据已唯一定位时可少于 3 个，但必须记录证据链 | 假设清单 + 证伪条件 |
| 3. Test | 从证据支持度最高的假设开始，一次只变一个变量 | 实验记录 |
| 4. Fix | 根因确认后：写回归测试(先失败) -> 最小修复 -> 原复现 + 回归 + 影响范围验证；核心/共享/高风险变更再跑全量 | 修复 diff + 测试结果 |

## 常见陷阱

- 跳过观察直接改代码 -> HARD-GATE 强制
- 为凑数编假设 -> 简单确定性问题记录唯一证据；复杂问题按输入/环境/依赖/状态/代码路径覆盖
- 创可贴修复（消除症状不解决根因）-> Phase 3 必须确认根因
- 修复引入新 bug -> Phase 4 按影响范围验证；无法全量时记录替代证据和残余风险
