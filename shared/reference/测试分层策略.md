# 测试分层策略

> 供 TDD 规范"测试分层"章节引用。定义何时写单元测试 vs 集成测试。

## 1. 测试金字塔

```
        /  E2E  \        ← 少量，验证关键用户旅程
       / 集成测试 \       ← 适量，验证模块间交互
      /  单元测试  \      ← 大量，验证核心逻辑
```

## 2. 单元测试 vs 集成测试边界

| 判断条件 | 单元测试 | 集成测试 |
|---------|---------|---------|
| 纯函数（无副作用） | YES | — |
| 数据转换/格式化 | YES | — |
| 业务规则计算 | YES | — |
| 数据库 CRUD | — | YES |
| HTTP 请求/响应 | — | YES |
| 文件读写 | — | YES |
| 多模块协作流程 | — | YES |
| 消息队列生产/消费 | — | YES |
| 缓存读写 | — | YES |

## 3. 隔离策略

### 数据库隔离

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| 事务回滚 | 单测试内的数据库操作 | 测试开始开事务，结束回滚 |
| 测试数据库 | CI/CD 环境 | 独立数据库实例，测试前 migrate |
| 数据清理 | 测试间互不干扰 | beforeEach/afterEach 中清理相关表 |
| Schema 隔离 | 并行测试 | 每个测试 worker 独立 schema |

### 外部服务隔离

| 策略 | 适用场景 | 实现方式 |
|------|---------|---------|
| 测试实例 | 有测试环境的服务 | 连接测试环境的真实服务 |
| 本地容器 | 数据库/缓存/消息队列 | docker-compose 启动依赖服务 |
| 录制回放 | 第三方 API（无测试环境） | 录制真实响应用于回放（最后手段） |

> 与 Mock 禁令的关系：录制回放仅限于「无测试环境的第三方外部 API」场景，且必须满足：
> 1. 首次录制使用真实 API 响应
> 2. 定期（每季度）重新录制验证响应格式未变
> 3. 内部服务、数据库、缓存等禁止使用录制回放

## 4. 速度与信心的 Trade-off

| 场景 | 推荐策略 |
|------|---------|
| 开发中频繁运行 | 仅跑单元测试（秒级反馈） |
| 提交前验证 | 单元 + 集成（分钟级） |
| CI/CD 流水线 | 全部（单元 + 集成 + E2E） |
| 关键路径变更 | 强制跑全量测试 |

## 5. 常见错误

| 错误 | 正确做法 |
|------|---------|
| 用 Mock 代替集成测试 | 用真实依赖写集成测试 |
| 所有测试都是集成测试 | 纯逻辑用单元测试（更快更稳定） |
| 测试只覆盖 happy path | 集成测试也要覆盖错误路径 |
| 测试依赖外部网络 | 本地容器化依赖服务 |
| 集成测试不清理数据 | 每个测试自己 setup + teardown |
