# 全栈开发

> 本文件提供全栈任务的协作建议与完成边界，不覆盖 `rules/执行纪律.md` 中的范围约束与流程纪律。

## 完成边界

- 声称全栈任务完成前，前后端都应完成并联调通过
- 前端调用后端接口前，应先确认接口已存在或契约已明确
- 联调结论必须以真实运行结果为准，不能用占位数据替代

## 推荐推进顺序

优先按功能闭环推进：接口契约 -> 后端能力 -> 前端接入 -> 联调验证。

## 常见风险

- 前端先接未实现接口，导致后续联调失真
- 只完成单侧实现却对外宣称功能已完成
- 按技术层大段切分计划，导致单个用户路径长期无法闭环

## 计划组织建议

- 优先按功能模块组织任务，而不是简单按技术层批量切分
- 涉及接口变更时，在设计或计划工件中明确契约引用
- 若发现前后端不同步且超出当前请求范围，先报告影响，再由用户决定是否扩展处理

## 联调验证

- 前端能正常调用后端 API，数据结构匹配
- 错误和边界情况处理正确，用户流程走通

## 说明

- workflow-specific 的强制步骤以对应 skill / plan / design 文档为准
- 本文件只保留跨项目可复用的全栈协作边界
