# 全栈开发

全栈任务的完成边界是用户路径真实打通，不是前端和后端各自“看起来完成”。

## 推进原则

- 先对齐接口契约，再实现后端能力，再接入前端，最后联调验证。
- 优先按功能闭环组织任务，让每个阶段都能靠真实路径证明进展。
- 前端调用后端接口前，确认接口已存在、契约已冻结，或明确当前仍是待实现依赖。
- 后端接口变更必须同步前端调用、错误处理和契约引用。

## 联调边界

声称全栈任务完成前，前后端都必须完成并联调通过。

联调结论必须来自真实运行结果：

- 前端能正常调用后端 API。
- 请求、响应、错误结构和状态码匹配契约。
- 关键用户流程走通，错误和边界情况有可理解反馈。
- 不使用占位数据、静态 mock 或单侧测试替代完成结论。

## 常见偏差

- 前端先接未实现接口，导致后续联调失真。
- 只完成单侧实现，却对外宣称功能已完成。
- 按技术层大段切分计划，让单个用户路径长期无法闭环。
- 发现前后端不同步时继续推进单侧改动，而不是先报告影响和同步范围。
