# 全栈开发

全栈任务先聚焦接口契约，再推进前后端实现。接口是前端和后端的衔接标准；完成边界是用户路径真实打通，不是前端和后端各自“看起来完成”。

## 接口先行

先把接口契约变成双方都能执行的衔接标准：

- 请求方法、路径、参数、鉴权、幂等和分页规则清楚。
- 响应字段、状态码、错误结构、空态和边界场景清楚。
- 前端据此实现调用、状态展示和错误反馈；后端据此实现接口能力和校验。
- 契约未冻结时，明确待决策项和阻塞范围，不把临时假设当成完成依据。

## 推进顺序

- 后端先提供契约匹配的真实接口，或明确当前是待实现依赖。
- 前端接入接口时同步处理 loading、empty、error、permission 和 retry 等用户可见状态。
- 任一侧修改接口契约时，同步另一侧调用、错误处理、测试和契约引用。
- 优先按功能闭环组织任务，让每个阶段都能靠真实路径证明进展。

## 联调边界

声称全栈任务完成前，前后端都必须完成并联调通过。

联调结论必须来自真实运行结果：

- 前端能正常调用后端 API。
- 请求、响应、错误结构、状态码和用户可见状态匹配契约。
- 关键用户流程走通，错误和边界情况有可理解反馈。
- 不使用占位数据、静态 mock 或单侧测试替代完成结论。

## 常见偏差

- 没有先对齐接口契约，前后端各自按假设实现。
- 前端先接未实现接口，导致后续联调失真。
- 只完成单侧实现，却对外宣称功能已完成。
- 按技术层大段切分计划，让单个用户路径长期无法闭环。
- 发现前后端不同步时继续推进单侧改动，而不是先报告影响和同步范围。
