# 测试规范

验证依据不清时，先把成功标准补成可观察行为、边界条件、失败路径和真实依赖。重述会改变验收口径时，记录待裁决问题，裁决关闭前不给出完成结论。

## 验证维度

每个变更审视三个维度，判断哪些被触发，被触发的必须有验证证据。

先从本次成功标准推导具体验证点，再用以下验证项补充审视盲区；这些验证项作为默认起点，实际执行时应结合变更目标、风险和上下文主动补充。

### 功能正确性 → 功能测试

任何行为变更都验证需求目标和验收标准是否全部达成。

- 产出与验收标准逐条对应——用验收标准逐项比对实际输出。
- 边界和特殊输入下行为符合需求意图——用边界值和特殊输入执行并验证结果。
- 实现的隐含假设合理——识别验收标准未明确的假设并验证其合理性。

### 集成正确性 → 集成测试

变更涉及模块边界、API、数据格式或外部依赖时，集成测试以被测系统边界为准，打穿从真实入口到可观察结果的端到端链路，验证模块协作、契约一致、数据流转、真实依赖交互和异常路径处理是否正确。

- 各边界对数据格式和语义的理解一致——用链路上游真实输出作为下游输入验证。
- 成功和失败响应都被正确处理——构造失败和超时场景验证处理逻辑。
- 数据变换链路各环节假设成立——追踪数据从真实入口到可观察结果的每次变换并验证。
- Mock/Stub/Fake 仅用于隔离不可控的外部依赖，不替代真实依赖验收。
- 无测试环境的第三方 API 可用录制回放验证，要求首次真实录制、定期重录、仅限第三方。

### 用户体验 → E2E / 浏览器测试

变更涉及用户可见界面或交互流程时，验证用户能从真实入口完成目标。

- 用户能走完正常流程——从真实入口执行完整操作路径。
- 非常规操作不会导致不可恢复状态——模拟乱序操作、重复提交、中途刷新。
- 错误状态下用户有清晰指引——触发错误并验证提示内容和恢复路径。

## 风险面

每个变更都必须审视以下风险面。结合变更目标、领域风险、影响范围和上下文补充其他风险面；触发的按标注层级执行，未触发的说明原因。

### 异常路径 · 必须测试 · 贯穿每个维度

被触发的验证维度必须覆盖异常情况，确保用户在非理想条件下仍受保护。

- 假设为"不会出现"的输入被安全处理——构造这些输入并验证系统响应。
- 失败后用户看到干净错误而非脏数据——触发失败场景验证状态和提示。
- 错误信息提供恢复指引且不暴露内部细节——检查错误输出内容。

### 安全 · 必须检查

涉及用户输入处理、权限变更或数据暴露时，确认系统保护用户的数据和访问边界。

- 所有用户输入进入查询、命令或渲染前，必须按场景做验证、参数化、转义或输出编码——用注入输入验证处理有效。
- 权限检查在每个后端入口执行——绕过前端直接调用后端接口验证。
- 用户间数据隔离有效——用一个用户的凭据尝试访问另一个用户的数据。

### 数据完整性 · 必须检查

涉及持久化操作、状态变更或缓存时，确认用户数据被正确保存且不会意外丢失。

- 写入数据能正确读回——写入后立即读取并比对。
- 并发操作不会导致数据损坏——模拟并发写入验证最终状态一致。
- 部分失败不会产生脏数据——中断写入过程验证数据状态。

### 性能 · 必须标记

涉及查询、批处理、高频路径或大数据量时，识别性能风险并说明影响和验证建议。

- 查询在数据量增长后仍可接受——检查分页、索引和查询计划。
- 无 N+1 查询模式——审查数据加载逻辑。
- 资源使用有上限——确认内存/连接/文件不会无限增长。

### 环境兼容 · 必须标记

涉及配置、依赖版本、部署环境或数据迁移时，列出环境假设和兼容风险。

- 环境配置缺失时系统给出明确错误——移除环境变量验证报错。
- 旧版本数据能正确迁移——用旧格式数据执行迁移验证结果。

## 测试可信度

测试是验证工具，工具不可靠则结论不可信。

- 每个测试可单独运行、任意顺序运行，结果不变。测试数据在测试内创建，执行后清理。
- flaky 测试不能作为通过证据；属于本次验证面的，记录为阻塞并修复根因；目标外 flaky 只报告风险。
- 断言验证真实业务结果，预期值来自需求或独立计算，不来自被测代码。
- 断言必须能区分目标内正确行为与关键失败模式；关键失败模式下仍会通过的检查，不作为该目标的验证证据。
- 样例、快照、录制回放和抽样只证明其覆盖输入；用于代表整体行为时，必须说明代表性、边界和未覆盖风险。
- AAA（准备→执行→断言），每个测试一个主要执行动作。测试名描述行为和条件。同一行为多组输入用参数化测试。

## 交付判定

- 被触发的验证维度都有对应验证证据；未触发的能从变更范围说明原因。
- 五个风险面都审视过；被触发的按标注层级执行，标记项写清内容、影响和验证建议。
- 每条结论有对应的测试输出或验证证据；不确定的标为待验证；flaky、skip、无意义断言不作为通过证据。
- 覆盖率作为发现未验证代码的辅助工具，不作为完成指标。
- 交付汇报逐维度/风险面列出：已验证 / 已标记 / 不涉及。
- 被触发的验证维度和风险面必须进入完成前验证；未关闭项不得写成完成。
