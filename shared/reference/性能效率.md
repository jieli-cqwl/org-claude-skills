# 性能效率

## 核心要点

| 维度 | 处理策略 |
|------|------|
| 增量 | 优先增量处理，记录已处理状态，避免全量重跑 |
| 并发 | 先确认瓶颈、依赖承载能力、并发上限和失败策略；I/O 密集使用有界并发，CPU 密集再评估多进程 |
| 内存 | 大数据集流式/分批处理，及时释放 |
| 清理 | 临时文件固定命名 + try/finally 清理 |
| 数据库 | 合理使用索引，避免 N+1 查询 |
| 异步任务 | 状态持久化到 Redis/DB |

## 缓存策略

流程：先用 profiling、日志或基准测试记录瓶颈与基线指标 -> 明确数据新鲜度、失效策略、回滚/绕过方式、成本上限 -> 请求用户确认 -> 添加缓存 -> 用同一场景对比命中率、延迟、内存、正确性回归和失效行为。

## 检查清单

- 确认重量级资源是否为单例，并确认是否支持增量处理或断点续传。
- 确认批量操作已定义批大小、并发上限、背压/重试策略；大文件采用流式处理；临时文件有清理路径。
- 异步任务已定义超时、状态持久化、幂等和失败续跑策略。
- 检查清单只是注意力提示，不替代基线指标、失败模式和回滚条件。
