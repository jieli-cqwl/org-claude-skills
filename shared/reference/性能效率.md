# 性能效率

性能优化从可观测瓶颈开始，以基线指标、承载能力、失败路径和对比验证收口。策略服务目标指标，复杂机制只在能改善真实瓶颈时引入。

## 判断顺序

1. 定位瓶颈：先用 profiling、日志或基准测试记录瓶颈与基线指标。
2. 判断约束：确认延迟、吞吐、内存、成本、依赖承载能力和失败代价。
3. 选择策略：优先增量、流式、分页、索引、批处理和有界并发；缓存必须经用户明确同意。
4. 设计失败路径：记录并发上限、背压、重试、超时、清理、回滚或绕过方式。
5. 对比验证：用同一场景对比命中率、延迟、内存、正确性回归和失效行为。

## 策略选择

| 场景 | 处理方向 |
| --- | --- |
| 重复全量处理 | 优先增量处理，记录已处理状态，避免全量重跑 |
| I/O 密集 | 使用有界并发，明确并发上限、背压和失败策略 |
| CPU 密集 | 先确认算法和数据规模，再评估多进程或任务拆分 |
| 大数据集 | 流式或分批处理，避免一次性加载 |
| 临时文件 | 固定命名 + try/finally 清理，避免无限累积 |
| 数据库 | 分页、索引和查询路径评估，避免 N+1 查询 |
| 异步任务 | 状态持久化到 Redis/DB，定义超时、幂等和失败续跑 |

## 缓存策略

缓存会改变数据新鲜度、故障模式和回滚方式。引入缓存前必须明确：缓存对象、失效策略、绕过路径、成本上限、命中率目标和用户确认。
