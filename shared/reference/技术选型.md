# 技术选型

技术选型让目标、约束、风险、可逆性和回退边界进入同一张决策图，形成可追溯、可复核的选择。

## 进入选型的条件

满足任一时进入选型：引入新技术栈或框架、存在 2 个以上可行方案、基础设施变更、全局影响、高影响低可逆决策。

轻量记录适用：项目已有统一方案或仅存唯一方案，且影响局部、低风险、可逆、无新增安全/合规/运维约束。其余情况写选型记录。

## 选型判断

1. 识别决策点：用户目标、失败代价、非协商约束、影响范围、可逆性、关联模块。
2. 收敛候选：普通决策至少列 2 个候选；高影响低可逆决策列 3 个候选，少于 3 个时记录不可行原因。
3. 比较维度：目标匹配、风险/合规、运维成本、一致性、复杂度、维护成本、性能、学习成本、锁定风险。
4. 说明取舍：选择什么、放弃什么、牺牲什么、失效条件是什么。
5. 对齐确认：全局影响、低可逆或引入新技术栈时先向用户确认；仅用户已预授权的非交互流程可执行 AUTO_DECISION。

## AUTO_DECISION

- AUTO_DECISION 只能形成待确认方案记录。AUTO_DECISION 不授权真实引入或不可逆执行。
- 执行 AUTO_DECISION 时，先满足非协商约束和用户目标，再按质量属性排序裁决；一致性、复杂度和可逆性只作为次级信号。必须记录 `decision_status: AUTO_DECISION`、依据、失效条件和待人工确认风险。
- 涉及真实引入、不可逆执行或改变非协商约束时，必须停止并等待用户确认。

## 完成标准

- 选型原因清楚，能回到用户目标、约束、风险和质量属性。
- 候选方案和排除理由可追溯。
- 关键风险、失效条件和回退边界已说明。
- 下游实施、运维、测试和迁移影响已记录。
