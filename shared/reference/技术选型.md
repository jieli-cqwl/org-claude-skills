# 技术选型

## 触发条件

满足任一时进入选型流程：引入新技术栈/框架、>=2 可行方案、基础设施变更、高影响低可逆决策。

无需选型：项目已有统一方案或仅存唯一方案，且影响局部、低风险、可逆、无新增安全/合规/运维约束。否则写轻量选型记录。

## 选型流程

1. 识别决策点：记录用户目标、失败代价、非协商约束、影响范围、可逆性、关联模块
2. 候选方案：普通决策至少列 2 个候选；高影响低可逆决策列 3 个候选，少于 3 个时记录不可行原因
3. 对比矩阵：统一维度——目标匹配、风险/合规、运维成本、一致性、复杂度、维护成本、性能、学习成本、锁定风险
4. 对齐确认：全局影响、低可逆或引入新技术栈时先向用户确认；仅用户已预授权的非交互流程可执行 AUTO_DECISION，且 AUTO_DECISION 只能形成待确认方案记录；涉及真实引入、不可逆执行或改变非协商约束时，必须停止并等待用户确认

## AUTO_DECISION 策略

先满足非协商约束和用户目标，再按质量属性排序裁决；一致性、复杂度和可逆性只作为次级信号。必须记录 `decision_status: AUTO_DECISION`、依据、失效条件、待人工确认风险；AUTO_DECISION 不授权真实引入或不可逆执行。

## 反模式

只给一个方案、无对比矩阵、忽略一致性维度、不标记 AUTO_DECISION、未记录下游影响。
