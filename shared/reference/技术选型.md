# 技术选型

> 触发条件：引入新技术栈/框架、>=2 可行方案、基础设施变更、高影响低可逆决策时读取。

## 触发条件

满足任一时进入选型流程：引入新技术栈/框架、>=2 可行方案、基础设施变更、高影响低可逆决策。

无需选型：项目已有统一方案、仅存唯一方案、纯实现细节。

## 选型流程

1. 识别决策点：记录影响范围（全局/模块/局部）、可逆性、关联模块
2. 候选方案：普通 >=2 个，高影响建议 3 个
3. 对比矩阵：统一维度——一致性、复杂度、维护成本、性能、学习成本、锁定风险
4. 对齐确认：可交互则与用户确认；不可交互执行 AUTO_DECISION 并标记

## AUTO_DECISION 策略

优先级：一致性最高 > 复杂度最低 > 可逆性最高。必须在文档中记录 `decision_status: AUTO_DECISION` + 依据 + 是否需人工确认。

## 反模式

只给一个方案、无对比矩阵、忽略一致性维度、不标记 AUTO_DECISION、未记录下游影响。
