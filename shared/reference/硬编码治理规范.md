# 硬编码治理规范

硬编码治理把信息放到正确拥有方：敏感信息外置，环境差异配置化，稳定公共语义共享，局部实现细节就近维护。

## 分类与存放

| 类型 | 判断 | 存放位置 |
| --- | --- | --- |
| 敏感配置 | 密钥、密码、Token、Secret | 环境变量 / `.env`（不入库） |
| 环境配置 | 地址、端口、凭据、部署差异 | 配置文件或环境变量 |
| 用户消息 | 会被用户看到、需统一维护或本地化 | `runtime_config/messages.yaml` 或项目既有消息系统 |
| 业务常量 | 由业务规则拥有，语义稳定 | 概念拥有方的 `constants` |
| 枚举/状态 | 有限集合，需要比较和流转 | `enums` 或项目既有类型系统 |

## 常量分层决策

- 仅当前文件使用：文件顶部就近定义。
- 同模块多文件共享：放到模块拥有方。
- 跨模块共享：只有语义稳定且属于公共契约时提升到全局。
- 跨模块导入模块级常量时，先判断是否为稳定共享语义；否则优先调整依赖方向、保留边界内重复或放到概念拥有方。

## 命名与拆分

- 全局常量用领域前缀表达公共契约；模块常量用模块或概念前缀防止误用。
- 有限集合优先枚举；裸字符串或数字只用于局部、稳定、低风险场景。
- `constants.py` 膨胀时，按领域、所有权、稳定性和依赖方向拆分；只有稳定公共语义才提升到全局。

## 完成标准

- 敏感信息和环境特定配置没有写死在业务代码中。
- 共享常量有稳定语义和明确拥有方。
- 没有通过跨模块常量导入制造反向依赖或错误耦合。
- 保留重复时，说明它服务的边界、语义差异或未来分叉点。
