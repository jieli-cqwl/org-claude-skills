# 影响范围分析

影响范围分析不是列文件，而是保护行为：找出本次变更会影响哪些代码、配置、数据流、运行时依赖、用户路径和业务不变量。

## 三步识别法

### 1. 列变更点

从需求、Bug 或重构描述中提取将被修改的对象：代码符号、配置键、文档/规则条目、契约字段、脚本入口、数据表或 API 端点。

产出：直接修改文件和变更原因。

### 2. 追依赖链

从变更点出发，找到依赖它的调用方、配置、测试、文档、数据读写方和运行时路径。优先使用 LSP `findReferences` / `goToDefinition`，再用 `rg` 补充字符串引用、配置引用、动态调用和表字段引用。

产出：受影响但不一定直接修改的候选文件和用户路径。

### 3. 评估影响面

判断每个候选影响是需要同步修改，还是只需要回归验证。行为语义不变时，列出调用方验证对象，并用回归结果证明行为未受影响。

产出：需同步修改的文件、需回归验证的功能、无法覆盖的盲区和风险接受依据。

## 必查维度

| 维度 | 要看什么 | 常见遗漏 |
| --- | --- | --- |
| 代码符号 | 函数、类、字段、导入、公开接口 | 同名不同义、动态分发 |
| 配置/数据流 | 配置键、环境变量、缓存 key、队列、数据库表字段 | 字符串拼接、异步消费者 |
| 运行时依赖 | 中间件、拦截器、装饰器、定时任务、外部服务 | 条件分支内才触发的依赖 |
| 用户路径 | AC、关键流程、错误路径、权限路径 | 只验证 happy path |
| 业务不变量 | 状态转换、一致性、审计、资金/安全/合规约束 | 跨模块规则 |
| 搜索盲区 | LSP 不可见路径、反射、生成代码、历史高风险区 | 搜索无结果就断言无影响 |

## 并行安全

`shared_files` 为 0 仅表示文件范围无交集；确认接口、数据、配置和运行时依赖无共享写入后，可并行。

存在共享文件、共享契约、共享数据写入或同一用户路径时，先拆出共享前置任务，或指定串行/合并验证。

格式定义详见 `{{RUNTIME_HOME}}/reference/影响文件格式.md`。

## 完成标准

- 直接变更点、依赖链和影响面均已说明。
- 每个 `impact_file` 都有因果原因，不只是搜索结果。
- 搜索盲区、运行时依赖和用户路径风险已记录。
- 回归验证覆盖受影响调用方、用户路径和业务不变量。
