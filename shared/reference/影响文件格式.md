# impact_files 格式定义

`impact_files` 用来表达“哪些文件或路径会被本次变更影响，以及为什么”。它不是搜索结果清单。

## Scope Freeze 格式

在矩阵单元格中只写文件路径，按阅读顺序排列：

```text
services/user.ts, api/user.ts, tests/user.test.ts
```

无额外影响时写 `[]`，不要留空。写 `[]` 前必须已按影响范围分析检查代码符号、配置/数据流、运行时依赖、用户路径/业务不变量和搜索盲区。

## Task 清单格式

```md
- impact_files:
  - services/user.ts: 引用了被重命名的接口
  - api/user.ts: 需要同步适配返回字段
  - apps/web/src/pages/user/detail.tsx: 需要回归验证详情页展示
  - 已由 Task-3 覆盖
```

## 写法口径

- 需要同步修改：`路径: 具体原因`。
- 仅需回归验证：仍列出路径和需要验证的原因。
- 已被其他 Task 直接覆盖：写 `已由 Task-N 覆盖`。
- 确认没有额外影响时写 `[]`；`[]` 只表示无额外文件或回归项，不表示跳过影响分析。
- 若存在无法覆盖的搜索盲区、运行时依赖或用户路径风险，在任务/计划风险或验证说明中记录盲区和风险接受依据。
