# 文档规范

> 触发条件：创建或更新文档时读取。
> rules/文档管理.md 定义核心原则。本文件补充命名、强调和归档的意图说明。
> 部分规则有辅助检查（warning 级，不阻断）：`tests/test-doc-format-compliance.sh`。

## 命名意图

- **任务目录**用中文描述性名称，让人在文件系统层面一眼识别功能范围。任务内文件由 skill 定义英文名，保持跨项目一致性。
- **独立报告文件**（`docs/reports/` 目录下）带日期前缀（`YYYY-MM-DD_类型.md`），支持按时间排序和去重。Skill 产出物（如 `research-report.md`、`developer-report-Task-N.md`）由各 skill 定义命名，不受此规则约束。
- 辅助检查：`tests/test-doc-format-compliance.sh` 规则 2（仅扫描 `docs/reports/`，warning 级）

## 术语分工

- `本期不交付` = 范围边界（能力维度，表示"做了但不在本期"）
- `排除项` = 行为断言（可测试的"系统不应..."）
- 混用会导致评审者无法区分"暂缓"和"禁止"，产生验收歧义。
- 辅助检查：`tests/test-doc-format-compliance.sh` 规则 3（warning 级）

## 强调格式意图

- `**` 传递"这里有硬约束或风险"的信号。结构职责应由 Markdown 标题/列表/表格承担。
- 当 `**` 承担结构（如 `**定义**：`），LLM 会误判权重——把格式装饰当作强制约束处理。
- 辅助检查：`tests/test-doc-format-compliance.sh` 规则 1（warning 级）
