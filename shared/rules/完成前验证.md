# 完成前验证

## 完成声明

- 声称完成、通过、已修复、可交付或可合并前，验收范围内每个目标内验收项必须已有符合证据标准的证据。
- 写入或汇报完成类状态（如 `PASS`、`VERIFIED`、`ALLOW`、`SIGNED_OFF`、`CLOSED`）前，状态语义必须符合对应 schema、script、hook 或测试；自然语言汇报不得放大结构化状态结论。
- 完成状态必须来自真实实现；占位、仅日志、删除标记但未实现、部分实现或单端完成不得声明完成。
- 验收范围内任一目标内验收项未执行、失败、证据不足、依赖不可用、风险未关闭或待裁决时，不得声明完成。

## 验收范围

- 完成声明必须覆盖用户目标、成功标准、AC、任务合同和用户指定验收标准。
- 成功标准必须是可判定结果；仅描述执行动作、中间步骤或工具结果时，先补成可观察结果，补齐会改变验收口径时先请求用户裁决。
- 影响范围分析已识别的回归验证项、用户路径、业务不变量、搜索盲区和待裁决风险，属于完成声明的验收范围。
- 测试规范判定触发的功能、集成、E2E 验证维度和风险面，属于完成声明的验收范围。
- 已定义验证步骤属于完成声明的验收范围；前置条件不满足时，不得跳过该步骤并声明完成。
- 不涉及结论必须来自目标边界、影响范围分析、测试规范触发判断或用户裁决；不得用主观判断排除验收范围。

## 证据标准

- 完成证据必须来自当前工作区、本次执行结果、真实依赖、真实测试环境或已验证集成路径，并直接对应验收范围内的目标或验收项。
- 有验证命令时，完成声明必须基于本次重新执行的结果；历史输出、缓存结论或印象不得作为完成证据。
- 无自动化命令时，完成声明必须基于可复验记录；记录必须包含输入、步骤、环境、预期结果和实际结果。
- 可复验记录不得替代已触发的真实集成、E2E 或真实依赖验收。
- Mock/Stub/Fake 只能用于隔离不可控依赖或构造异常路径，不得单独证明真实集成通过。
- 日志摘要、主观判断、单个局部绿灯、工具状态或 report 自引用，不得单独证明完成。
- 本次变更必须能通过 `git diff` 对应当前目标；目标外修改未处理或未报告时，不得声明完成。

## 失败处理

- 失败后保持原目标、原成功标准和原验证口径；只允许重跑同一口径验证，或做不改变口径的诊断。
- 验证失败时，先定位失败对应的成功标准、AC、验收范围项或既有行为。
- 目标内失败必须修根因；目标外失败只报告，不扩大本次范围。
- 禁止用 skip、xfail、注释、删除测试、放宽断言或改写验收口径绕过失败。
- 需要换方案、降级能力、放宽验收、跳过步骤、用 Mock 替代真实依赖或接受未覆盖风险时，先请求用户裁决。
- 成功标准、真实依赖、测试、构建或联调无法满足时，停止完成声明并请求用户裁决。

## 完成汇报

- 完成汇报必须逐项列出成功标准、AC、触发验证维度、触发风险面和影响范围回归项，并标明状态与证据。
- 失败、阻塞或待裁决项必须说明阻塞原因和下一步；不涉及项必须说明不触发依据；未验证项、失败项、阻塞项和待裁决项不得并入完成结论。
