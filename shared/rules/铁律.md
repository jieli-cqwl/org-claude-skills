# 铁律（零容忍）

## 禁止降级

方案执行失败时，必须报告失败原因并等待指示。禁止静默切换备选方案、跳过失败步骤继续执行、或降低验收标准以通过检查。

## 禁止 Mock

测试必须连接真实数据库和服务。

## 硬编码规则来源

硬编码约束统一由 `rules/代码规范.md` 定义并执行，本文件不重复规则正文。

## 禁止跳过/删除/注释测试

测试失败时必须修复根因，禁止用 skip/注释/删除绕过。包括但不限于：`@pytest.mark.skip`、`@unittest.skip`、`xfail`、注释掉测试代码、删除失败的测试用例。

## 零容忍行为

- 虚假完成（代码是占位符）
- 删除 TODO/FIXME 假装修复——必须实现功能后再删除标记
- 日志输出假装功能——`console.log("done")` 不是实现
- 部分实现假装全部完成——必须逐条对照需求
- 前端完成后端未完成。详见 {{RUNTIME_HOME}}/reference/全栈开发.md
- 使用模糊表述（基本上、应该、可能、大概、差不多）

## 完成 = 验证通过

声称"完成"前，必须亲眼看到验证命令成功输出。详见 {{RUNTIME_HOME}}/reference/完成前验证.md

## 常见绕过借口

| 借口 | 现实 |
|------|------|
| "这个太简单不用测试" | 简单代码也会出 bug，测试只需 30 秒 |
| "我确定它有效了" | 确信不是验证，运行命令看输出 |
| "先写代码再补测试" | 后补的测试无法证明什么，必须先失败 |
| "Mock 一下更快" | Mock 测试只证明 Mock 行为，不证明真实行为 |
| "这次特殊，可以跳过" | 没有特殊情况，规则适用于所有情况 |
| "换个方案试试" | 禁止静默降级，报告失败原因并等待指示 |
| "先跳过这个测试" | 测试失败必须修根因，禁止 skip/注释/删除 |
