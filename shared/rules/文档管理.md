## 同步

- 代码与文档必须同步更新，过时文档视为 Bug
- 过时文档指与当前代码、contracts、scope registry、已接受决策或验证工具结果冲突的文档
- 完成标准：代码 + 文档同步完成才算完成
- 当仓库已有 contracts、hooks、validator 或 runtime 工具承载文档规则时，总纲、合同、工具、测试必须同步更新；只改说明或只改工具都不算完成

## 归档

- 过时文档必须归档至 docs/archive/（不参考此目录）
  Why：未归档的过时文档会被 LLM 当作有效参考读取，产生连锁错误
- 归档前先处理 active docs、测试、fixture、runtime 的入站引用；仍被验证或运行消费的材料迁入 fixtures/reference 等稳定位置，再归档任务目录
- 受管需求/任务文档目录完成并解除 active docs、测试、fixture、runtime 入站引用后，整目录移至 docs/archive/{task}/
- 被 scope registry 纳管的需求归档时，必须把 registry entry 改为 legacy，并写入 archive_ref / archived_at；归档后的 worklog 仍必须可恢复
- 发现过时文档时立即归档，不留到"以后处理"
  Why：延迟归档 = 延迟风险暴露，下一次对话会读到错误文档

## 活跃需求上下文接手

- 活跃需求默认只从 contracts/active-doc-scope.yaml 的 managed / migrated 条目发现；未纳管的 docs/* 不作为默认接手候选
- docs/{feature}/worklog.md 是受管需求接手入口，只记录 handoff_status / state_ref / next_ref 等导航字段，不复制 PRD、设计、任务或验收全文
- small-chain 的进展真源是 active workset 内的 design.md / tasks.md / plan.md / verify-change-report.md
- standard-chain 的进展真源是 canonical JSON；worklog 只能定位 active canonical artifact，不能替代 canonical 状态
- 上下文接手、归档恢复和引用可达性必须能通过 validate_context_contract.py、recover_context.py、validate-contracts 和对应测试证明

## 设计文档

- 只描述"是什么"和"为什么"，禁止 checklist/版本待办（进度跟踪属于 plan 文档）
  Why：设计文档混入进度跟踪会导致职责模糊，LLM 无法区分"设计决策"和"执行状态"
