# 文档管理

## 命名

- 受管目录统一使用 `--` 分隔语义段，语义段内部使用单 `-`，例如 `docs/feature--doc-governance--context-recovery`、`2026-04-28--doc-governance--context-recovery`
- 同一层级不得同时存在语义相同但分隔风格不同的目录
- 已纳管路径改名必须同步 `contracts/active-doc-scope.yaml`、入站引用、fixtures 和恢复测试

## 同步

- 行为、规则、contracts、工具或测试任一变化影响同一约束时，相关文档必须同步更新
- 过时文档指与当前代码、contracts、scope registry、已接受决策或验证工具结果冲突的文档
- 过时文档若与本次变更属于同一约束、会阻断验证或会误导当前交付，必须在本次变更内修正或归档；边界外过时文档只记录并报告，禁止借机扩大范围
- 涉及行为或约束变更时，完成验收必须包含文档同步证据

## 归档

- 过时且不再作为当前事实使用的文档必须归档至 `docs/archive/`
- 默认上下文接手不得读取 `docs/archive/`
- 归档前必须清理 active docs、tests、fixtures、runtime files 中仍指向该目录的引用；仍被验证或运行消费的材料必须迁入稳定 fixture/reference 位置
- 受管 feature/task 完成且解除入站引用后，整目录移至 `docs/archive/{feature-or-task}/`
- scope registry 纳管的需求归档时，必须把 entry 改为 `legacy`，写入 `archive_ref / archived_at`，并保留可恢复的 `worklog.md`

## 活跃需求接手

- 活跃需求接手必须从 `contracts/active-doc-scope.yaml` 的 `managed / migrated` 条目开始；未纳管的 `docs/*` 不作为接手候选
- `docs/{feature}/worklog.md` 只记录 `handoff_status / state_ref / next_ref` 导航字段；不得复制 PRD、设计、任务或验收全文
- standard-chain 的进展真源是 canonical JSON；worklog 只能定位 active canonical artifact，不能替代 canonical 状态
- 接手、归档恢复和引用可达性必须由 `validate_context_contract.py`、`recover_context.py`、`tools/validate-contracts.sh` 和相关测试证明
