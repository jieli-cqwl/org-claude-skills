# 代码规范

## MUST（必须遵守）

### 复杂度约束

- 函数圈复杂度（CC）<= 10。参数 > 5 个时，先按职责拆分函数或改为有业务含义的参数对象；只有存在框架签名、公共接口兼容或调用方契约证据时才可保留，并记录具体约束。嵌套 > 3 层时，先拆分职责或把失败条件移到主流程前。禁止为满足数字阈值机械拆出错误抽象。
- 文件 <= 400 行；超出时必须按职责拆分。仅生成文件、纯配置映射文件、稳定数据表可豁免，且必须在文件头或门禁配置记录来源、豁免原因和校验方式；禁止为规避行数把可执行业务逻辑放进这些豁免文件。

### 注释规范

- 注释用于解释意图、边界、约束和失败条件
- 公共边界、复杂业务逻辑、非显然约束必须注释
- 能从代码直接读出的内容不作为注释对象

### 错误处理规范

- 禁止空 catch 块、禁止裸 except
- 面向用户的错误提示必须可理解，禁止暴露堆栈、SQL、内部服务名等技术细节；内部日志或错误对象必须保留脱敏定位信息。
- 外部 API、网络和数据库调用必须设置超时并处理错误；文件 IO 必须处理错误并清理资源
- 错误路径要能追到上游依赖、请求 ID、重试状态

### 硬编码规范

- 禁止硬编码密钥/Token/密码/Secret，必须从配置或环境变量读取
- 禁止通过字符串拼接、默认值回填等方式绕过密钥配置管理
- 环境特定配置（地址/端口/凭据）必须外置配置化，禁止写死在业务代码
- 禁止跨边界导入非公共契约的模块私有常量。跨模块共享常量只有语义稳定且属于公共契约时，才由概念拥有方或公共契约层导出；否则调整依赖方向，或在各自边界内保留重复值。
- 详细分层与命名见 `{{RUNTIME_HOME}}/reference/硬编码治理规范.md`

### 死代码规范

- 本次新增、本次修改引入或本次目标内暴露的未使用导入、变量、函数和字段必须删除。
- 注释掉的大段旧实现、不可达分支、废弃占位逻辑禁止长期保留；既有目标外死代码只报告，除非阻断本次验证或属于本次目标边界。
- 确需保留兼容代码时，必须标注保留原因与失效条件

### 性能约束

- 临时文件使用唯一路径并确保清理；禁止固定共享路径或无限累积
- 大表查询必须分页；涉及用户路径、批处理或高频查询时，必须基于查询路径和执行计划评估索引
- 异步任务状态持久化到 Redis/DB，必须有超时控制
- 引入跨请求、跨进程、持久化、共享状态或会影响数据新鲜度/一致性的缓存前，必须经用户明确同意；单次执行内的局部去重或中间结果复用不属于缓存引入。
- 详细指南见 `{{RUNTIME_HOME}}/reference/性能效率.md`

### 复用治理规范

- 新增实现前，必须先判断是否已有语义一致的候选实现
- 最终选择不复用而新建实现时，必须在代码注释、设计文档或 PR 描述中说明原因
- 复用的目标、判断标准与注意事项见 `{{RUNTIME_HOME}}/reference/代码复用.md`
