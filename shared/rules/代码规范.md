# 代码规范

## MUST（必须遵守）

### 复杂度约束

- 默认上限：函数 CC <= 10、参数 <= 5、嵌套 <= 3；代码文件 <= 400 行。
- 优先前置失败条件，让主流程保持线性，避免深层嵌套。
- 函数超限时按职责拆分；参数过多时改为有业务语义的参数对象。
- 豁免边界：函数仅限框架签名、公共接口兼容或调用方契约；文件仅限生成文件、纯配置映射或稳定数据表。豁免必须记录依据和校验方式。
- 禁止为凑阈值拆出错误抽象，或把业务逻辑塞进豁免文件。

### 注释规范

- 注释只解释代码本身看不出的意图、边界、约束、取舍和失败条件。
- 公共边界、复杂业务规则、非显然约束和高风险异常路径必须注释。

### 错误处理规范

- 禁止空 catch、裸 except、仅 log 后继续或返回无错误信号的默认值。
- 用户可见错误必须可理解，不暴露堆栈、SQL、密钥、内部路径或服务名。
- 外部 API、网络和数据库调用必须设置超时并处理失败；文件 IO 必须处理失败并清理资源。
- 错误必须留下可排障上下文，如请求 ID、失败依赖和重试状态；日志不得包含密钥或用户敏感数据。

### 硬编码规范

- 禁止硬编码密钥、Token、密码和 Secret；必须从配置或环境变量读取。
- 禁止通过字符串拼接、默认值回填等方式绕过密钥配置管理。
- 地址、端口、凭据等环境差异必须配置化，禁止写死在业务代码。
- 跨模块共享常量仅限语义稳定的公共契约；禁止导入其他模块私有常量，不满足时调整依赖方向或在边界内保留重复值。
- 详细分层与命名见 `{{RUNTIME_HOME}}/reference/硬编码治理规范.md`

### 死代码规范

- 本次新增、修改或目标范围内发现的未使用导入、变量、函数和字段必须删除。
- 本次目标内不得保留注释掉的旧实现、不可达分支、废弃占位逻辑。
- 既有目标外死代码只报告；阻断本次验证或属于本次目标边界时才处理。
- 兼容代码必须标注保留原因和失效条件。

### 性能约束

- 临时文件必须使用唯一路径并清理，禁止固定共享路径或无限累积。
- 大表查询必须分页；涉及用户路径、批处理或高频查询时，必须评估查询路径、索引和执行计划。
- 异步任务状态持久化到 Redis/DB 时，必须定义超时和可见失败路径。
- 引入跨请求、跨进程、持久化、共享状态或影响数据新鲜度/一致性的缓存前，必须经用户明确同意；单次执行内的局部去重或中间结果复用不属于缓存。
- 详细指南见 `{{RUNTIME_HOME}}/reference/性能效率.md`

### 复用治理规范

- 新增实现前，必须判断是否已有语义一致的现有实现。
- 复用必须同时满足语义一致、变化节奏一致和依赖方向健康；不满足时保留具体实现。
- 选择新建时，必须在代码注释、设计文档或 PR 描述中说明候选实现和不复用原因。
- 复用细则见 `{{RUNTIME_HOME}}/reference/代码复用.md`
