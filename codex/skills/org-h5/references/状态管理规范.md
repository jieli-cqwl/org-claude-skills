# 状态管理规范（Pinia）

## Store 目录与命名

```
store/
├── Index.js          # 统一导出所有 useXxxStore
└── modules/
    ├── Common.js     # 系统信息、用户信息、全局配置
    ├── User.js       # 用户状态
    └── {业务}.js     # 业务状态
```

| 约定 | 格式 | 示例 |
|------|------|------|
| Store ID | 小写 | `'tenant'` |
| 导出函数 | `use{模块}Store` | `useTenantStore` |
| 文件名 | PascalCase | `Tenant.js` |

## Common Store 职责

- `initSystemInfo()`：statusBarHeight / windowWidth / safeAreaInsets / platform
- `setLoginStatus(token, userInfo)`：写 state + `uni.setStorageSync`
- `logout()`：清 state + `uni.removeStorageSync`

## 业务 Store 模式

### 多步骤表单
- state: `step / maxStep / 各步骤数据对象`
- actions: `nextStep() / prevStep() / saveStepData(name, data) / getFormData() / reset()`
- 页面 `onUnmounted` 调用 `reset()`

### 列表筛选
- state: `filters: { status, keyword, ... } / sortBy / sortOrder`
- actions: `setFilter(key, value) / setFilters(obj) / resetFilters()`

## 使用约定

| 场景 | 方案 |
|------|------|
| 多组件/多页面共享、多步骤表单 | Store |
| 单页面临时数据、组件内部状态 | `ref` |
| 解构响应式状态 | `storeToRefs(store)` |
| 解构 actions | 直接解构 `const { reset } = store` |

## 持久化

需持久化的字段在 action 中手动 `uni.setStorageSync`，初始值从 `uni.getStorageSync` 读取。

## 页面离开清理

页面级 store 必须在 `onUnmounted` 调用 `reset()`。
