# Skill 反模式清单

## 常见反模式

| # | 反模式 | 表现 | 正确做法 |
|---|--------|------|---------|
| 1 | 身份单薄 | 一句话身份 | 补心理驱动 + 质量锚点 |
| 2 | 约束后置 | 约束埋在中间/末尾 | 约束紧跟角色，放文档前部 |
| 3 | 缺少反例 | 只有好的 Few-shot | 好/坏成对，坏的附原因 |
| 4 | 模糊输出 | "输出分析报告"无格式 | 提供完整输出模板 |
| 5 | 知识散落 | 方法论混在入口 Skill 中 | 三层分离：入口 + Agent 身份 + 知识引用 |
| 6 | 任务类型错配 | 创造型用竞争框架 | 按任务类型-身份匹配表选择 |
| 7 | 无偏差对抗 | 审查/验证类缺偏差检测 | 输出前增加偏差自检 |
| 8 | 过长无结构 | 大段文字没有层次 | 标题/表格/列表组织 |
| 9 | CSO 违反 | description 写完整摘要 | description 只写"何时触发" |
| 10 | Token 超标 | SKILL.md 500+ 行不拆分 | 详细内容拆到 references/ |
| 11 | 字段格式过时 | 用 `user_invocable` | 用 `user-invocable`（连字符） |
| 12 | 冗余字段 | 写了 `command: xxx` | `command` 已废弃，由 name 决定 |
| 13 | 无基线测试 | 写完直接用没验证 | 跑 TDD RED-GREEN-REFACTOR |
| 14 | 时效性信息 | 包含日期/版本等会过时的内容（如"2025年8月前用旧API"） | 用 "Current method" / "Legacy (deprecated)" 结构替代日期条件（官方） |

## 反合理化条款

FORBIDDEN 以下跳过理由：
- "任务简单" -> 不可跳过 Few-shot 对比示例
- "不适用" -> 不可跳过认知偏差自检（纯 Reference 除外）
- "格式灵活" -> 不可省略输出模板必填字段
- "效率优先" -> 不可合并或跳过验证步骤

## TDD 验证流程

| 阶段 | 目标 | 完成标准 |
|------|------|---------|
| RED | 无 Skill 基线 | 记录遗漏步骤、格式问题、偏差、评分(1-5) |
| GREEN | Skill 有效性 | 评分 >= RED + 2（或达 5）|
| REFACTOR | 堵合理化漏洞 | 连续 2 次无新借口，评分稳定 >=4 |
