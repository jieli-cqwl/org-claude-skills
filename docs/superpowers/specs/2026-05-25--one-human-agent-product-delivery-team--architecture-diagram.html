现状差距摘要

这部分供评审讨论和工程化排期使用，不属于主图表达。

维度目标要求现状证据差距判定建议下一步
层级模型主链、执行池、保障脊柱、支撑输入分层清楚。standard-chain.yaml 主要只有 main / sidecar。机器真源缺少 L0-L4 语义。为流程契约增加层级、权限和支撑接口元数据。
产品边界产品总监拥有方向和阶段基线；产品经理只产出需求单元和变更建议。当前产品经理仍可 refine 上游 brief.json 与 phase-prd.json。可执行契约和目标边界不一致。把 refine 改成变更请求或派生视图。
执行池定位开发、验证、审查、验收、修复、审计只由交付负责人调度。交付负责人 skill 已这样定义，但标准链仍把部分执行角色放在主链。行为描述和机器模型漂移。把执行角色统一标成执行池或受控 sidecar。
运行门禁交付运行应有可验证、可暂停、可恢复的阶段门禁。skill 文本有分阶段规则，schema 和 chain 还没有完整承载。规则可读但不可充分机器验证。把交付阶段门禁落入状态契约和校验脚本。
证据来源事实、假设、建议必须分层进入主链。现状多为证据引用，缺少统一 provenance 字段。证据可信度和 canonical impact 不够硬。新增证据来源契约并接入各阶段门禁。
签收边界交付包表示准备就绪，不等于用户签收。已有签收状态字段，但 readiness 和 acceptance 语义仍需收紧。字段雏形存在，语义边界未完全工程化。增强签收包 schema 与完成门禁。
