# 2026-04-01 首周执行节奏与分工

周期：`2026-04-01 ~ 2026-04-07`

## 角色分工

- 试点负责人：
  - 维护试点入口口径
  - 审核样本是否纳入试点池
  - 汇总周复盘和试点总结
- 样本执行人：
  - 按入口文档执行真实样本
  - 记录单样本证据
  - 发现超界时及时转标准链
- 反馈记录人：
  - 汇总误路由、卡点、运行面波动
  - 维护复盘指标

## 执行节奏

### Day 0

完成启动确认：

1. 阅读 `docs/community-first/试点执行入口.md`
2. 阅读本轮启动说明
3. 确认首周样本池
4. 确认记录模板位置

### Day 1 ~ Day 5

每天最多跑 `1` 个真实样本，顺序如下：

1. 选择样本
2. 先建单样本记录
3. 执行 community-first 轻量链
4. 当天补齐结论和问题记录

### Day 6 ~ Day 7

收口阶段：

1. 汇总本周样本数据
2. 补周复盘
3. 判断下周是否继续扩大样本池

## 每日最小检查

若当天是第一次执行，先跑：

```bash
cd ~/org-claude-skills
bash tests/run-all.sh
bash tools/dev/probe-runtime-capabilities.sh ~/org-claude-skills
```

说明：

- 若 `probe-runtime-capabilities` 只出现已文档化 WARN，可继续
- 若出现新的 `FAIL`，暂停当天试点

## 暂停规则

出现任一情况，当天停止继续加样本：

1. 出现新的未文档化 runtime `FAIL`
2. 连续两个样本都误路由
3. 连续两个样本都被迫转标准链，且原因相同
4. 边界判断明显无法达成共识

## 周末输出

本周结束时至少补齐：

- `1` 份周复盘
- `1` 份 go/no-go 判断
- 若发现高频边界问题，再补 `1` 份边界修订建议
