# Community-First 试点执行入口

目标：给试点负责人一个单页入口，明确“先看什么、怎么执行、产出什么、遇到什么情况暂停”。

## 当前真源

试点期间只认下面这组真源：

- 分层与职责：`docs/community-first/boundary-contract.md`
- 默认链与阶段：`docs/community-first/README.md`
- 机器链路合同：`contracts/community-first-chain.yaml`
- 投入使用判断：`docs/community-first/go-live-plan.md`
- 试点执行清单：`docs/community-first/pilot-rollout-checklist.md`
- 仓库级运行验收：`docs/runtime-acceptance-sop.md`

以下文档仅作为历史背景，不作为当前执行口径：

- `docs/rfcs/2026-03-26_community-first默认流RFC.md`
- `docs/reports/readiness/2026-03-26_community-first轻量流程采用建议.md`

## 建议执行顺序

1. 先读 `docs/community-first/boundary-contract.md`
2. 再读 `docs/community-first/README.md`
3. 用 `docs/community-first/go-live-plan.md` 判断当前是否进入试点窗口
4. 按 `docs/community-first/pilot-rollout-checklist.md` 执行单样本试点
5. 用 `docs/runtime-acceptance-sop.md` 做仓库级运行验收补充
6. 把结果写入 `docs/community-first/pilot-records/`

## 样本选择原则

优先挑这种需求：

- 单次可收口
- 风险低到中
- 不需要正式多阶段排期
- 行为变化可以在一次 change 内说清

不要放进试点池：

- 核心模型或核心 API 大改
- 高风险安全、性能、兼容变更
- 明显需要完整标准链的需求

## 暂停条件

出现任一情况就暂停试点，回到显式标准链或先修口径：

- 默认入口频繁误路由
- `boundary contract` 或 validator 出现结构性失败
- 安装与运行验收结果和文档口径明显冲突
- 试点成员无法判断边界
