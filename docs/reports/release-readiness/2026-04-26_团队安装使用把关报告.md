## 主要风险

### R1: secret scanning 未清零

- 证据：`tests/test-feishu-docs-wrapper.py:110`, `tests/test-feishu-docs-wrapper.py:111`, `tests/test-feishu-docs-wrapper.py:136`
- 影响：团队或 CI 启用 gitleaks 会失败；即使是假 token，也会造成发布门禁噪音。
- 建议：改为不会触发 secret scanner 的 fixture，或加精确 allowlist。
- 状态：已改为运行时拼接 fixture；历史 fixture 通过 `.gitleaks.toml` 精确 allowlist 处理。

### R2: 当前本机存在 ignored token 日志

- 证据：`tools/eval/results/standard-chain-local-20260421/design-alternatives-fixture-debug-run-1/design/alternatives-and-runtime-scan/run-1/executor.log:2084`
- 影响：不在 git 发布快照里，但对当前机器和任何直接打包当前工作区的动作有风险。
- 建议：立即轮换相关 token，删除本地日志，并补充 eval 日志脱敏策略。
- 状态：已删除本地日志；token 轮换仍需用户在凭据侧完成。

### R3: `claude-code-engineering` gitlink 无 `.gitmodules`

- 证据：`git ls-files -s` 显示 `160000 ... claude-code-engineering`；`git submodule status` 失败。
- 影响：团队 clone、健康检查、递归子模块流程会困惑；本地子模块内容还会放大 secret scan 噪音。
- 建议：明确删除该 gitlink，或恢复 `.gitmodules` 并把它作为教学材料单独治理。
- 状态：已从 git index 移除 gitlink，并把本地目录加入 `.gitignore` / `.gitleaks.toml`。

### R4: deep-research XML 解析需要 hardening

- 证据：`shared/skills/deep-research/scripts/arxiv_search.py:31`
- 影响：手动触发 deep-research 时会解析外部 arXiv XML；Bandit B314 报 MEDIUM。
- 建议：改用 `defusedxml.ElementTree`。
- 状态：已改用 `defusedxml.ElementTree`。
