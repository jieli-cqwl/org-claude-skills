**结论：冲突成立，必须拆 Phase。**

**总目标**
长期方向是“agent 能力平台化”：未来多业务线可接入渠道、bot、上下文、调度、观测、灰度、权限、计费、配置等能力。
但这只是北极星，不是单 Phase 交付目标。

**目标冲突**
“全量平台化”是跨业务线、跨能力域的平台建设，投入量级明显大于两周。
“两周见真实效果”要求最小闭环、真实业务验证。两者不能同时塞进 Phase 1，否则 PM 会被迫背全量平台范围，必炸。

**Phase 1**
两周内只做“单业务线 / 单渠道 / 单 bot / 单真实场景”的端到端样板验证。
目标是证明：一人 + agents 可以基于现有 qft-pai 能力完成一次真实交付闭环，并产出可观察效果信号。

**Phase 1 非目标**
不做全渠道接入平台。
不做通用 bot 管理平台。
不做完整上下文平台、agent 调度平台、观测平台、灰度平台、权限平台、计费平台、配置平台。
不承诺多业务线通用化。
不进入语言选型、架构方案、PRD、UNIT、AC、设计或任务拆解。

**投入边界**
Phase 1 固定两周内，默认一人 + agents。
优先复用现有 qft-pai 能力，只允许为样板闭环补最小必要能力。
任何会把范围推向“通用平台底座”的内容全部后置，不交给 PM 在 Phase 1 内细化。

**给 PM 的保护边界**
PM 只能基于 Phase 1 细化“单场景真实闭环”。
PM 不承担“未来所有业务线接入”的全量平台目标，也不负责把渠道、bot、上下文、调度、观测、灰度、权限、计费、配置一次性产品化。
