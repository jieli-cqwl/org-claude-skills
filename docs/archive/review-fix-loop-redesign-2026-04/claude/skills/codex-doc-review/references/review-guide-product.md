# 审查指引 — product 阶段特异维度

> 本文件定义 product 阶段（PRD）的 2 个特异审查维度。
> 与 `review-guide-base.md` 拼接后传给 Codex，基础维度（一致性/完整性/DECEPTION）在 base 文件中定义，此处不重复。

---

## 特异维度 1: 可验证性

- 审查焦点: AC（验收标准）是否可测试、可观察，有无模糊词
- 判定标准:
  - PASS: 所有 AC 都有明确的行为定义和可观察的预期结果，无模糊词
  - WARN: 部分 AC 表述稍模糊但可推断意图（如"返回错误"未指明具体错误码）
  - FAIL: AC 使用不可测试的表述（如"系统应当高效处理"、"用户体验良好"）

### 审查检查项

1. 每条 AC 是否包含触发条件（When）+ 预期行为（Then）？
2. 预期行为是否可观察（返回值、状态变化、输出内容）？
3. 是否存在模糊词："高效"、"良好"、"合理"、"适当"、"基本"？
4. 成功标准是否有度量方式（数字、百分比、具体状态）？

## 特异维度 2: 范围边界

- 审查焦点: 功能范围和排除项是否明确，无模糊地带
- 判定标准:
  - PASS: 范围明确定义了"做什么"和"不做什么"，排除项具体可判断
  - WARN: 范围基本明确但存在少量灰色地带（如未说明是否包含某个边缘场景）
  - FAIL: 范围描述含糊（如"支持常见场景"未列举）或排除项缺失

### 审查检查项

1. "范围"章节是否列出了具体的功能项？
2. "排除项"是否明确列出了不做的事？
3. 是否存在可能引起歧义的边界场景未做说明？
4. 范围和排除项是否互斥（不存在既在范围内又在排除项中的功能）？
