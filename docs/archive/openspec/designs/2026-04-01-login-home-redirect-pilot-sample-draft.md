# 登录成功后跳转首页 试点模拟样本设计（Draft）

日期：`2026-04-01`

## 1. 背景

本设计不是面向当前仓库的真实业务实现，而是作为 `community-first` 小范围试点的第一条模拟样本，用来验证：

1. 一个典型小需求能否被 `brainstorming` 正确收口
2. 该需求是否适合继续进入 `writing-plans`
3. 边界合同、样本记录模板和试点入口，是否足以承接真实业务样本

样本需求：

- 用户在登录页输入有效凭证
- 登录成功后写入本地登录态
- 跳转到首页

## 2. 目标

把“登录成功后跳转首页”定义成一条典型小需求样本，并明确它在真实业务仓库中的最小闭环。

本样本要验证的不是视觉设计或复杂鉴权架构，而是下面这条最短用户路径：

1. 用户提交登录表单
2. 后端返回成功
3. 前端保存登录态
4. 页面跳转到首页

## 3. 非目标

本样本不覆盖：

- 注册
- 找回密码
- 第三方登录
- 复杂权限模型
- 首页复杂业务初始化
- 登录失败态的完整文案矩阵
- 未登录访问首页后的回跳逻辑

这些内容超出了本轮“小需求样本”的最小闭环。

## 4. 为什么这是一条合适的试点样本

这条样本符合当前 `community-first` 小需求边界：

- 单次可收口
- 风险低到中
- 用户价值明确
- 成功标准清晰
- 不依赖正式多阶段排期

同时，它也足够真实，能暴露以下关键判断：

- `brainstorming` 是否能把需求边界收紧到最小闭环
- `writing-plans` 是否能把它拆成可执行步骤
- 团队是否能判断哪些能力属于本期不交付

## 5. 方案

### 方案 A：最小闭环跳转

登录成功后：

1. 写入本地登录态
2. 立即跳转首页

优点：

- 最符合本轮试点目标
- 范围最小
- 易于验证成功路径

缺点：

- 未覆盖回跳和失败态细节

### 方案 B：补回跳参数

登录成功后优先跳回原始目标页，否则跳首页。

优点：

- 更接近真实产品

缺点：

- 边界扩大
- 会把本轮样本从“成功后跳首页”扩成“会话路由策略”

### 方案 C：同步首页初始化

登录成功后不仅跳首页，还触发首页首屏数据加载和动效恢复。

优点：

- 更完整

缺点：

- 明显超出本轮样本的最小闭环

## 6. 选择结果

选择 **方案 A：最小闭环跳转**。

理由：

- 这是当前最适合作为试点首样本的闭环
- 能验证 route、session 和样本边界判断
- 不会把样本扩成鉴权体系改造

## 7. 最小业务语义

若放在真实业务仓库中，本样本的最小语义定义如下：

- 输入：
  - 用户名/密码
- 成功条件：
  - 登录接口返回成功
  - 本地登录态写入成功
  - 页面路由切到首页
- 失败条件：
  - 登录接口失败时不跳转首页

## 8. 数据流

最小数据流：

1. 登录页提交表单
2. 调用登录接口
3. 登录成功响应返回 token 或会话信息
4. 前端写入本地存储或内存会话
5. 执行 `redirectTo` / `replace` / 等价路由动作进入首页

## 9. 测试关注点

真实业务仓库中，这条样本最小应覆盖：

1. 登录成功时跳转首页
2. 登录成功时会话已写入
3. 登录失败时不跳转

## 10. 试点判断

本样本结论：

- 适合作为 `community-first` 第一条真实模拟样本
- 适合作为首周样本池中的“实现类小需求”
- 不需要退回标准链
