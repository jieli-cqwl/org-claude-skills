# org-claude-skills 系统性项目分析设计草稿

## 背景

当前接手者刚进入 AI 应用开发语境，需要先建立对 `org-claude-skills` 的系统认知，而不是直接进入局部优化。本次工作的目标不是实现功能变更，而是通过一轮结构化并行调研，回答项目定位、关键问题和最佳实践方向三个核心问题，并通过独立 challenger 机制抑制既有叙事、既有文档和权威结论带来的锚定偏差。

## 目标

本次分析要产出以下三类结论：

1. 当前项目的真实定位，以及它试图解决的业务目标。
2. 当前仓库中哪些能力、资产、规则、流程或验证手段已经存在，但尚未形成足够高的实际收益；其中哪些问题一旦修复，会显著提升整体产出质量，尤其是正确性、一致性和验收可信度。
3. 在质量优先前提下，接下来最值得探索和落地的最佳实践方向，以及哪些方向应立即推进、试点验证或暂缓。

## 分析方法

本次调研采用五路并行审议结构：三条主分析线加两条 challenger 线。各线先独立形成初步判断，再由主审议者统一做交叉比对、冲突归并与裁决。

### 主分析线

#### 1. 定位线

关注以下问题：

- `org-claude-skills` 本质上是产品、工程资产库，还是组织级 AI 工程工作流基础设施。
- 它服务的主要对象是谁。
- 它试图解决的核心业务问题是什么。
- README、contracts、shared、community、docs 与近期变更是否共同支持同一条主叙事。

#### 2. 高杠杆问题线

关注以下问题：

- 哪些资产、机制、流程、规则、验证手段已经存在，但没有形成真实收益。
- 哪些能力只是“声明存在”，但运行面证据不足。
- 哪些问题修复后能带来质量跃迁，而不是局部修补。
- 哪些改动会显著提升正确性、一致性、验证可信度与复用效率。

#### 3. 最佳实践线

关注以下问题：

- 在质量优先前提下，下一阶段最值得投入的工程实践是什么。
- 哪些方向适合立即落地，哪些方向应先试点，哪些方向暂不建议投入。
- 哪些实践能增强真实运行验证、路线判断、单一真源治理、双运行时差异治理和文档合同运行时一致性。

### Challenger 线

#### 4. Challenger A：产品 / 组织视角

重点挑战：

- 项目是否真的在解决高价值问题。
- 现有流程和治理是否真正转换为业务收益。
- adoption 成本是否可能抵消质量收益。
- 是否存在“为了治理而治理”的倾向。

#### 5. Challenger B：架构 / 工程治理视角

重点挑战：

- 当前体系是否存在过度设计或概念层次过多的问题。
- canonical、contracts、openspec、shared、adapter 分层是否引入过高理解成本。
- 运行时真实性是否真的强于文档叙事，还是仍有大量声明性保障未被实证闭环。
- 当前复杂度里哪些是 Essential，哪些是 Accidental。

## 证据边界

本次分析遵循以下证据边界：

- 以仓库内证据为主，包括 README、contracts、shared、community、docs、tests、近期提交与运行验证材料。
- 允许使用上游社区来源与外部最佳实践作为对照与挑战，但不得替代本仓库证据。
- 不把已有报告、设计文档或说明文档的结论直接视为事实，必须检查其是否被合同、测试或真实运行验证支撑。
- 证据优先级遵循：运行面证据 > 文档叙事；真实验证 > 设计意图。

## 裁决规则

当不同分析线或 challenger 结论冲突时，按以下顺序裁决：

1. 真实运行验证证据优先于静态文档描述。
2. 已被合同、测试、样本回放支撑的判断优先于仅存在于设计意图中的判断。
3. 能显著提高质量并形成长期复利的方向优先于仅增加流程完整性的方向。
4. 可落地且可验证的正确方向优先于 adoption 成本过高的理想化方案。

若 challenger 成功推翻主线结论，最终报告必须显式记录修正过程与原因。

## 输出结构

最终交付采用双层输出。

### 第一层：战略判断

面向接手者快速建立全局认知，回答：

1. 当前项目的真实定位与业务目标。
2. 当前最值得优先处理的高杠杆问题。
3. 接下来最值得探索和落地的最佳实践方向。
4. 关键风险与优先级建议。

### 第二层：执行视图

对每个核心结论给出：

- 证据来源。
- 关键发现。
- challenger 的反向挑战与是否成立。
- 修正后的最终判断。
- 优先级。
- 建议动作。
- 为什么该动作能提升质量而不是单纯增加流程。

## 协作机制

每个 agent 都必须独立产出以下内容：

- 结论。
- 支撑证据。
- 不确定项。
- 风险判断。
- 建议动作。

在主审议阶段，不允许 agent 之间先共享结论，以减少锚定效应。最终统一归并时，才进行交叉质询和冲突对照。

## 本期不交付

本次工作不包含以下内容：

- 直接修改仓库实现。
- 直接落地新的规则、hook 或 skill。
- 在没有新一轮设计批准前，启动实现型技能或执行变更计划。
- 把本次分析直接扩展为 roadmap 执行。

## 成功标准

本次分析完成后，接手者应能够：

1. 用简洁语言说明 `org-claude-skills` 的定位、服务对象和核心价值。
2. 区分“已经有但没真正发挥价值”的能力与“目前根本不存在”的能力。
3. 明确 3-5 个对质量提升最关键的高杠杆问题。
4. 明确下一阶段最佳实践的推进顺序，并理解其依据不是权威，而是证据、挑战和裁决。
