### 逐条对比

| HARD-GATE | A 变体 | B 变体 | 差异点 |
|-----------|--------|--------|--------|
| 1. 扫描现状 | PASS | PASS | 均有架构师审视维度 |
| 2. 方案对比+闭环 | FAIL (3/5 DD有对比, 无迁移闭环) | PASS (5/5 DD有对比, 全部有迁移/验证/回滚) | B 显著优于 A |
| 3. 完整工件集 | FAIL (缺待计划约束+影响范围) | PASS (两项均有) | B 完整, A 缺失关键章节 |
| 5. 共创记录 | PASS | PASS | 均有共创摘要 |
| 6. 无流程跳步 | PASS | PASS | 均顺序执行 |
| 8. 最终确认 | PASS | PASS | 均有交付确认 |

### 分析

结果与预期相反：移除 Why 后合规率未下降反而上升。可能解释：

1. **Context 预算假说**：B 变体 SKILL.md 少了 8 行 Why（约 300 tokens），agent 有更多 context 预算用于生成完整设计文档。A 变体的 Why 消耗��� context，可能导致尾部章节（待计划约束、影响范围清单）被截断或遗忘。
2. **随机方差**：单次运行（n=1），两次执行的 agent 实例可能在能力上有自然差异。无法从单次结果得出因果结论。
3. **Why 认知干扰假说**���Why 解释可能反而分散了 agent 对规则本体的注意力，导致"理解了为什么但遗忘了做什么"。

**结论**：单次运行数据不足以判定 Why 的因果效应。需要至少 3×3 重复实验确认方向。当前数据提示 Why 的正面效应不如预期明显，且可能存在 context 消耗的负面效应。
