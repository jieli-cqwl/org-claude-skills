### ADR-002: API 契约设计
状态: Accepted
背景: 前后端分离需要明确 API 契约。需覆盖登录、周报列表两个端点，以及统一错误格式。
决策: 选择 RESTful JSON API + 统一错误响应格式。
理由: 1) 端点少（2 个），REST 足够表达；2) FastAPI 原生支持 JSON schema 和自动文档；3) 统一错误格式降低前端解析复杂度。
用户确认: RESTful 足够，不需要 GraphQL — 共创步骤 5
备选方案:
| 方案 | 优势 | 劣势 | 淘汰原因 |
|------|------|------|---------|
| GraphQL | 灵活查询、减少冗余传输 | 2 个端点过度设计、增加依赖 | 场景简单，REST 足够 |
| gRPC | 高性能、强类型 | 浏览器支持差、需 protobuf | 前端 React 不适合 |
后果: 正面：简单直观、FastAPI 自动生成 OpenAPI 文档 / 负面：无 / 约束：所有端点返回统一 JSON 结构
