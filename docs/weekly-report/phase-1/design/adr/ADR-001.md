### ADR-001: JWT 存储方案
状态: Accepted
背景: 前端需存储 JWT token 以维持登录态。localStorage 和 httpOnly cookie 各有安全权衡：localStorage 易受 XSS 攻击但实现简单；httpOnly cookie 防 XSS 但需处理 CSRF 且跨域配置复杂。
决策: 选择 localStorage。
理由: 1) 内网应用 10-50 人，XSS 风险可控；2) 前后端分离架构下 cookie 跨域配置复杂度高（需 SameSite/Secure/CORS credentials），收益不匹配；3) 24h 过期 + 不含敏感信息，token 泄露窗口有限。
用户确认: 内网场景优先简单方案，安全风险可接受 — 共创步骤 5
备选方案:
| 方案 | 优势 | 劣势 | 淘汰原因 |
|------|------|------|---------|
| httpOnly cookie | 完全防 XSS 读取 token | CSRF 风险、CORS 配置复杂、前端无法读取 token payload 做路由守卫 | 路由守卫需读 token 判断过期，httpOnly 阻断此路径 |
| sessionStorage | 标签页隔离、关闭即清除 | 新标签页需重新登录，用户体验差 | 10-50 人内网场景多标签使用频繁 |
后果: 正面：实现简单，路由守卫可直接解码 token / 负面：XSS 可读取 token / 约束：前端必须做 XSS 防护（React 默认转义 + 禁止 dangerouslySetInnerHTML）
