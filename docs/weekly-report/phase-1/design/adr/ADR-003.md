### ADR-003: 数据库 Schema 设计
状态: Accepted
背景: SQLite + 原生 SQL，需设计 users 和 reports 两张表的结构、索引和约束。display_name 是否 NOT NULL 影响前端展示逻辑。
决策: 选择 display_name NOT NULL（注册/预置时必填）+ reports 按 created_at 倒序索引。
理由: 1) 消除前端空值降级逻辑；2) 管理员预置账号时填写 display_name 是合理约束；3) 倒序索引优化首页查询性能。
用户确认: display_name 必填合理，预置数据可控 — 共创步骤 5
备选方案:
| 方案 | 优势 | 劣势 | 淘汰原因 |
|------|------|------|---------|
| display_name 允许 NULL + 前端降级显示 username | 灵活 | 增加前端逻辑、展示不一致 | 预置场景下 NULL 无业务意义 |
| 单独 profiles 表 | 扩展性好 | 两表 JOIN 增加复杂度 | 本轮字段少，不需要拆表 |
后果: 正面：简化前端、数据一致性 / 负面：未来若开放注册需确保注册流程填写 display_name / 约束：种子数据 display_name 不可为空
