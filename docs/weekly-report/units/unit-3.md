# UNIT-3: 登录态路由守卫

**优先级**: MVP

## 优先级依据

没有路由守卫，认证边界形同虚设，未登录用户可直接访问首页看到周报内容，安全模型崩溃。

## 背景

内部技术周报平台需要保障只有登录用户才能访问内容。同时已登录用户不应看到登录页，需自动跳转到首页。

## 需求描述

前端根据 JWT token 的存在性和有效性控制路由跳转：未登录或 token 过期时拦截并跳转登录页，已登录时访问登录页自动跳转首页。

## 功能闭环定义

- 输入/触发: 用户在浏览器中访问任意页面
- 核心行为: 前端检查 localStorage 中 JWT token 的存在性和有效期，决定路由走向
- 可观察结果: 未登录 → 跳转 `/login`；已登录访问首页 → 展示首页；已登录访问登录页 → 跳转 `/`；token 过期 → 清除 token 并跳转 `/login`

## 验收标准

### 正常场景

- AC-U3-01: 浏览器无 token，访问 `/` → 自动跳转到 `/login`，URL 变为 `/login`
- AC-U3-02: 浏览器有有效 token，访问 `/` → 正常展示首页内容

### 异常场景

- AC-U3-03: token 已超过 24 小时过期，访问 `/` → 清除本地 token，自动跳转到 `/login`

### 边界条件

- AC-U3-04: 浏览器有有效 token，访问 `/login` → 自动跳转到 `/`，不展示登录页
- AC-U3-05: 浏览器中 token 为非法格式（非 JWT 结构，如被篡改或损坏的字符串）→ 清除本地 token，跳转到 `/login`

## 业务规则

- R2: JWT token 有效期 24 小时，过期后需重新登录

## 依赖

- 依赖 UNIT: UNIT-1（JWT token 由登录流程签发）
- 依赖业务对象: 无（仅检查本地 token 状态）
- 受影响方: 无（全新项目）

## 排除项

- 基于角色（author/reader）的细粒度权限控制
- Token 静默刷新（refresh token）
- 后端 token 黑名单/撤销机制
- 多设备登录管控
