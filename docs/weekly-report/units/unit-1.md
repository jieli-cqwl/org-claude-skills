# UNIT-1: 用户账密登录

**优先级**: MVP

## 优先级依据

没有登录功能，用户无法进入系统，UNIT-2（首页展示）和 UNIT-3（路由守卫）均无法工作。登录是整个平台的入口。

## 背景

团队工程师需要一个安全的登录入口来访问内部技术周报平台，账号由管理员预置。

## 需求描述

提供账号密码登录功能，验证凭据后签发 JWT token，登录成功跳转首页，失败显示错误提示。

## 功能闭环定义

- 输入/触发: 用户在登录页输入 username 和 password，点击登录按钮
- 核心行为: 后端验证凭据（查询用户表 + 比对密码哈希），验证通过则签发 JWT token
- 可观察结果: 成功 → 前端存储 token 并跳转首页；失败 → 页面显示错误提示

## 验收标准

### 正常场景

- AC-U1-01: 输入正确的 username + password，点击登录 → 返回 HTTP 200 + JWT token，前端存储 token 并自动跳转到首页 `/`（token 存储方式由 DD-001 决定）

### 异常场景

- AC-U1-02: 输入存在的 username + 错误 password，点击登录 → 返回 HTTP 401，页面显示"用户名或密码错误"
- AC-U1-03: 输入不存在的 username，点击登录 → 返回 HTTP 401，页面显示"用户名或密码错误"（与密码错误提示一致，不泄露用户是否存在）

### 边界条件

- AC-U1-04: username 或 password 为空时点击登录 → 前端表单校验拦截，不发送请求，提示"请填写用户名"或"请填写密码"
- AC-U1-05: username 或 password 包含 SQL 特殊字符（如 `'`、`--`、`;`）→ 后端正常处理（参数化查询），返回 401 而非 500，不产生 SQL 注入

## 业务规则

- R1: 密码错误时返回通用错误提示"用户名或密码错误"，不区分用户名不存在和密码错误

## 依赖

- 依赖 UNIT: 无
- 依赖业务对象: User（需预置种子数据）
- 受影响方: 无（全新项目）

## 排除项

- 用户注册功能
- 密码找回/重置
- 第三方登录（OAuth/SSO）
- Refresh token 机制
- "记住密码"功能
