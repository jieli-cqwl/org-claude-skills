# 用户场景路径

## 正常路径

### UP-N1: 首次登录成功
- 用户打开登录页
- 输入正确的账号密码
- 点击登录
- 系统验证通过，创建会话
- 跳转到系统主页

### UP-N2: 会话内访问功能
- 用户已登录（持有有效会话）
- 访问系统功能页面
- 系统验证会话有效
- 刷新会话过期时间
- 正常展示功能页面

### UP-N3: 主动登出
- 用户在系统内点击登出
- 系统删除会话
- 跳转回登录页

## 边界路径

### UP-B1: 会话即将过期时操作
- 用户登录后 29 分钟无操作
- 第 29 分钟时访问功能
- 系统验证会话仍有效
- 刷新过期时间为新的 30 分钟
- 正常展示功能

### UP-B2: 空账号或空密码提交
- 用户在登录页留空账号或密码
- 点击登录
- 前端拦截，提示"请输入账号和密码"
- 不发送后端请求

### UP-B3: 特殊字符账号密码
- 用户输入包含特殊字符的账号密码（如 `user@domain.com`, `P@ssw0rd!`）
- 系统正常处理，不因特殊字符报错
- 验证逻辑与普通字符一致

## 异常路径

### UP-E1: 账号不存在
- 用户输入不存在的账号
- 系统返回"账号或密码错误"（不暴露账号是否存在）
- 用户停留在登录页

### UP-E2: 密码错误
- 用户输入存在的账号，但密码错误
- 系统返回"账号或密码错误"
- 用户停留在登录页

### UP-E3: 会话过期后访问
- 用户登录后 30 分钟无操作
- 第 31 分钟访问功能
- 系统返回 401 Unauthorized
- 前端跳转登录页，提示"会话已过期，请重新登录"

### UP-E4: Redis 不可用
- 用户登录时 Redis 连接失败
- 系统返回"系统繁忙，请稍后重试"
- 用户停留在登录页

### UP-E5: 伪造或篡改会话标识
- 用户手工修改会话标识
- 系统在 Redis 中查不到对应会话
- 返回 401，要求重新登录

## 排除路径（Phase 1 不支持）

### UP-X1: 记住我功能
- 用户勾选"记住我"选项
- Phase 1 不实现此功能
- 所有会话统一 30 分钟过期

### UP-X2: 多设备同时登录
- 用户在设备 A 登录后，在设备 B 再次登录
- Phase 1 不做互斥处理
- 两个会话独立存在

### UP-X3: 密码找回
- 用户忘记密码，点击"忘记密码"
- Phase 1 不实现密码找回
- 需联系管理员重置

### UP-X4: 第三方登录
- 用户点击"微信登录"或"钉钉登录"
- Phase 1 不支持第三方登录
- 仅支持账号密码
