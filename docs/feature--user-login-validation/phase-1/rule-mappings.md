# 业务规则映射

## BR-1: 账号密码验证规则
**业务语义**: 用户必须提供正确的账号密码组合才能通过认证  
**验证时机**: 用户提交登录请求时  
**判定条件**:
- 账号在用户表中存在
- 密码经 bcrypt 验证匹配存储的哈希值
**通过结果**: 创建会话，返回会话标识  
**拒绝结果**: 返回"账号或密码错误"，不区分是账号不存在还是密码错误

## BR-2: 会话过期规则
**业务语义**: 用户无操作 30 分钟后会话自动失效  
**验证时机**: 用户携带会话标识访问功能时  
**判定条件**:
- 会话在 Redis 中存在
- 会话的 `last_access_time` 距当前时间 ≤ 30 分钟
**通过结果**: 允许访问，刷新 `last_access_time` 为当前时间  
**拒绝结果**: 返回 401，要求重新登录

## BR-3: 密码存储安全规则
**业务语义**: 密码必须以不可逆方式存储，防止泄露  
**执行时机**: 用户注册或修改密码时  
**实现约束**:
- 使用 bcrypt 算法加密密码
- 不存储明文密码
- 不支持密码找回，只能重置
**违反后果**: 不符合安全规范，存在数据泄露风险

## BR-4: 错误信息模糊化规则
**业务语义**: 登录失败时不暴露账号是否存在，防止账号枚举攻击  
**执行时机**: 账号不存在或密码错误时  
**实现约束**:
- 账号不存在 → 返回"账号或密码错误"
- 密码错误 → 返回"账号或密码错误"
- 两种情况返回相同错误消息和 HTTP 状态码
**违反后果**: 攻击者可枚举有效账号

## BR-5: 会话唯一标识规则
**业务语义**: 每个会话必须有唯一标识，不可预测  
**执行时机**: 创建会话时  
**实现约束**:
- 使用 UUID v4 或等效随机算法生成会话 ID
- 会话 ID 长度至少 128 位
- 不使用用户 ID、时间戳等可预测值
**违反后果**: 会话可被猜测或伪造

## BR-6: Redis 故障降级规则
**业务语义**: Redis 不可用时拒绝登录和访问，不降级到无认证状态  
**执行时机**: Redis 连接失败或超时时  
**实现约束**:
- 登录时 Redis 不可用 → 返回"系统繁忙，请稍后重试"
- 访问时 Redis 不可用 → 返回 401
- 不允许绕过会话验证
**违反后果**: 系统退化为无认证状态，存在安全风险

## BR-7: 前端输入校验规则
**业务语义**: 前端必须校验账号密码非空，减少无效请求  
**执行时机**: 用户点击登录按钮时  
**实现约束**:
- 账号和密码均不能为空字符串
- 前端拦截空输入，不发送后端请求
- 后端仍需二次校验，不信任前端
**违反后果**: 增加后端无效请求负载
